# RocketWright UI・UX設計 / 改訂案

更新日：2026-11-05。対象は専門知識のない人が、実機のペットボトル水ロケットを検討・比較・製作する体験。
この文書は画面・操作・状態の提案。実装済み機能や実機の検証結果として扱わない。
[最新版の3画面](ui-drafts.html#explained)、[寸法・色・文字のトークン](design-tokens.json)、[操作状態の説明用ケース](ux-flows.examples.json)を合わせて読む。
成果物と技術評価の条件は[出力仕様](output-spec.md)、組立の評価は[組立仕様](assembly-spec.md)、機材の扱いは[機材設定仕様](equipment-settings-spec.md)に従う。
新しい画像07〜09と本仕様を優先し、旧画像01〜06は検討の経緯として残す。

## 1. 使う人が常に分かること

1. どの案件・案・版を見ているか。
2. 何を計算・確認し、今どこまで分かったか。
3. 見ている内容が、下書き・計算途中・確定結果・実物の記録のどれか。
4. 次の操作で、何が保存・変更・実行されるか。

数値と立体表示を読み解く説明を近くに置く。専門語の説明を開いても、選択中の図・部品・工程を失わない。
案の採用、製作版の確定、実機の確認を別の判断として表示する。
水ロケットを初期の入口にし、将来の月ミッションは対応範囲と入力が整った段階で追加する。

## 2. 共通の画面構造

| 場所 | 役割 | 固定するもの・切り替えるもの |
| --- | --- | --- |
| 上段 | 案件・案・版・保存状態・設定 | 現在の対象を常時表示。保存済みの版と編集中の下書きを併記 |
| 工程バー | 条件 / 設計 / 解析 / 比較 / 組立 / 出力 | 項目名と順序を固定。選択と到達状況を文字・形でも示す |
| 左 | 今の工程の対象を選ぶ | 条件一覧、構成部品、解析工程、候補、組立手順を切り替える |
| 中央 | 見て理解・比較・操作する | 機体、解析図、比較表、組立図。選択を右パネルと同期 |
| 右 | 意味・根拠・次の操作 | 解説、変更、確認、相談。文脈に合うタブだけを出す |
| 下段 | 現在の仕事と重要な操作 | 実行中は時間と停止、編集時は未保存、組立時は記録状態を出す |

- 工程を移動しても計算は勝手に開始・停止しない。戻る操作だけで設計版を巻き戻さない。
- 先の工程も説明と準備状況を閲覧できる。未完了の必須項目があるときは確定操作を止め、その理由と戻り先を表示する。
- 左端の細いアイコン列は案件一覧・機材ライブラリー・履歴などの全体移動に限定する。工程バーと同じ工程を重複して並べない。通常は折りたたみ可能とし、項目名も確認できるようにする。
- 編集中に案件・案を変えるときは、保存・破棄・戻るを選べる。図のタブ切替や拡大では下書きを保持する。
- 右パネルの主要操作は一つ。補助操作は輪郭ボタンか文字リンクにし、中断は強い主要色を使わない。

## 3. 最初の入力を短くする

入口は目的を一文で入力する欄と、例を選べるボタンにする。例の高度・費用はユーザーの条件として自動確定しない。
送信後は要求を編集できる項目に整理し、出典を「入力した内容」「選んだ設定」「提案」「未確定」と区別する。

| 順序 | 見せる内容 | 次の操作 |
| --- | --- | --- |
| 目的 | 何をどこまで飛ばし、どう回収したいか | 自然文から条件案へ進む |
| 条件 | 高度・積載物・回収・予算など、今回必要な項目 | 単位付きの項目を確認・修正 |
| 使えるもの | 保存済み機材の要約と、不足しているもの | 設定を開く、使わないと指定、未確定で保存 |
| 開始前 | 対象版・入力・行う解析・不足事項 | 明示的に解析開始、または下書き保存 |

最初から全ての材料・工具・人体寸法を入力させない。その条件を必要とする工程で確認する。
未入力の項目を埋める操作と、提案された値を採用する操作を区別する。画面の入力だけで不明値を事実に変えない。

## 4. 解析を見る・理解する

[07 / 解析画面](drafts/07-analysis-explained.png)を基準にする。
中央の背面スクリーンを主役にし、整備員と機体は前景の下側へ寄せる。整備員は注釈・凡例・操作を隠さない。
組立の手の寸法は整備員の大きさから求めず、別の実寸データとして扱う。

右の解説は「何を確かめる？」「今わかること」「まだ決められないこと」の順にする。
結果が届いただけなら受信した事実を説明し、性能の良否は評価が成立してから述べる。
解説の根拠を押すと該当の図と条件を強調する。長い内部処理ログを既定表示にしない。

| 操作 | 表示の変化 | 解析への影響 |
| --- | --- | --- |
| 工房 / 図を拡大 | 図を大きくし、戻るとカメラ・選択を復元 | なし |
| 整備員を表示 | キャラクターだけを表示・非表示 | なし |
| 履歴の結果を選ぶ | その結果を固定、時刻と版を明示 | なし |
| 最新へ戻る | 現在版の最新結果へ追従を再開 | なし |
| 動きを止める | 演出・カメラ移動を止める | なし。結果追従の設定は別に保持 |
| 解析を中断 | 対象と保存済み結果を示して確認 | 確認後に停止要求、サーバー応答後に停止と表示 |

固定中は新しい結果が届いても図を切り替えず、新着件数を知らせる。経過時間はジョブ、図の時刻は選んだ結果に結び付ける。
複数の図の取得時点が違う場合は図ごとに示し、未取得の図を新しい結果があるように補完しない。
図の凡例・単位・断面位置・等値面の定義・表示範囲へ辿れるようにする。比較時には同じ尺度を使う。
残差、格子依存性、性能の推移は別の評価として表示する。反復上限に対する割合を工程完了率にしない。
既存の解析画像を受け取っただけなら画像として拡大し、3Dデータがある場合だけ回転を提供する。

時間推定の根拠がなければ「見積もり中」。推定できる場合も工程単位で範囲を示す。
通信切断時は「接続が切れています」と最終更新時刻を表示し、サーバー上の実行状態は確認できるまで不明とする。

## 5. 比較から変更・採用へ進む

[08 / 比較と変更](drafts/08-change-review.png)を基準にする。
左右の案はカメラ・尺度をそろえ、選択した部品を対応付ける。比較表の各列に版を付ける。
比較項目は今回の要求に沿って絞り、費用・高度だけで案を順位付けしない。未評価、未確認、未実施を値として隠さない。
目標範囲と結果、概算と実測、成功件数とその定義は詳細で確認できるようにする。

変更の操作は次の順序にする。

1. 構成一覧または機体から部品を選ぶ。右パネルが同じ部品へ切り替わる。
2. 材料・寸法などを編集する。各入力に単位を付け、入力範囲と根拠がある場合に示す。
3. 変更部を重ねて表示し、変更前と下書きを区別する。旧版の結果を変更後の形状の性能と表示しない。
4. 影響する解析・図面・手順、必要な追加条件を示す。
5. 「変更案を保存」で新しい版の下書きへ保存する。不足条件があっても下書きは残せる。
6. 再解析は別の開始確認で、対象版・範囲・必要入力・見込める場合の時間を示して実行する。
7. 必要な評価がそろった案から「採用の確認へ」進む。確定する版・未完了項目・次工程を確認する。

保存後も旧版を閲覧している場合は、下書きへの移動を案内する。新しい版へ移ったら旧値は履歴として参照し、現在の評価は未評価にする。
案の選択とG2の確認、G3の製作版確定を同じ「採用」ボタンへまとめない。
未保存変更がある間は、その扱いを決めるまで採用を止める。無効なボタンの理由は常に読める位置に置く。
「変更を破棄」はその下書きだけを対象にし、保存済みの案・解析結果を削除しない。

## 6. 組立の閲覧と実作業の記録

[09 / 組立画面](drafts/09-assembly-access.png)を基準にする。
左は工程、中央は組立図、右は条件と観察記録。手順番号は閲覧位置で、完了した工程数ではない。
図には必要な部品・向き・接近・保持・操作・抜き取りを表示し、手・工具と周辺部品の関係を確認できるようにする。
同じ対象版・作業者条件の「手順書PDFを保存」を補助操作として置く。状態を未生成・生成中・保存可能・失敗・旧版で示し、必須データ不足の実機用手順を保存可能にしない。
下書きやレイアウト見本を保存する場合は用途を区別する。[出力内容の設計](export-content-spec.md)でPDF・文章・工程JSONの構成を定める。

- 中央の「組立図 / 手と工具 / 写真」は同じ工程を参照する。写真がなければ追加する入口を表示する。
- 作業者、手袋、工具は案件に適用した版から始める。工程だけの変更はその範囲を明記する。
- 工具の抜き取り経路などの指摘を押すと、該当部位と時点を表示する。手が入ることだけで作業全体を確認済みにしない。
- 「確認項目を記録」は観察の入力を開く。結果・方法・条件・対象版・資料を保存し、自動的に工程全体を合格にしない。
- 「前 / 次」は閲覧の移動だけ。実作業の実施・完了は別の記録にする。
- 条件不足でも観察記録は残せる。幾何確認、使用者の観察、実物試行は区別する。
- 成人と子ども＋成人の条件を切り替えたら、その条件の評価と役割を示す。成人の結果を子どもの結果へコピーしない。

09の金具・工具経路は表示方法の概念図。採用する部品形状・手順・締結・余裕を確定した図ではない。
実装では採用版のCADと人体・工具条件から描画し、根拠のない寸法・締付け条件を図へ書かない。
初期対象の既製の耐圧ボトルへ穴を開ける工程を、生成した概念図から導入しない。

## 7. 設定と成果物を使いやすくする

設定は上部右から右側のドロワーで開く。今回の設計と標準設定を明示し、適用前に影響を見せる。
右パネルに未保存の編集がある場合は保持し、設定を閉じたら元の部品・入力へ戻る。
保存した機材の型番を会話で毎回聞き直さず、必要な不足項目だけを確認する。
自然文による変更も同じ下書きと差分へつなげ、会話だけで設計条件を確定しない。

出力画面は採用版を上部に示し、設計データ・製作図・組立手順・動画を目的別に並べる。
各成果物に版、準備状態、対象、保存を表示する。動画生成中でも、完成した図面は個別に保存できる。
旧版は別の履歴へまとめ、現在版の一括保存へ混ぜない。未生成のファイルを完了リンクにしない。
初期の実機向け出力と、表示用のモデルを識別する。旧画像に残る展示用模型という名称は最新の実機方針へ置き換える。

## 8. 迷いやすい状態と回復

| 状態 | 表示するもの | 次にできること |
| --- | --- | --- |
| まだ何もない | この工程の目的と必要な入力 | 条件を追加、下書き保存 |
| 必須入力が不足 | 項目名、必要な理由、対象範囲 | 該当欄へ移動。入力済みの内容は保持 |
| 解析中・結果なし | 実際の工程と経過、結果待ち | 別工程を閲覧、中断を確認 |
| 途中結果あり | 途中の表示、条件、更新時点 | 拡大、履歴、解説。確定扱いはしない |
| 表示を固定中 | 固定結果の時刻と新着件数 | 最新へ戻る |
| 未保存の変更 | 変更対象、保存済み版との差 | 保存、破棄、編集へ戻る |
| 古い版の結果 | 対象版と現在版との差 | 旧版の根拠を見る、現在版を解析 |
| 中断要求中 | 応答待ちと保存済み結果 | 二重要求を防ぎ、状態照会 |
| 接続が切れた | 最終受信時刻と状態不明 | 同じジョブを照会して再接続 |
| 一部の生成が失敗 | 対象成果物と理由 | 完成済みを保存、対象だけ再試行 |
| 必須評価が未達 | 要求との差、確認できた範囲 | 条件か設計を修正、根拠を見る |
| 保存に失敗 | 未保存の内容と失敗箇所 | 入力を保持して再試行 |

再接続は新しいジョブを開始しない。停止位置からの継続は実行基盤が対応するときだけ提示する。
再開できない場合も保存済み結果を残し、新規実行の入力・範囲を確認してから開始する。
表示用データが古いと分かっているときは、直前の成功画面のまま現在も成功しているように見せない。

## 9. 寸法・文字・色

[design-tokens.json](design-tokens.json)を実装の初期値にする。全端末の最適値やページ全体の適合を検証した数値ではない。

| 要素 | 初期値 | 目的 |
| --- | --- | --- |
| 上段 / 工程バー | 48 / 44 px | 案件と工程を分ける |
| 左 / 右パネル | 224 / 344 px、大きいPC | 部品名と説明文を読む余裕を作る |
| 間隔 | 4、8、12、16、24、32 px | 関連する情報を近づけ、グループを区切る |
| 本文 / 行高 | 14 / 22 px | 日本語説明を読む |
| パネル見出し / 行高 | 16 / 24 px | 見出しを追えるようにする |
| 補足 / 行高 | 12 / 18 px | 版・時刻を補足。重要な理由は本文サイズで表示 |
| 主な操作対象 | PC高さ36 px、タッチ44 pxを目安 | 小さなアイコンだけを押させない |
| 角丸 | 操作6 px、パネル0 px | 工房の連続したドック構造を保つ |

無彩色の面、青の選択と主要操作、琥珀の確認待ち、赤系の失敗を使い分ける。
状態は色に加えて文字・アイコン・形で伝える。科学可視化の色は物理量の凡例に従い、合否の色と混ぜない。
数値は桁をそろえ、単位を省略しない。日本語の本文を極小の等幅書体にしない。
フォントは利用できる日本語フォールバックから始め、外部フォントを導入した前提にしない。

不透明な単色ペアを計算した結果：

| ペア | コントラスト比 |
| --- | --- |
| 本文 / パネル | 14.458 |
| 補足 / パネル | 8.152 |
| 主要ボタン文字 / 青 | 5.169 |
| 選択文字 / 選択面 | 9.463 |
| 確認待ち文字 / 確認待ち面 | 8.801 |
| 失敗文字 / 失敗面 | 7.256 |
| 完了文字 / 完了面 | 7.584 |
| 操作の境界 / パネル | 3.881 |

相対輝度から比を計算し、丸め前の値で本文4.5、必要な境界3という本設計の目標と比較した。
この検査はトークンの組み合わせに限る。画像内の文字、透明度、グラフ、操作状態、実際の画面全体は別に確認する。

## 10. 狭い画面・キーボード・動き

- 1440 px以上：左224、右344 pxとし中央を可変にする。
- 1200〜1439 px：左200、右320 px。図の拡大を常に選べるようにする。
- 768〜1199 px：左はドロワーへ。右の説明は開閉でき、中央の最低幅を守る。
- 768 px未満：単列へ。中央図の下に解説・操作を並べ、必要なものだけを選んで開く。横方向へページ全体を押し広げない。
- スマホの比較は案ごとに並べ、比較表のスクロールは表の中に限定する。組立の工程と次の操作は指で押せる大きさで残す。
- 工程バーが収まらない場合は現在工程の名前と一覧ボタンを表示し、選択・確認待ちを隠さない。
- 狭い画面に固定した操作は本文やフォーカスを覆わず、端末の安全領域を確保する。
- 部品選択は構成一覧でも行えるようにし、3D上のクリックだけを必須にしない。図の説明・数値表も用意する。
- フォーカスは工程、対象、表示、右の判断、下の操作の順に移る。見た目だけで読順を入れ替えない。
- 設定・確認ダイアログを開くと見出しと最初の入力へ移し、閉じると開いた操作へ戻す。Escapeで閉じても入力を無言で捨てない。
- タブ・一覧・図の操作をキーボードでも行えるようにする。入力欄の文字操作をショートカットで奪わない。
- 動きを減らす設定では整備員ループ、カメラ移動、自動アニメーションを止める。数値・状態・新着通知は残す。

これらの端末・入力操作は今回まだ実装・実機確認していない。

## 11. 次の実装で確認する課題

1. 専門知識のない人が、解析図の意味と未確定事項を説明できるか。
2. 過去結果の固定中に新着を受けても、表示時点と実行中の時点を混同しないか。
3. フィンの下書きを保存しても計算が始まらず、旧版の結果が現在版へ移らないか。
4. 不足情報を残して保存でき、製作の確認済みにはならないか。
5. 比較から採用確認へ進むと、確定する版と次工程を理解できるか。
6. 工程を移動しても実作業の記録が増えず、手・工具の条件不足を理解できるか。
7. 通信切断・中断・生成失敗から、既存の成果物を失わず回復できるか。
8. スマホとキーボードで、条件修正・図の説明・組立の次工程へ進めるか。

[ux-flows.examples.json](ux-flows.examples.json)はこれらを説明する状態例。動作テストの結果ではない。
今回は新しい3画像の目視、PNGの整合、リンク・JSON・トークンの計算・状態例の整合を確認した。
ブラウザーでの実操作、利用者テスト、CAD干渉評価、実物組立は未実施。既存の本番画面・API・解析処理はこの変更で編集していない。
