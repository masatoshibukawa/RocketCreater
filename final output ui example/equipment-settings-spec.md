# RocketWright：機材・材料・作業環境の設定

更新日：2026-11-04。設定メニューと構造化入力の仕様案。[設定パネルの画像](drafts/05-equipment-settings.png)と[出力仕様](output-spec.md)、[組立仕様](assembly-spec.md)に対応する。
設定の保存・設計への適用・カタログ検索・機材制約の判定は今後の実装対象。画像中の機材と寸法は表示例で、ユーザーの所有機材ではない。

## 1. 配置と画面構成

上部右に常設の `設定` ボタンを置き、`機材と作業環境` の右側パネルを開く案を主案にする。
設計中の機体と左の工程を残し、右の相談領域を一時的に設定パネルへ切り替える。画面が狭い場合は全画面の設定へ切り替える。
デスクトップでは入力項目が多くなってもパネル内を移動でき、保存・適用の操作を末尾に置く。
キーボードで開閉と入力ができ、閉じた時に設定ボタンへフォーカスを戻す。

パネル上部に `今回の設計` と `標準設定` の対象を表示し、編集先を取り違えないようにする。
主な分類は `プリンター`、`材料`、`工具・治具`、`発射・計測機材`、`作業者`、`出力`。画像は主要項目を一枚で検討するための簡略表示。
設計画面にも、現在適用中のプロファイル名と版を小さく表示する。

## 2. 選ぶ内容

| 分類 | ユーザーが選択・登録するもの | 設計に使う条件 |
| --- | --- | --- |
| 3Dプリンター | 保有機材、借りる機材、外部への依頼、プリンターを使わない | 方式、有効造形範囲、対応する製作方法、機材の選択版 |
| プリンターの仕様 | メーカー・型番・バリエーション、構成、ノズル等 | 確認した仕様と出典、使用できる条件、未確認の項目 |
| 材料 | 実際に使える材料とグレード、製品、在庫・利用可否 | 材料資料、製作工程との組合せ、質量推定や必要な検証への入力 |
| 工具・治具 | ドライバー、保持具、切断・加工道具など | 作業で必要な工具の有無、形、寸法、入れ方と操作範囲 |
| 発射・計測機材 | 使用する既製ランチャー・ノズル、計測道具等 | 適合部品、確認済みの製品条件、測れる項目と精度の根拠 |
| 作業者 | 成人、子ども＋成人、両方、利き手、手袋、担当 | 組立の対象者と手・工具の評価条件 |
| 出力 | 必要な図面・モデル・動画の種類 | 対応済みの生成ジョブと、希望する成果物の目録 |

機材を所有していること、今回使えること、その工程で使えること、製作条件が検証されたことを別に記録する。
プリンターを選ぶだけで材料・造形方向・製作条件・部品性能の確認を省略しない。
既製品の仕様と、実測した条件やユーザーの変更を区別する。独自入力は元のカタログを上書きせず、別の版として根拠を持たせる。

選び方は `登録済みから選ぶ → 必要な差分だけ入力 → 不明項目を確認` を基本にする。
カタログにない機材も手動登録できるが、必要な値を不明のまま0や無制限で補わない。
型番を選べたことと、必要な仕様が揃ったことを区別する。

## 3. 標準設定と今回の設計

| 操作 | 保存・反映するもの |
| --- | --- |
| 標準設定として保存 | 次の案件に使う初期値。作成済み案件の入力や結果を変更しない |
| 今回の設計で編集 | その案件用の変更案。適用中の版とは別に保持する |
| この設計に適用 | 案件の機材スナップショットを確定し、影響する入力・結果・確認事項を示す |
| 閉じる | 未適用の編集を完成した設計条件へ混ぜない。編集の保持・破棄を明確に表示する |

設定が不完全でも下書きとして保存できる。`材料が未選択` 等を保持し、必要な製作確認は確認待ちとする。
設定の保存を、G3の製作版の確定にしない。
案件で適用した値は、標準設定やカタログが後から更新されても勝手に書き換えない。
更新を取り込む場合は、新しい案件設定版を作り、差分と再確認の対象を示す。

機材の基本情報、材料・製作プロファイル、工具、作業者はそれぞれIDと版を持つ。
実行開始時に解決した仕様値をスナップショットへ保存し、後から同じ条件を確認できるようにする。

## 4. 自然言語の処理を減らす設計

設定画面の入力は型付きの項目へ変換し、機材ID・版・値・単位・不明事項を確定する。
選択肢の解決、必須項目・単位の検査、対応範囲や利用可否の照合は通常のコードで行う。
自然言語から機材名や寸法を毎回取り直す工程を減らし、対話は目的や比較の説明、変更意図、未確定事項の確認へ集中させる。

処理の流れは `設定の選択 → 型と単位の検査 → 案件用スナップショット → 必要な制約の解決 → 設計・評価 → 節目で確認`。

- LLMへは、その判断に必要な機材ID・版と簡潔な制約、不明事項を渡す。機材カタログや説明書を毎回全文で送らない。
- 部品の寸法比較などは、解決済みの構造化条件を使う評価処理へ渡す。必要ならツールで追加情報を取得する。
- 会話から機材変更を求めた場合も、設定の変更案として反映し、案件へ適用する節目で差分を確認する。
- 「固定したプリンター」と別の機材を求める会話が競合した場合は、変更案と適用中の版を並べて示す。意図を無視したり、結果の入力を無言で変更したりしない。
- 設定の内容が同じ間は同じスナップショットを参照し、変更時は差分と影響を記録する。

聞き取り・仕様抽出を減らせるという設計上の見込みと、実際のトークン数・時間の削減を区別する。
現在のAPIは `text / seed / env` が主な入力で、機材設定からの構造化入力は未実装。実測の削減率はまだない。
比較検証では、同じ目的・機材を伝えるケースで、聞き返し回数、機材抽出の呼出し回数、送信トークン、処理時間、設定の取り違えを測る。

## 5. 設計と組立への反映

| 設定 | 確認・変更するもの |
| --- | --- |
| 有効造形範囲 | 選択した造形方向、配置、サポート等を含む工程上の使用領域で収まるか。公称サイズだけで確定しない |
| 方式・材料・工程 | 部品の製作方法、必要な設計入力、質量や適用性能の根拠、対応する出力形式 |
| ノズルや機材構成 | 形状の成立性を評価するための製作条件。選択だけで寸法精度や強度を確認済みにしない |
| 使用工具・治具 | 手順、両手の分担、アクセス経路、工具の進入・操作・抜き取り |
| 作業者・手袋 | 対象者ごとの組立性の評価、担当、必要な実物確認 |
| 計測道具 | 実測・検査の手順、確認できる項目、未確認で残るもの |

同じ部品でも、ある向きで収まらないことと、その機材で絶対に造形できないことを区別する。
別の向き、分割、別工法、既製品、外部依頼は候補として比較する。変更した質量、接続、強度、空力、組立性は必要な評価へ戻す。
使用できない工具を必要とする手順を完成版に含めない。代替の工具・治具には寸法と作業条件の根拠を付ける。
不明な材料・工程を、利用できることや性能が成立することへ自動変換しない。

機材変更の影響は依存関係で判定する。工具だけの変更なら組立評価と手順が対象になり得る。
形状や質量が変わった場合は関連する飛行・安定性・回収解析も確認する。影響しないことを説明できない結果の再利用は仮定しない。
設定を編集している最中に、実行中のジョブの入力を差し替えない。新しい版を適用し、古い結果は元の版に保持する。
月向けを含む将来の計画でも、手元の機材で製作できる範囲、外部設備が必要な範囲、設備未確定の構想を区別する。

## 6. 状態表示と不足情報

| 状態 | 表示と次の操作 |
| --- | --- |
| 機材未登録 | 機材を追加、外部へ依頼、プリンターを使わない等を選ぶ。未登録を機材なしと同一にしない |
| 機材を使わないと指定 | 対応する既製品・他の製作方法の範囲を表示する |
| 仕様不明 | 不足項目を直接表示し、根拠を追加するか下書き保存 |
| 工程への適合未確認 | 機材は選択済み、製作条件は確認待ち、と表示する |
| 条件に合わない | どの部品・向き・工程が何に適合しないかを示し、変更候補へ進む |
| 未適用の変更あり | 保存した編集と適用中の版を区別し、案件への適用を選ぶ |
| 変更を適用した | 影響する結果・図面・手順と、必要な再確認を一覧で示す |

未登録、未選択、不明、利用不可、未対応を同じチェックボックスのOFFで表さない。
希望する出力形式は、実装・生成・検証の状態と分ける。未対応形式の選択を、生成済みリンクにしない。

## 7. 保存・入出力と検証例

内部では、案件に `equipment_profile_id / equipment_revision` を持たせ、プリンター・材料・工具・作業者・出力希望のIDと版へ参照する。
保存時の元仕様、独自変更、値と単位、根拠、欠けている項目を保持する。
最終パッケージへ `design/equipment.json` を追加し、製作・組立・検査で何を使う想定だったかを再現できるようにする。
プロファイルの登録・選択は機材の接続や実行とは別の機能。今回の案では実機の自動操作を開始しない。

[equipment-contract.examples.json](equipment-contract.examples.json)に6つの説明用ケースを記録する。API実装やユーザー所有機材の実データではない。

1. 機材未登録と、プリンターを使わない明示選択を区別する。
2. 型番を選んでも材料や工程が不足している場合、下書き保存はできるが製作確認済みにならない。
3. 標準設定を更新しても、既存案件の適用済みスナップショットは変わらない。
4. 工具の変更によって、その工具を使う組立手順と作業余裕の評価を再確認する。
5. 会話と固定設定が競合した場合、案件版を無言で変更せず、変更案を条件確認へ戻す。
6. 同じ選択から、機材IDと必要な制約・不足情報を構造化して渡し、カタログ全文を必須にしない。

## 8. 今回の成果物と未確定事項

今回作るのは、設定パネルの静止画、この仕様、例示データ、既存仕様との接続。実際の設定保存や設計APIへの接続は追加していない。
選択する実機の型番、カタログの提供元、登録済み機材の初期セット、ユーザー登録値の確認方法、保存先・共有範囲、対応する製作プロファイルは今後確定する。
設定画面は日常の道具を選ぶ操作に留め、目的・要求・採用案を確認する既存の節目へつなげる。
