# 出力ファイルの内容設計

更新日：2026-11-05。実機のペットボトル水ロケットを最初の対象にする。
[内容の実例](export-example/README.md)を同梱する。これはr00の下書きで、未確定の形状・数値・作業方法を完成データに見せるための見本ではない。
Web・PDF・動画の工程IDと入力版をそろえる。[組立仕様](assembly-spec.md)、[出力仕様](output-spec.md)、[UI・UX仕様](ux-spec.md)と合わせて読む。

## 1. 受け取る人の読む順序

1. READMEで対象版、目的、使えるファイル、未完了事項を知る。
2. PDF手順書で準備・順序・作業図・確認方法を読む。
3. 部品表と設計データで、必要なものとその根拠を調べる。
4. 確認スクリプトでファイルと参照の整合を確認する。
5. 詳細が必要な人が解析データ・判断履歴・再生成用コードへ進む。

最初のREADMEに、開く順序と用途を載せる。ファイル一覧だけを渡して、何が完成し何を確認すべきかの解釈を受け手に任せない。

## 2. 全ファイルで共有する約束

| 項目 | 内容 |
| --- | --- |
| 対象 | package_id、design_revision、工程や部品の版 |
| 状態 | 下書き、未生成、計算途中、確定、旧版、失敗、未評価を区別 |
| 値 | 数値と単位を組にし、未知はnull。0・無制限へ置き換えない |
| 根拠 | source_id、使った条件、方法、対象範囲、必要な確認 |
| 依存 | 元となる要求・部品・機材・工程・解析のID |
| 表現 | 人が読む日本語と、機械用の安定したキー・IDを分ける |
| 保存 | UTF-8、テキストの改行LF、相対パス。個人環境の絶対パスを入れない |

例のschema_versionは本サービス内の草案の版で、外部規格への適合を表さない。
CSVでは未知の値を空欄にし、status列で理由を残す。未実行の時系列CSVを空の完成物として作らない。
CSVを表計算ソフトへ渡す場合は文字列が式として評価されない扱いも実装時に確認する。

## 3. 人が読むテキスト

| ファイル | 必ず含める内容 | 読み手 |
| --- | --- | --- |
| README.md | 目的・版・状態、読む順序、ファイルの役割、実行方法、未完了事項 | 全員 |
| assembly/instructions.md | PDFと同じ工程ID、部品・工具・担当・向き・保持・操作・確認・戻し方 | 作業者・確認者 |
| history/decisions.md | 判断ID、変更前後、理由、根拠、保留、影響範囲 | 設計を見直す人 |
| 解析説明の文章 | 問い、条件、手法、結果、要求との差、限界、次の判断 | 利用者・確認者 |

見出しは対象と作業が分かるものにする。合格・推奨・完成という語は、それに必要な確認がそろった範囲で使う。
PDFは画面キャプチャを並べる形式にせず、工程の構造化データから印刷用に組む。
Markdownは検索・差分確認しやすくし、本文全体を画像に変換しない。

## 4. 機械が読むデータ

| ファイル | 主な内容 | 未確定の扱い |
| --- | --- | --- |
| manifest.json | ファイル状態、用途、版、依存、サイズ、SHA-256 | 未生成はpathとhashをnullにし理由を残す |
| design/requirements.json | 目標、許容範囲、積載、回収、固定条件、出典 | 値とstatusを分ける |
| design/equipment.json | 適用したプリンター・材料・工具・作業者のIDと版 | 未登録・未選択・使わないを区別 |
| design/design.json | 部品ID、構成、数量、材質、形状、座標、単位 | 未設計・未評価を明示 |
| parts/bom.csv | 部品ID、版、名称、数量、調達、材料、根拠 | 数量0と未知の空欄を区別 |
| assembly/steps.json | 工程ID、前提、部品、役割、操作、条件、図、完了基準 | 必須情報不足の工程を実行可能としない |
| analysis/results.json | 解析ID、入力版、条件、方法、値、判定、図と時系列の参照 | not_run、not_evaluated、failedを区別 |
| provenance/sources.json | 出典ID、種類、内容、参照先、確認日、適用範囲 | 出典がない数値を確定値にしない |
| verification/technical-status.json | 幾何・作業・実物・製作確認の状態と不足 | 未確認をファイル整合チェックで埋めない |

将来の飛行時系列はtime_s、altitude_m、velocity_m_sなど物理量と単位が分かる列にする。
ヘッダーだけの未実行ファイルは出さず、生成元の解析ID・入力版・条件を目録から参照できるようにする。
工程・部品・出典の参照先が無い場合は、公開前の整合検査で検出する。

## 5. 組立手順書PDF

標準成果物のパスはassembly/instructions.pdf。対象機体・手順・作業者・機材の版を固定して生成する。
版の一致と発行状態を画面・PDF・目録でそろえ、準備のできたPDFを個別保存できるようにする。
未確定条件のある資料は「下書き」と明記する。製作に使う確定版とは種類と保存名を分ける。
この内容見本のPDFは、後から追加するレイアウト検討用で、実機用手順の発行にはしない。

| 章・ページの役割 | 掲載する内容 |
| --- | --- |
| 表紙と読む順序 | 機体・版・日付・発行状態、対象者、必要な確認、全体の見取り図 |
| 準備 | 部品ID・版・数量、工具・治具・消耗品、作業者と支援者、製品資料 |
| 工程一覧 | 工程ID・依存・役割・必要な事前条件。目次から工程へ移動 |
| 各工程 | 一つの主作業、開始状態、図、向きと保持、手・工具の経路、作業条件と根拠 |
| 完了確認 | 正しい状態と確認方法、記録欄、続けない条件、戻る工程 |
| 巻末 | 点検・交換・再作業、未完了事項、出典、変更履歴 |

各ページに機体版、手順版、工程ID、ページ番号を載せる。ページを単独で印刷しても対象を識別できるようにする。
A4縦・白地・黒文字を初期案とし、図版に必要なら横ページを使う。黒いWeb画面をそのまま背景にしない。
本文は初期値10.5 pt以上、図と余白を優先し、工程が長ければ続きページへ送る。固定のページ数に詰め込まない。
連続ページにも工程IDと継続表示を付け、図・注意・操作の対応を切らない。
色だけに頼らず線種・記号・文字を付ける。原寸図でない図は縮尺または模式図と明記する。
作業条件に応じた分岐を表示し、成人用の経路評価を子ども用へ流用しない。
チェック欄は未記入から始め、紙への記入とサービスへの実施記録の取り込みを区別する。
WebへのリンクやQRは補助にし、紙だけでも工程と必須条件を読めるようにする。
PDFの図版は同じ採用CAD・工程データから作る。見栄えのよい生成画像を製作図の代用にしない。

## 6. スクリプトの内容

どのスクリプトにも、目的・対応する入力版・依存環境・入出力・変更するファイル・終了コードを記す。
--helpで使い方を表示し、設定・認証情報や個人環境のパスを埋め込まない。
受け取っただけで実行せず、依存ライブラリーの自動インストールや機材操作を開始しない。

| 種類 | 入力と出力 | 今回の扱い |
| --- | --- | --- |
| verify_package.py | 目録と実ファイルを読み、整合レポートを標準出力 | 動く読み取り専用の例を同梱 |
| inspect_design.py | 要求・機材・技術状態を読み、日本語の要約を標準出力 | 動く読み取り専用の例を同梱 |
| CAD再生成用 | 確定パラメータ・部品版・単位から指定部品を生成 | 形状と環境が未確定のため未生成 |
| 解析再実行用 | 入力版・モデル版・環境・シードから結果を生成 | 実行基盤と入力が確定してから同梱 |
| 映像再生成用 | 採用形状・工程・台本・カメラ・依存環境から映像を生成 | 本体と素材の依存が整ってから同梱 |

再生成用スクリプトは入力検査と実行を分け、対象・出力先・必要資源を実行前に確認できるようにする。
既存ファイルの上書きは明示的に指定したときだけ行い、出力先を引数で指定する。
CADコードを保存しただけで、形状・製作条件が検証済みとは表示しない。
スクリプトやモデルの外部依存は版と入手先・必要な利用条件を記録し、秘密情報は外から与える。

## 7. 確認スクリプトの範囲

verify_package.pyは、目録上のreadyファイルの存在・バイト数・SHA-256、UTF-8/LF、余分なファイル、版の一致、部品・工程・出典・作業者の一部の参照を確認する。
相対パスの逸脱、シンボリックリンク、重複したID・パス、工程の循環依存を拒否する。
目録そのものは自己ハッシュの対象外。署名・発行者認証・全てのJSON項目の完全なスキーマ検証は行わない。
パッケージに含まれる実行コードの無害性を証明するものでもない。

終了コード0：対象の整合が通った。1：不一致か形式の問題。2：コマンド引数の問題。
技術評価は常に別項目でnot_performedと出し、製作承認を与えない。
目録の修復やファイルの削除を黙って行わない。再生成したファイルは、発行側で意図的に新しい目録へまとめ直す。

## 8. この見本の発行と確認

このディレクトリの内容例は、APIに接続した出力生成機能ではない。
部品・寸法・材料・工具・実機手順はまだ確定していない。PDFレイアウトとテキスト構造をレビューするためのもの。
生成できていない実機用CAD・PDF・解析CSV・動画は、目録に未生成として記録する。
レビュー用PDFの生成後は全ページを画像にして確認し、文字の欠け・重なり・余白・ページ番号・対象版を検査する。
スクリプトは正常パッケージだけでなく、改変・欠落・参照不備・パス逸脱の例でも確認する。
最終提出のチェックは実際に渡す範囲が決まった時点で行い、この見本の作成だけで完了としない。
