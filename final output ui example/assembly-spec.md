# RocketWright：組立方法と作業余裕の設計案

更新日：2026-11-04。[途中・最終出力仕様](output-spec.md)の組立性に関する詳細。初期対象は実機のペットボトル水ロケット。
成人と、子どもが大人と一緒に組み立てる場合の両方を対象にし、作業者の条件を選べるようにする。
本書は機能・出力の仕様案。実際の手の寸法、組立経路、材料、締結条件を計算・検証した成果物ではない。

## 1. 設計に加える判断

設計時に、部品が所定の位置に収まることに加え、人が順番に組み立て、確認し、必要なら分解できることを評価する。
組立性は、G1の構成選択から評価し、G2の候補比較に含め、G3の製作版を確定する条件にする。
組立途中の形状、作業者、両手の分担、工具、治具、作業台、部品のばらつきを評価の入力に含める。

| 観点 | 問い | 記録する結果 |
| --- | --- | --- |
| 指・手のアクセス | 開口から作業箇所まで、必要な姿勢で指や手が届くか | 対象プロファイル、進入方向、対象範囲、最小余裕、干渉箇所 |
| 操作の空間 | つまむ、支える、押す、回す動きに必要な空間があるか | 操作ごとの動作範囲と成立／未成立／未評価 |
| 工具 | 工具本体と握る手を入れ、動かし、最後に抜けるか | 対象工具、接近・操作・離脱の経路、干渉 |
| 作業順序 | 他の部品を付けた後も、必要な箇所にアクセスできるか | 工程の依存関係、閉じる順序、実行不能な工程 |
| 保持と反力 | 両手で必要な箇所を保持しながら操作できるか | 同時作業、作業人数、固定方法、必要な治具 |
| 視認と確認 | 実際の作業姿勢で位置や完了状態を確認できるか | 視線、見える目印、代替の検査方法 |
| ばらつき | 部品公差、製作誤差、手袋や姿勢の違いを含めても成立するか | 評価した条件と余裕、条件外の範囲 |
| 分解・再作業 | 工具・手を戻せるか、点検や交換ができるか | 逆手順、不可逆工程、交換範囲、再検査 |

## 2. 作業者の条件

UIでは `成人`、`子ども＋大人`、`両方で評価` を選ぶ。各工程に実際の担当者と支援者を割り当てる。
[機材と作業環境の設定](equipment-settings-spec.md)で選んだ工具・治具・手袋・対象者は、案件用スナップショットから組立入力へ参照する。同じ条件を対話で繰り返し聞き取らない。
設定を変更した場合は、関係する工程・手順・アクセス結果の版と適用範囲を再確認する。
子どもが担当する工程に成人の見守りを付けることと、成人が代わりに操作することを区別する。
作業に必要な力、熟練、道具の扱い、姿勢の確認から担当を決める。手が入ることだけで子どもが実行できると判定しない。

| 入力 | 必要な情報 |
| --- | --- |
| 対象者 | 対象年齢帯、作業の経験、担当と支援者、適用対象の範囲 |
| 手の形 | 指の長さ・幅・厚さ、関節部、手掌・手首、つまむ時の形、プロファイルの版 |
| 動作 | 作業姿勢、届く範囲、必要な指や手首の動き、片手／両手 |
| 左右 | 利き手、左右どちらから操作するか、左右の寸法を同一と仮定した範囲 |
| 手袋 | 素手／対象の手袋、手袋を含めた外形と可動範囲、根拠 |
| 出典 | 対象集団、計測方法、データの項目定義、実測か統計値か、取得日、適用範囲 |

指の幅だけ、平均的な成人の手だけ、一律の余裕寸法だけで全員に対応したことにしない。
作業姿勢と必要な動きを含む手の形を用意し、対象にした複数の形・条件を記録する。未計測の値を0で補わない。
統計の各項目の大きい値を無条件に組み合わせ、それを実在する代表者や確認済みの人口カバー率としない。
寸法や手袋条件が未確定なら `作業者条件を確認中`。不明な集団を合格対象に含めない。

成人の参考資料には[河内まき子、2012：AIST日本人の手の寸法データ](https://www.airc.aist.go.jp/dhrt/hand/index.html)がある。調査対象は18〜64歳の日本人成人で、計測した側は右手と記載されている。
[寸法項目一覧](https://www.airc.aist.go.jp/dhrt/hand/data/list.html)は、指の幅・厚さ・長さ等の定義を確認する資料とする。成人の資料を縮小して子どもの確認済みデータにはしない。子どもの対象年齢帯と適切な資料・実測方法は今後確定する。
本書では具体的な人体寸法値や、全工程に共通する合格余裕寸法は採用していない。

## 3. 作業余裕の評価方法

### 3.1 工程ごとの途中形状

各工程の開始時に存在する部品、既に締結した箇所、開いている箇所、治具の位置を状態として保存する。
完成形の空間だけから組立可能性を判断しない。
例えば内部の保持部へ触る工程は、外側を閉じる工程より前に置く。最後に工具が取り残されないことも確認する。
工程を並べ替える場合は、前提となる保持、位置決め、接着・硬化等の条件が成立するかも再評価する。

### 3.2 手・工具・持っている部品の動く範囲

進入、把持、部品の挿入、操作、離脱の経路を分けて持つ。
手、手袋、工具、保持している部品が、その経路で通る空間を評価する。工具の軸だけでなく、柄、手、回転や持ち替えの空間を含める。
接触してよい対象面と、接触してはいけない周辺部品を指定する。ねじへの工具の接触や、把持対象への指の接触を、無条件に干渉エラーにしない。

初期実装では、単純化した手・指・工具の形で干渉候補を絞る段階から始める。
近似形状の結果には方法と精度・省略を付け、詳細形状や可動域を評価した結果と区別する。
経路の点だけを粗く調べて点の間の干渉を見落とさないよう、経路間の空間と判定精度を記録する。判定精度を満たせなければ `未評価` または `判定保留`。

### 3.3 余裕と公差

`最小余裕` は、評価した経路と姿勢における許可されていない接触までの最小距離として定義する。
必要な余裕は、作業内容、対象プロファイル、寸法公差、製作誤差、経路や計測の不確かさに結び付けて決める。
結果には、名目形状での値と、公差・変動を反映した評価を区別して出す。
必要余裕の根拠がない場合は、正の隙間があることを示せても `余裕を満たすことは未確認` とする。
人体の寸法差、製作の寸法差、必要な動作の余裕を同じ項目へまとめず、何を含めたかを記録する。

### 3.4 保持・力・視認

同時に必要な保持と操作を列挙し、作業者の両手と支援者・治具へ割り当てる。保持が無いまま部品が浮いているアニメーションを手順にしない。
反力をどこへ逃がすか、部品が動かないか、作業に必要な力・操作量が確認されているかを別に評価する。
締付条件や接着・硬化条件は、選定部品・材料・製品資料等の根拠を持つ値として扱う。値が無ければ未指定とし、自動で作らない。
必要な位置が見えない工程には、姿勢・部品配置の変更や、確認用の目印・検査方法を検討する。画面を透視できることだけで実物の視認性を確認済みにしない。

## 4. 判定とゲート

| 判定の層 | 状態の例 | 意味 |
| --- | --- | --- |
| 入力 | 未入力／適用確認待ち／入力確認済み | 手・工具・部品・工程の条件が揃っているか |
| 幾何 | 未評価／簡易チェック通過／干渉あり／詳細チェック通過／判定保留 | 評価した形・経路・公差の範囲で空間的に成立するか |
| 作業 | 力・保持・姿勢・視認の確認待ち／要変更／確認済み | 人の動作として成立する根拠があるか |
| 実物 | 未試行／試行中／作業不能／確認済み | 実物やモックアップでの試行結果 |
| 版 | 現在版／条件変更で旧版 | 今回の工程・手・工具・部品の版に対する結果か |

一部の幾何チェックを通過した状態を、実物で組立可能と確認した状態へ自動で昇格させない。
両方を評価対象にした場合は、必須工程を担当する成人・子どもそれぞれの結果を示す。片方が通った結果だけで全体を合格にしない。
成人だけが担当すると定義した工程は子どもの評価で無条件に合格を付けず、担当外とその根拠を示す。
必要な作業者・条件が一つでも不足なら、その適合性は未確認として残す。

G1では組立方式とアクセスの成立見込み、G2では候補ごとの困難箇所、G3では手順と製作形状の整合を確認する。
G3の確認パッケージには、未解決の干渉、必要な実物試行、必要な道具・治具、対象者の条件を必ず含める。
重大な未解決は製作版の確定を止め、検討用の試作出力と検証計画を取り出せるようにする。
試作を使って組立確認し、その結果を同じゲートへ戻す。実物が無いと初回の検討用形状を出せない循環にはしない。

## 5. 組み立てやすさを設計へ戻す

問題が出たら、手順の変更、部品の仮保持、工具の選択、締結箇所の向き、外側から操作できる構成、部品の分割や治具を候補として比較する。
アクセス開口を検討する場合は、新規に設計する非耐圧の保持部・カバー等の範囲を明示する。既製ボトルや耐圧部品へ無条件に穴を開ける案へ展開しない。
各候補について、アクセス、保持、視認、工程数、工具の種類、実物確認、質量、強度・取付、空力への影響を記録する。
組立性を改善する変更で影響する性能解析と製作データを旧版とし、必要な評価をやり直す。

作業者条件や工具だけを変更した場合は、関連する組立評価・手順・ゲートを再確認する。
飛行解析の入力が変わらないことを依存関係から説明できる場合は、その結果を再利用できる。依存関係が未定なら再利用を仮定しない。
工具が通ることを優先して、他の必須要求を無言で外さない。

## 6. 詳細な組立手順の一工程

各工程を一つの構造化レコードとして保存し、Web、PDF、組立動画を同じ工程から生成する。

| 項目 | 含める内容 |
| --- | --- |
| 識別と前提 | 工程ID、機体・部品・手順の版、前工程、開始時の組立状態 |
| 担当 | 成人／子ども＋支援者、左右の手の役割、同時に必要な人数 |
| 部品と道具 | 部品ID・版・数量、消耗品、工具の識別と寸法、治具、必要な製品資料 |
| 向きと位置 | 基準面・目印、前後左右、挿入方向、位置決め、保持点、触れてよい面 |
| 手の置き方 | 指・手・工具の入り方、持つもの、反対側の保持、離脱経路 |
| 操作 | その工程で行う一つの作業。必要なら途中の姿勢を分けた小工程 |
| 条件 | 選定した部品・材料に基づく締結・接着等の条件、根拠、未確定事項 |
| 完了の確認 | 正しい見た目・位置、計測箇所と基準、確認する動き、記録する結果 |
| 問題が出た場合 | 続けない条件、戻る工程、取り外せる範囲、交換・再検査の条件 |
| 表示素材 | 通常図、分解図、必要な断面、手と工具の表示、動画区間、字幕 |
| 検証 | 作業者条件別のアクセス結果、保持・視認・操作の確認、実物試行と根拠 |

手順の文章はLLMで補助できるが、部品の版、順序、寸法、設定値、工具、確認基準は確定データを参照する。
根拠の無い締付値や、実行できない動きを文章や動画で補完しない。
この仕様では具体的な水ロケットの締結値・接着方法・加圧操作等を確定していない。

## 7. 組立画面

- 左：工程一覧と依存関係。部品・道具・担当者、未確認項目を選択できる。
- 中央：選択工程の開始状態、分解・挿入表示、手と工具の実寸の半透明形状、動く範囲、干渉点と寸法。
- 右：部品の向き、手の置き方、実際の一作業、完了基準、参照資料、質問と確認操作。
- 下：工程番号、対象版、作業者条件、評価方法、結果、前後の工程と再生・停止。

画面には `作業者：成人 / 子ども＋大人`、`手袋`、`利き手`、`工具` の条件を表示する。
切り替えると対応する評価結果へ切り替わり、未評価の組み合わせならその状態を示す。
寸法線には何と何の間の距離かを示し、接近・操作・離脱のどの時点で最小になるかへ移動できるようにする。
色と同時に「工具の抜き取り経路が干渉」などの説明を出す。

小さな整備員は現在の工程を案内する。評価用の手は対象者条件に基づく実寸表示として別に持つ。
組立動画を停止しても、手順・向き・保持点・完了基準を静止図と文字で確認できる。
「工程を確認した」と「実物で実施・検査した」を分けて記録する。

## 8. 最終成果物へ追加するもの

| 出力 | 内容 |
| --- | --- |
| assembly/instructions.pdf | 部品・工具一覧、工程順、各工程の図と操作、担当、確認と戻し方、対象版 |
| assembly/steps.json | 工程ID、依存、開始・終了状態、部品・手・工具・条件・確認事項 |
| assembly/operator-profiles.json | 選んだ対象者・手袋・左右・寸法等の参照と適用範囲。保存する個人情報は必要最小限 |
| assembly/access-evaluations.json | 条件別・工程別の手と工具の経路、判定方法、余裕、干渉、未評価 |
| assembly/verification-records.json | 実物で組み立てた人・条件、観測結果、問題、資料、修正と再確認 |
| assembly/figures/ | 分解図、向き、手・工具の位置、干渉と改善前後の図 |
| videos/assembly-guide.mp4 | 同じ工程IDに対応する組立解説。章・字幕で工程へ移動できる |

PDFは対象者と工具の条件を冒頭に示す。条件が違う工程を混ぜず、分岐を識別する。
[PDFとテキスト・スクリプトの内容設計](export-content-spec.md)では、準備・工程・作業図・記録欄の構成と、共通の工程データから出す方針を具体化する。
PDFは標準出力としてWebから個別に保存できるようにし、印刷用の白地、対象版・工程ID・ページ番号、未記入の確認欄を持たせる。
[4ページのPDF見本](export-example/assembly/instructions-preview.pdf)と[工程の文章表示](export-example/assembly/instructions.md)で、構成と記入欄を確認できる。実機の確定手順ではない。
入力や評価が不足する場合、下書き資料と実機用の発行済み手順を分ける。レイアウト見本を実機の確定手順として扱わない。
実機の点検・回収装置の詰め直し・部品交換等の手順も、初回組立とは別の作業モードとして必要範囲を定義する。
まだ生成していない工程図や動画を完成済みとして表示しない。各ファイルを既存のマニフェストと版管理へ接続する。

## 9. 例示データと受け入れ条件

[assembly-contract.examples.json](assembly-contract.examples.json)は独立した説明用ケース。現在のAPI応答、実際の人体寸法、幾何計算、実物試行を表していない。

1. 成人と子どもの対象を選択でき、年齢帯や手袋が未設定なら判定を保留する。
2. 成人資料だけで子どもの対象を確認済みとしない。未入力寸法を0で補わない。
3. 同じ工程で、片方の条件で干渉があれば、両方に対応したという全体判定にならない。
4. 完成位置では干渉しなくても、工具の進入・回転・抜き取りで干渉があれば箇所と時点を示す。
5. 内部の作業前にカバーを閉じる順序を検出し、前提を満たす工程順へ戻せる。
6. 手や工具と把持対象の許可された接触は、周辺部品への干渉と区別される。
7. 必要な保持と操作を両手に割り当てられない場合、支援者・治具等の必要条件を示す。
8. 手袋、公差、治具、工具や作業者条件が変わると、対象の評価・手順・確認を旧版にする。
9. 幾何チェックだけ通っていても、力・保持・視認・実物試行を確認済みにしない。
10. 締結・接着条件の根拠が無いときは、値を生成せず不足事項として扱う。
11. 手順・部品図・部品表・組立動画が同じ機体・部品・工程の版を参照する。
12. アニメーションを止めても、作業内容と必要な確認を読み取れる。

## 10. 参照資料と未確定事項

確認日：2026-11-04。

- [河内まき子、2012：AIST日本人の手の寸法データ](https://www.airc.aist.go.jp/dhrt/hand/index.html)、[寸法項目一覧](https://www.airc.aist.go.jp/dhrt/hand/data/list.html)：対象集団・計測側・幅・厚さ・長さの項目定義を確認。寸法値の一式を本仕様へ採用したわけではない。
- [Cal/OSHA：Hand Tool Ergonomics – Select the Tool](https://dir.ca.gov/dosh/dosh_publications/handtools5.html)：作業、手に合う工具、利き手、手首の姿勢、持続した保持に対する固定具などの検討項目を参照。記載の数値を水ロケットの全作業へ一律に適用しない。
- [NASA-STD-3001 Volume 2の案内](https://www.nasa.gov/reference/nasa-std-3001v2/)：人とハードウェアの適合を将来のミッションで検討する資料。有人宇宙システム向けの適用範囲であり、水ロケットが同規格へ適合したという扱いにはしない。旧版の開口寸法を現在の共通閾値として採用していない。

次に確定する項目は、対象年齢帯、子どもと成人の作業分担、人体データ・実測方法、手袋と工具、最初に評価する組立工程、余裕と公差の根拠、実物試行の方法。
現行コードには、この手・工具・経路を使う組立性の判定器や詳細な組立手順生成は未実装。文章・動画の生成と、幾何・作業・実物の評価を分けて実装する。
