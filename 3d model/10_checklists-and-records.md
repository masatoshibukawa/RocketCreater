# チェックリスト、記録、再現保存

## 作る前

- [ ] 用途と最終寸法を決めた。
- [ ] FDMまたは光造形、機種、材料、ノズルまたは層高を決めた。
- [ ] 重要な面、測る寸法、必要な嵌合、外観の自由度を明記した。
- [ ] 参考画像と入力素材を使える条件を確認した。
- [ ] 生成、修復、書出し、試作、後処理まで含む予算を決めた。
- [ ] 成功判定と、最初に出す原寸の部分試作を決めた。

記入用：[project-brief.md](templates/project-brief.md)

## AI生成後

- [ ] 使用サービス/実装、モデル版、日時、入力、取得可能なseed/タスクIDを保存した。
- [ ] 元の形状と修正用コピーを分けた。
- [ ] 単色で全方向を見て、必要な凹凸が形状として存在する。
- [ ] 背面、底面、隙間、手足のつながりが意図どおり。
- [ ] 最終サイズで細部と接続が成立する見込みがある。
- [ ] 生成時点のプランと、非公開・帰属・配布に関する条件を記録した。

構造化記録：[project-record.example.json](templates/project-record.example.json)。内容は未実施のテンプレートであり、成功結果の例ではない。

## メッシュ/CADとスライス

- [ ] 実寸と単位が一致し、書出し後にも確認した。
- [ ] 意図しない破片、交差、開いた境界、薄壁を調べた。
- [ ] 必要な開口や穴は残り、必要な材料部分は閉じた体積になっている。
- [ ] 接合面と嵌合を、定義した隙間で原寸試作した。
- [ ] 荷重方向、表面、支持、分割を比較して向きを選んだ。
- [ ] 実際の機種、ノズル、材料、プレート/レジンに合うプロファイル。
- [ ] 全層を見て、消える壁、空中から始まる部位、支持、内部、上下面を確認した。
- [ ] プロジェクトと、機械用の最終データを区別して保存した。

## FDMの出力前・出力後

- [ ] 材料の状態、残量、もつれ、供給経路を確認した。
- [ ] プレートとノズルを指定の方法で準備した。
- [ ] 必要な校正を行い、初層と支持の接地を確認した。
- [ ] 薄い接続、橋、支持の立ち上がりを確認した。
- [ ] 指定の冷却・取り外しを行い、支持を除去した。
- [ ] 完成寸法と外観を確認し、材料・設定・写真を保存した。

## 光造形の出力前・出力後

- [ ] 材料SDS、保護具、洗浄・乾燥・硬化と廃液の場所を確認した。
- [ ] レジン・温度・層高・プロファイルを合わせた。
- [ ] island、初期接点、大断面、吸盤状の空洞を調べた。
- [ ] 中空部ごとに、排液・通気・洗浄・乾燥・必要な硬化ができる。
- [ ] タンク内の異物や損傷を、機種の手順で点検した。
- [ ] 材料に指定された洗浄、十分な乾燥、必要な二次硬化を行った。
- [ ] 指定された時点で支持を除去した。
- [ ] 中空部の状態を確認してから組立し、完成寸法を測った。
- [ ] 汚染した液と資材を、SDSと地域の手順に従って処理した。

## 失敗と試験の記録

印刷一回につき[print-log.csv](templates/print-log.csv)へ一行記録する。形状の版、プロファイルの版、方式、向き、材料、失敗位置、後処理、結果、写真を同じ試行IDで結び付ける。csvはUTF-8で保存し、表計算ソフトではUTF-8のCSVとして取り込む。

原因を調べる比較には[experiment-log.csv](templates/experiment-log.csv)を使う。変更する変数、固定した条件、測り方、単位、合格条件を先に書く。測れなかった項目をゼロで埋めず、未測定として扱う。

外形寸法や穴径だけでなく、どの段階で測ったかを残す。光造形なら洗浄後・硬化後、FDMなら冷却後・研磨後等を区別する。[S22: 後処理と寸法](https://formlabs.com/jp/blog/understanding-accuracy-precision-tolerance-in-3d-printing/)

## 推奨する制作データの構成

以下は今後の制作で使う構成例。この調査には実際の入力画像・生成物・機械用データを含めていない。

```text
project-name/
  brief.md
  references/           元画像・実測・出典
  generation/           元メッシュ・入力・生成条件
  working/              Blender/CAD等の編集原本
  print-mesh/           寸法確認済みのSTL/3MF等
  slicer/               配置・支持・機種・材料プロジェクト
  machine/              その構成用に作った実機データ
  trials/               試行ID別の写真・測定・失敗記録
  rights/               入力素材と生成サービスの条件・表示
```

モデル名には用途と版、mm単位の代表寸法を入れると探しやすい。機械用データには、少なくとも機種・ノズル/層高・材料・版を対応させる。タスクIDだけで元の条件を再現できるとは限らないため、入力と設定も保存する。APIキーや認証情報は記録用JSONやリポジトリへ入れない。

## 費用と時間を見積もる

```text
総費用 = 生成・再生成・修復・書出しの費用
       + 本体・支持・パージ・試験の材料費
       + 洗浄・硬化・仕上げの消耗品
       + 電力・外注・送料
       + 必要なら人の修正・監視・後処理の時間
```

サービスの月額だけを比較せず、採用できた一個あたりで見る。ローカル実行も、環境構築、GPU資源、メッシュ修正の時間がかかる。スライサーの表示時間と材料量は見積で、実測値とは分けて記録する。

再生成より短い局所修正で済む場合、全体を作り直す必要はない。逆に、ポーズや背面が大きく間違っているなら、修復に入る前に入力へ戻る。どちらを選んだかは修正見積で決める。

## ファイルや作品を外へ渡す前

- [ ] 提出するモデル、図、プロジェクト、URLの範囲を確定した。
- [ ] 編集原本、印刷メッシュ、機械用データの役割が分かる。
- [ ] 単位、最終寸法、対象機種と材料、後処理、検査条件を添えた。
- [ ] ファイル名、内部のオブジェクト名、コメント、絶対パス、リンク、プレビュー画像、3MF等のメタデータに不要な作業名がない。
- [ ] 依存する素材のライセンス、出典、必要な生成ツールの表示とAI利用申告を保持した。
- [ ] 書出しファイルを再読込し、アーカイブなら展開して、渡すURLなら実際に開いて確認した。
- [ ] 変更できないホスト名や共有履歴に問題があるなら、提出前に対象と影響を報告した。

提出のための名前整理と、正当な出典・ライセンス表示の削除は別に扱う。今回の成果物はこの`3d model`ディレクトリの調査と記録用テンプレートであり、第三者への最終製品や印刷適合証明ではない。
