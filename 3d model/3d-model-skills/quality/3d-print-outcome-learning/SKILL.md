# 試行結果を条件付きの改善へつなぐ

既存の[制作記録](../../categories/3d-model-records/SKILL.md)と写真・ログ・材料/機材情報を先に使い、同じ質問を繰り返さない。新たな印刷を依頼されていない場合は、比較と次の試験案までを作る。

## 一試行の結果を分ける

モデルのハッシュ、縮尺/姿勢、接地・支持、機種/FW、材料製品・色/状態、ノズル/コア、プレート/接着剤、スライサー/有効プロファイル、後処理を必要な範囲で残す。初層、全高、取り外し、寸法/嵌合/外観は別の結果にする。途中で倒れた試行は、初層に付いたことを理由に成功のまま残さない。

失敗した時刻・層/Z高さ、位置、写真、実際の症状を記録し、原因の仮説と区別する。「密着不足」「ノズル接触」「支持破断」「冷却不足」等を、写真一枚や終了表示だけで確定しない。指令速度と観測された動作も分ける。

## 知見の適用条件を照合する

[試行・知見テンプレート](../../../13_公開スキル比較と検証改善/outcome-lesson.example.json)は`proposed`から始める。試験済みの範囲、反例、未確認を残し、`trial_supported`を万能な設定にしない。

次の試行へ使う前に、少なくとも「現在の症状/工程」「機種とノズル」「材料製品と状態」「モデルの縮尺/姿勢/接地」「有効プロファイル」の関連条件を比較する。関係する条件が欠けている/違う場合は自動適用せず、新しい仮説か適用外とする。機種＋材料名だけの一致、単純なキーワード一致、同じ項目の最新値という理由では選ばない。

例えばフィンの終盤転倒で得たブリムと速度条件を、レジンの薄い耳やPETGの別形状へ移さない。別症状の古い知見を一括で重ねず、同じ設定に複数の案がある場合は根拠・条件・反例を比較する。元の試行と棄却された案を上書きしない。

## 次の比較試験

原因を切り分けられる最小の変更を選び、固定条件、変更項目、観察箇所、合格条件、終了/中断条件を先に記す。変更を束ねる必要がある場合は、一つずつの効果を特定できないことを残す。

嵌合は原寸片、顔は原寸の細部、背の高い部品の転倒は全高で必要な確認を行う。小片や短い初層試験から全高の安定を推定で合格にしない。異常後の残片・プレート等は機種手順で処理し、原因や条件が変わらないまま同じジョブを繰り返さない。

試行後に「何を観察したか」「何が改善したか」「未確認/悪化は何か」を更新する。恒久的なユーザー好みと工程上の技術知見は分け、勝手に好みを推定保存しない。記録だけでなく共有スキルへ反映する依頼では、根拠と適用範囲を保った必要な修正を行う。
