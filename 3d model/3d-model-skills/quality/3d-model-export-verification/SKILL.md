# 最終出力の寸法と形状を検証する

編集原本、比較元、実際に渡す出力を区別し、対象ファイルのハッシュ・単位・座標・姿勢と合格条件を残す。コードの変数、編集画面の寸法、修復の終了表示だけで出力を合格にしない。

## 寸法と姿勢を保つ

- 嵌合・穴・機能寸法がある場合、造形範囲に合わせる自動縮小を適用しない。収まらなければ向き、分割、対応機を比較する。縮尺変更を採用した場合は壁厚・隙間も再評価する。
- STLは単位を自己記述しない。案件の単位と実測から確定し、寸法が小さいことだけでm→mmと推測変換しない。3MFも使用ツールの単位・各オブジェクトの変換を読み、最終配置で測る。
- XYZは現在の造形姿勢で比較する。各軸の長さを並べ替えた「どこかの向きなら入る」判定を使わない。提案した回転は実際に適用し、接地と支持も再検査する。
- 造形範囲と使える範囲を分け、ブリム、パージ、除外領域、ヘッドとの干渉は[機種別条件](../../printers/3d-printer-profiles/SKILL.md)で確認する。

## 再読込と比較

出力を新規シーンへ再読込し、最終的な変換・モディファイアを反映した形状を検査する。ワールド座標とローカル法線を混ぜない。拡張機能がなく省略された薄壁・交差検査は未実施として残す。

同じ単位・基準面・座標・カメラで修正前後を比較する。外観は単色の正面/側面/背面、内部と嵌合は断面、局所変更は追加/除去体積の差分が候補。比較のための自動位置合わせや正規化で、位置ずれ・寸法変更を隠さない。想定した変更領域と、保持する穴・薄部・顔・キーを先に決める。

別部品は予定の個数と役割を確認する。常に一つのソリッドへ統合せず、意図しない浮遊片と正しい別部品を区別する。書出し時に失われたテクスチャや部品IDも記録する。

## STL寸法の補助スクリプト

[check_stl_export.py](scripts/check_stl_export.py)はPython標準ライブラリだけでASCII/バイナリSTLを読み、mm換算の軸別外形・境界・SHA-256を記録する。入力を変更しない。

```text
python <skill>/scripts/check_stl_export.py part.stl --input-unit mm --expected-mm 80 30 100 --tolerance-mm 0.1 --build-volume-mm 220 220 250 --xy-margin-mm 5 --out export-check.json
```

数値は記法の例。期待寸法・許容差・機械の範囲を案件から与える。許容差は造形精度の保証ではない。範囲判定は外形寸法だけで、実配置やブリム込みの経路判定ではない。薄壁、ソリッド数、閉じ方、穴径、強度は測らず`unmeasured`に残す。3MF/STEPをSTLへ変換して使う場合も、元データの部品・色・配置は別途確認する。

結果は[検証記録](../../../13_公開スキル比較と検証改善/verification-record.example.json)へ対応させる。スライス後は[実経路の確認](../3d-print-toolpath-review/SKILL.md)、実物の失敗は[試行と改善の記録](../3d-print-outcome-learning/SKILL.md)へ渡す。参考にした公開手法と採用しない条件は[比較記録](../../../13_公開スキル比較と検証改善/adoption.md)に残す。
