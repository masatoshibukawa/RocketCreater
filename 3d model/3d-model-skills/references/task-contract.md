# 制作・検証の共通条件

新規制作、工程をまたぐ修正、出力データの受け渡しで使う。依頼に関係する項目だけを確認し、既知の条件をユーザーへ聞き直さない。詳細な記入項目は既存の[仕様メモ](../../07_チェックと記録/templates/project-brief.md)を使う。

## 到達点と寸法

調査、参考画像、編集可能な形状、印刷用メッシュ、スライスデータ、実機造形、後処理のどこまで依頼されたか特定する。元ファイル、保存先、使用ツール、機種・材料、既存の承認を引き継ぐ。

- 用途、最終外形、単位、基準面、原点、重要な面、嵌合相手、荷重・環境のうち、作業に影響するものを記録する。
- 設計値、許容範囲、部品間の隙間、測定誤差を分ける。隙間は片側・直径差等の定義を付ける。
- 壁厚、接続部、必要な穴、支持痕を避ける面を確認する。機種・材料・層高の条件を外した万能値にしない。
- 嵌合や細部は同じ材料・向き・後処理で原寸の対象部分を試す。全体縮小を原寸の公差試験の代わりにしない。

## 根拠に合わせて状態を記録する

| 段階 | 確認できること | それだけでは確認できないこと |
| --- | --- | --- |
| 設計・指示文 | 意図、指定寸法、生成条件 | 生成後の実寸や形状 |
| ファイル確認 | 外形、断面、接続、メッシュ検査 | 実際の造形経路や物理性能 |
| スライス確認 | 対象プロファイルでの層・経路・支持 | 実機の成功、完成寸法、強度 |
| 実機と後処理 | 観察・測定した試行の結果 | 未試験の機種・材料・荷重での適合 |

未実施、確認済み、推定を分ける。測っていない値をゼロや合格で埋めず、`null`等で未測定として保持する。閉じたメッシュを防水・耐圧・安全適合の証明にしない。

## 外部サービスと実機

費用、素材の外部送信、実機開始の範囲を依頼と既存の承認から判断する。対象が既に承認されていれば重ねて確認しない。調査やローカル編集の依頼を、未承認の課金・アップロード・実機開始まで拡大しない。

承認や実機情報が必要なら、独立して進められるローカル編集・検査と候補ファイル・条件の整理を先に行う。対象と条件が確認できない機械用データは実行しない。異常が起きた工程は、原因や条件が変わらないまま繰り返さない。

## 次工程へ渡す

入力と編集原本、採用版、印刷用メッシュ、スライサープロジェクト、機械用データを区別する。確認済み・残る確認、変更理由、必要な表示・ライセンス条件を添える。[制作記録](../../07_チェックと記録/templates/project-record.example.json)は必要な項目だけコピーして使い、認証情報を含めない。
