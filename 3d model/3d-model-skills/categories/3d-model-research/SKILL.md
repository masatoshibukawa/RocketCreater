# 多言語調査と出典の管理

[多言語調査ノート](../../../08_多言語調査と出典/09_multilingual-research.md)と[出典CSV](../../../08_多言語調査と出典/sources.csv)から関連する資料を探す。CSVの`topic`と`referenced_categories`で絞り、全出典を一律に読み直さない。

## 問いと条件を絞る

疑問を、入力→生成→修正→設計→印刷→後処理のどの判断に必要かへ結び付ける。機種、材料製品、方向、層高、ソフト/モデル版、クラウド/ローカル、測定時点から適用条件を特定する。

料金、提供モデル、利用プラン、ライセンス、API/UI仕様、購入候補や現在の推奨は、利用時点の公式資料を閲覧して確認する。既存ノートの調査日を、再確認していない情報の確認日に置き換えない。

## 原語で確認する

1. 公式マニュアル、開発元のリポジトリ、規格、メーカーのTDS/SDS、研究原著を優先する。公式サイト内の一般ユーザー投稿と、提供元の説明を区別する。
2. 英・日・中・独・仏・西・韓の用語表から必要な言語を選び、対象の公式ドメインと機種・版・症状で検索する。言語数を満たすだけの検索を目的にしない。
3. 原文の条件と例外を確認し、日本語の要点と作業への影響に整理する。検索掲載本文だけで確認した場合はその範囲を明記する。
4. 翻訳・地域版の重複、未訳の本文、旧版、取得不能を区別する。同じ解説の翻訳を独立した実験の裏付けとして数えない。
5. 数値が違う場合は平均せず、測定対象、条件、最小造形値か耐久値か、角度の基準、片側隙間か直径差かを照合する。

一般的な3MFの機能と、その生成ツールの実際の書出し機能を分ける。公開実装の要求環境やライセンスを、同名系列のクラウド版へ当てはめない。

## 知見と出典を更新する

調査結果は観察された記載、そこからの推論、試作の提案を分け、根拠となるページを近くにリンクする。未確認の項目を断定せず、制作を左右する不足と次の確認方法を示す。

依頼が保存・更新を含む場合は、既存の出典IDと列を維持して新規IDを追加する。URL、言語、提供元、確認日、確認範囲、主題、適用条件を記録し、調査文書で参照するカテゴリーに合わせて`referenced_categories`を更新する。重複登録や既存IDの振り直しを避ける。

## 渡すもの

問いへの回答、適用条件、直接の出典、食い違いの理由、未確認と次の検証を返す。文献上の推奨を実機での検証結果へ変えない。制作へ進むなら[索引](../../SKILL.md)から該当工程を選ぶ。承認範囲と実施状態には[共通の作業条件](../../references/task-contract.md)を使う。
