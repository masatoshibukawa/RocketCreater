# チェック、記録、受け渡し

[チェックと記録の調査](../../../07_チェックと記録/10_checklists-and-records.md)と[共通の作業条件](../../references/task-contract.md)から、今回必要な記録・検査・提出範囲を選ぶ。記録だけの依頼を、新しい生成や印刷の開始へ拡大しない。

## テンプレートを選ぶ

| 記録 | コピー元 | 扱い |
| --- | --- | --- |
| 仕様と合格条件 | [仕様メモ](../../../07_チェックと記録/templates/project-brief.md) | 用途・最終寸法・重要面・嵌合・最初の試験を記入 |
| 制作全体の版と条件 | [制作記録JSON](../../../07_チェックと記録/templates/project-record.example.json) | 必要な項目を使い、未実施の状態から開始 |
| 一回の印刷と後処理 | [印刷ログCSV](../../../07_チェックと記録/templates/print-log.csv) | 一試行一行、推定と実測を区別 |
| 仮説を比較する試験 | [比較試験CSV](../../../07_チェックと記録/templates/experiment-log.csv) | 固定条件、変更項目、測り方、合格条件を先に記入 |

テンプレート原本を作業記録で上書きせず、依頼の保存先へ必要なものをコピーする。既存ログがある場合はその形式と試行IDを引き継ぐ。CSV/JSONは更新後に構文と列の対応を確認する。

## 記録をつなぐ

入力画像・指示文、生成サービス/実装と版、取得可能なseed・タスクID、編集原本、印刷メッシュ、スライサー、機械用データを同じ案件・版・試行へ対応させる。サービスの一時リンクだけを保存先にせず、認証情報は記録しない。

材料製品・色・ロット、方向、層高、プロファイル、後処理、測定時点を残す。設計値・見積・実測を分け、未測定をゼロで埋めない。実機や測定が未実施なら、完了フラグや合否を成功に変えない。

失敗結果も位置、層/時点、写真、変更点と一緒に保存する。[トラブル対処](../3d-model-troubleshooting/SKILL.md)で比較するときは、変更以外の条件が揃っているか確認する。

## 検収と受け渡し

1. 依頼された検査を、指定された後処理後の状態で行う。設計上の確認と実物の合格を分ける。
2. 渡すファイルとURL、用途、単位、最終寸法、機種・材料、必要な後処理、残る試験を確定する。
3. 編集原本、印刷メッシュ、対象構成用の機械データを見分けられる形にし、書出しを再読込して必要な寸法と部品を確認する。
4. 最終提出ならファイル名、内部名、コメント、絶対パス、リンク先と表示、プレビュー、生成物のメタデータを確認する。必要なAI利用申告、ライセンス、出典、著作者表示は保持する。
5. アーカイブは展開し、渡すURLは実際に開いて確認する。変更できない名称等は提出前に対象と影響を報告する。共有履歴の書換えや他者の表示の削除へ勝手に広げない。

成果物の所在、検査結果、未実施/未解決、再現に必要な条件を短く添える。外注への送信や公開は、整理・準備とは別に依頼された範囲で行う。
