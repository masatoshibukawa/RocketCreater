# AIによる3D形状の生成

[AI生成の調査](../../../02_AI生成/02_ai-generation.md)を参照し、[共通の作業条件](../../references/task-contract.md)から到達点と使用条件を確認する。指定済みのツール・素材・公開範囲を引き継ぐ。

## 入力とツールを決める

- 最終サイズ、正面、重要な凹凸、底面、部品数を決める。寸法拘束が中心なら[CAD設計](../3d-model-preparation/SKILL.md)を起点にする。
- 単一の被写体、読める輪郭、隠れにくいポーズを使う。複数視点は形・姿勢・装飾を一致させ、AIで補った背面を実測データと扱わない。
- 被写体、大きな形、姿勢と接続、底面、印刷条件を具体的に伝える。指示した寸法・厚み・閉じ方は生成後に検証する。
- クラウド/ローカル、モデル版、出力形式、GPUと依存関係、書出し・公開・帰属の条件を比較する。環境導入や有料処理は依頼の範囲で行う。

機能、料金、無料枠、ライセンス、API仕様は現在の公式資料で確認する。同じ系列でもクラウド版と公開実装を混ぜない。調査ノートのGPU値や対応OSを全版へ一般化しない。

## 生成して選ぶ

1. 元画像と加工画像、入力、実装/サービスとモデル版、取得可能なseed・タスクIDを保存する。
2. 輪郭と接続を比較できる案を作り、採用案だけを必要な精度へ上げる。単色印刷ではテクスチャやリギングより形状を優先する。
3. 単色で全方向を見て、背面、底面、手足、穴、浮遊片を確認する。表示用の点群等と、印刷へ渡す表面メッシュを区別する。
4. 最終サイズで細部と修正量を評価する。スライサーが使えれば早い段階で消える壁や過大な支持を調べる。
5. 採用理由と残る修正を記録する。同じ失敗が続いたら入力・姿勢・方式を見直し、原因が変わらないまま有料生成を繰り返さない。

テクスチャの模様はSTLへ変換しても凹凸にならない。元のGLB/OBJ等を残し、書出しで寸法・面数・カラーがどう変わるか確認する。

## 渡すものと確認

入力、生成条件、元メッシュ、採用案、単色での評価、修正点を[モデル修正と設計](../3d-model-preparation/SKILL.md)へ渡す。入力文や画面の見栄えだけで印刷可能と判定しない。

ツールが利用できない場合は入力と再現可能な設定・手順を作り、未生成と明記する。実在しないSTLや成功ログを作って生成済みと扱わない。
