# 初期機体の増強と並行比較

既存機体を複数の出発点にして探索する。候補数の増加は探索範囲を広げ、並行化は待ち時間を短くするための仕組みである。これだけでCFDの格子誤差や実機との誤差が減ったとは判断しない。

指定された資料収集の文献ブランチ（`research/redistributable-literature`, `3da2a93`、[PR #54](https://github.com/masatoshibukawa/RocketCreater/pull/54)）を参照した。登録値と出典は [initial_models.json](../rocketwright/catalog/initial_models.json)。ファイル単位のSHA-256、原著者、ライセンス、原リポジトリの固定コミットURLを持つ。取得コードやFreeCADマクロは実行していない。

| 系統 | 新しい出発点 | 採用した情報 | 主な簡略化・未確定値 |
|---|---|---|---|
| D09 RocketFins | 狭い3枚、広い3枚、狭い5枚 | 枚数、中心／先端弦長、半径90 mm、ボトル半径46 mm | 胴表面への投影、狭い翼の弦長拡大、翼型の平板化、首部取付の省略。容量・胴長・ノーズは仮定 |
| D22 0.5 L機 | 4枚フィンの近似機 | 容量、70 mm径、60 mmスパン、厚さ、ノーズの寸法 | 丸い翼を35/10 mmの台形に変更、丸いノーズを円錐化、胴長220 mmと取付位置を仮定 |
| D40 waterRocketToolbox | 1.5 L、2 L | シミュレータ定数の容量と100 mm径 | 胴長・フィン・ノーズは共通の仮定形状。多ボトルCAD組立の再現ではない |

追加は**3出典系統からの6派生候補**。以前の5出発点と合わせて11件。原型を完全再現した6機、あるいは独立した6件の実験データとは扱わない。材料・取付・その他部品質量は入力テンプレートから継承し、原資料のボトル単体質量を総乾燥質量へ置き換えない。市販ボトルの適合性や耐圧認定も継承しない。

OpenRocketのモーター・推力履歴を水ロケットへ転用しない。発射台のみのCADも機体候補に数えない。これらの資料は別途、形状抽出や数値検証の候補として残す。

## 固定条件での比較

`scripts.screen_initial_models` は11件を読み、圧力・水量比・ノズル・ペイロード・回収条件・抗力係数を入力に統一する。同一形状・同一物理入力になる候補は別名として記録し、重複計算しない。現在の1.5 L入力では3件が重複し、**8形状**となる。目標高度、環境、評価閾値は保持する。

各候補でCADを生成し直し、CAD体積から質量を再計算する。その後、熱→排出／推進→簡易空力の6自由度飛行→時間刻み半減／抗力係数+10%の感度解析を行う。以前の印刷質量、合格判定、原資料の飛行成績は再利用しない。

最大1〜4ワーカー（既定2）で独立実行し、候補ごとの時間枠を総予算÷候補数で先に固定する。全体の実時間締切も共有する。ワーカーごとにディレクトリと子プロセスを分け、タイムアウト時はそのプロセス群だけを終了する。BLAS/OpenMPのスレッド数は1に指定するが、CADエンジンの内部スレッド数全体を保証する設定ではない。GPU CFDとFEMはこの並行バッチに含めない。

完了順に関係なく入力順で集約し、失敗・適用域逸脱・時間刻み未達も保存する。変更されたソースの結果は候補選択に使わない。簡易空力の適用域と時間刻みの条件を通過したものだけを、元の高度・静安定余裕・迎角要求に対する不足量で仮順位付けする。高度だけで勝者を決めない。数値上の不合格と計算失敗は別に残す。

この比較はLLM呼び出しを必要としない。同一入力の比較後、保存した仕様を通常のローカルLLMによる適応探索へ渡せる。過去の学習結果は旧ソースに固定された証拠であり、新しいソースと同じ精度の学習例として自動的に読み替えない。

## 実行

リポジトリルートから、利用中のPython環境で実行する。出力先は未使用の短いパスを使う。

```powershell
python -m scripts.verify_initial_model_sources <文献ブランチの作業ツリー>
python -m scripts.screen_initial_models input.json output/is-p1 --workers 2 --budget-s 1800
python -m scripts.run_adaptive_design --spec output/is-p1/selected-cfd-compatible.json --root output/is-followup --runtime runtime.json --limits limits.json
```

`selected.json` は仮順位先頭、`selected-cfd-compatible.json` はそのうち現CFDが扱える4枚フィンの先頭。該当候補がなければ作らない。3枚・5枚を4枚へ勝手に変更しない。全結果・別名・エラー・費用・仕様・出典を `report.json` に保存し、各候補の `manifest.json` で入力と計算証拠を検証できる。

別コマンドの `scripts.run_design_search` は従来の逐次適応探索で、既定では全登録出発点を扱う。`--max-starts` は明示的な上限。今回の並行初期比較とは別の実行であり、前段の費用も合わせて評価する必要がある。

## 解釈の範囲

時間刻み差は離散化への感度、抗力係数+10%は仮定への感度であり、実機の信頼区間ではない。CFD/FEM、材料・取付の実測、圧力容器、回収・着地等の最終判定は未実施。この結果だけで製作・発射可能とは判定しない。
