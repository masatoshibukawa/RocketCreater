# 共通シーン・差分キャッシュの実測

採用版v4（1.5 L・搭載60 g・最低15 m要求）で、共通舞台、代表テンプレート、部分再利用、軽量プレビューを試した。初回の540pプレビューは6分18.1秒、同じ条件の再制作は11.4秒だった。後者は新しい形状の初回生成時間を表していない。

## 実装と役割

- Gemmaの保存済み演出案を使う。今回、新しいモデル推論・課金API呼び出しはない。
- スクリプトは採用版の実STLと計算軌跡を読み込み、機体の高さとフィン幅に合わせてcompact / standard / largeの舞台を選ぶ。機体形状を代表モデルに置き換えたり、拡大縮小したりしない。
- 作業台、地面、写真由来の環境・材質、照明、カメラをpacked Blender libraryとして事前準備する。舞台ファイルにはロケット・CAD・水・軌跡を含めない。3種類ともこのPCで生成済み。実機体の描画確認は自動選択されたcompactで行い、他のサイズの構図は単体テストの寸法確認まで。
- ハーネスは設計解説と飛行の描画キー、字幕の合成キーを分ける。プロジェクトID、履歴、保存先をキーに含めず、CAD内容・寸法・画質・実際に使う設計値・環境素材・描画コード・Blender版を照合する。軌跡は飛行側にだけ結び付ける。
- PNGとMP4は保存ハッシュを確認してコピーする。壊れたファイルは再利用しない。完成動画は全フレームのデコード検証後にキャッシュへ登録する。Windowsの一時的な置換拒否には上限付きで再試行する。
- 画面の「軽量プレビューを制作」は960×540・12fps・8 samples、本番は1920×1080・24fps・32 samples。どちらも16秒の解説と12秒の飛行。プレビューは本番と別の種類・ディレクトリで保存され、承認済み本番設定を変更しない。

## 計測結果

環境はWindows / RTX 4090 / Blender 5.2.2 LTS。各条件1回の観測で、素材・実行環境は導入済み。共通舞台の事前生成は別計測で、ライブラリ生成自体は各約0.67秒（Blender起動を除く）。

| 条件 | 対象 | 所要時間 | 実際の再利用 |
|---|---|---:|---|
| 初回プレビュー | 540p・12fps、計336枚 | 378.1秒 | 全336枚を描画。事前準備した舞台を使用 |
| 同一条件の再制作 | 同じ540pプレビュー | 11.4秒 | 全336枚とMP4 2本を再利用、描画ゼロ |
| 字幕だけ変更 | 隔離した同一設計のコピー | 10.5秒 | 描画ゼロ。設計解説の字幕を再合成、飛行MP4は再利用 |
| 軌跡だけ変更 | 隔離したソフトウェア検証用データ | 167.5秒 | 解説192枚とMP4を再利用。飛行144枚を描画 |
| 本番画質の比較用静止画 | 1080p・32 samples、計6枚 | 23.3秒 | 6枚を新規描画 |
| 同じ本番画質の静止画を別出力先へ | 同じ6枚 | 2.5秒 | 6枚すべてを再利用。PNGのバイト列も一致 |

初回プレビューは計測CLIから、同一条件の再制作は実際の画面のボタン → API → detached workerで実行した。11.4秒はサーバーの受付から登録完了までで、画面の次回ポーリング待ちは含まない。字幕・軌跡の条件は採用版を書き換えない独立コピーで測った。軌跡の高度を1%変えたケースはキャッシュ依存関係を検証する合成データであり、新しい物理解析・採用設計ではない。

以前の46分13秒は1080p・24fpsの描画に中断対応も含む。同じ画質の初回生成を今回6分へ短縮したという比較には使えない。今回の確実な効果は、確認用動画を早く出せることと、同じ条件・部分変更での再描画を減らせること。

## 品質と確認範囲

舞台を共通化し、被写界深度をf/8からf/11へ広げた。540pの設計・飛行それぞれ9時点、1080pの比較画像と2枚の全解像度静止画を確認した。透明胴体の輪郭、フィンとの接続、画面内の収まりは保たれている。大幅な写実品質向上を裏付ける結果は得ていない。540p・12fpsは構図確認用で、本番と同じ細部・滑らかさではない。

実保存シーンのノーズ1個とフィン4枚は、採用STLの頂点・面・印刷姿勢の寸法・尺度・配置と一致した。全7メッシュの頂点署名も以前の採用版映像と一致。プレビュー飛行144時点の位置は元の計算軌跡の補間と最大約0.0000009 m以内で一致する。CAD・質量・軌跡の入力、既存本番動画のバイト列は変更していない。

プレビュー2本は全336フレームをデコードし、統合画面で最後まで再生した。観測したコンソール・再生エラーはゼロ。既存本番2本と新プレビュー2本はAPIの返却バイト列と登録ハッシュが一致する。本番画質の新設定では静止画6枚を検証し、新しい1080p動画2本を通し生成する試験は今回行っていない。P12の数値条件・実機飛行・印刷認定の未完了項目には影響しない。

## 証拠と再実行

[計測・検査・動画・比較画像](../assets/product-demo/production-plan/video-reuse/)を保存した。`preview-cold.json`の`cold_frames`は古い出力ディレクトリの有無による推定値がfalseになっているが、`cache.clips`の`rendered`は192+144、`restored`は0であり、全フレームが新規描画された。生の計測記録を改変せず、集計結果では実際の描画枚数を使う。

描画ソースは`df32311`、API・プローブ・計測の追加ソースは`6cdae02`。最終の証拠コミットでは描画コードを変更しない。保存済み素材のライセンス・ハッシュは従来のappearance manifestを保持する。共有キャッシュはローカルの`output/`にありGitへ含めない。

```powershell
$env:PYTHONPATH = (Get-Location).Path
$env:ROCKETWRIGHT_BLENDER = 'C:/Program Files/Blender Foundation/Blender 5.2/blender.exe'
$env:ROCKETWRIGHT_RENDER_CACHE = (Join-Path (Get-Location) 'output/render-cache')
# 既存ジョブの検証済み素材を使って舞台を事前準備
& $env:ROCKETWRIGHT_BLENDER --background --python-exit-code 1 --python scripts/prewarm_video_scenes.py -- JOB.json $env:ROCKETWRIGHT_RENDER_CACHE
# 採用版から別の軽量プレビューを作る。既存動画がある場合は--regenerateを付ける
python scripts/verify_photographic_project.py PROJECT_ROOT PROJECT_ID NEW_REPORT.json --quality preview
# 元の採用版を編集しない字幕・合成軌跡・1080p静止画の比較。新しい出力先を指定する
python scripts/probe_video_reuse.py PREVIEW_JOB.json NEW_PROBE_DIRECTORY
```

ローカル画面の検証用に`ROCKETWRIGHT_NEXT_DIST`を指定すると、別のNext.jsビルド出力を使える。既存のプレビューサーバーと生成ファイルを取り合わずに同じソースを確認するための設定。
