# ローカルの作業場所

リポジトリ直下は `main` の確認場所にする。実装や調査は、同じ深さに置いた `.worktrees/<作業名>/` の個別ブランチで進める。直下の未コミット変更を消して切り替えず、先に出典ブランチ上へ保存する。

```text
RocketCreater/
├─ rocketwright/、api/、web/       アプリのソース
├─ docs/、examples/、tests/        説明・実行例・テスト
├─ UI/、AIvideo/、3d model/、文献/  分野ごとの資料と制作コード
├─ presentation-techniques/      発表資料
├─ .worktrees/                    進行中・未統合の作業コピー
├─ .cache/                        再利用するモデル・ダウンロードキャッシュ
├─ .local/                        ローカル環境・ツール・保全した作業データ
└─ output/
   ├─ archives/                  ZIP・tarなどの生成物
   ├─ images/                    画面確認用画像
   ├─ media/                     動画・音声の作業データ
   ├─ reports/                   検証・棚卸し・整理記録
   ├─ analysis/                  計算結果
   └─ previews/                  公開前のサイト書出し
```

`.worktrees/`、`.cache/`、`.local/`、`output/` はローカル用で、Gitには追加しない。納品に必要な小さな検証済み成果物は、用途を明示して `assets/` などに保存する。秘密情報や第三者資料の再配布条件は、配置の変更によって変わらない。

## 既存の参照先

以前の `output/<作業名>` などは、既存チャット・起動中のサーバー・実行環境が参照する場合がある。通常の保存先とGitの作業ツリー登録先を新配置へそろえ、旧パスからも参照できるようにする。稼働中の実体は元の場所に保持し、新しい入口をジャンクションにする。それ以外は実体を移し、旧パスをジャンクションにする。旧パスは通常のフォルダ表示では隠す。再帰的に削除する操作に、ジャンクションを渡さない。

直下にあった単独ファイルは内容を変えずに分類先へコピーし、元ファイルを隠して互換性を保つ。特に一時的なPythonスクリプトは `__file__` から旧配置を求める場合があるため、既存の呼出し先を維持する。`.local/maintenance/` のコピーは履歴確認用で、新しい起動コマンドとして扱わない。

仮想環境やモデルキャッシュには絶対パスが残る場合がある。移動後は、旧パスからの実行と新配置の参照を確認する。稼働中の処理を止めたり、環境を作り直したりして整理を強行しない。

## 完了した作業コピーを片付ける条件

1. 作業コピーのコミットが `origin/main` に含まれ、未コミット変更と未追跡ファイルがないことを確認する。
2. 開いているPR、進行中のチャット、起動中の処理が使っていないことを確認する。コマンドラインに名前がないサーバーもあるため、プロセスの実際の作業ディレクトリと使用中の実行環境も調べる。
3. 無視対象の生成物や実行環境も点検し、必要なものを `.local/retired-worktrees/` へ保全する。元のパスとコミットIDを整理記録へ残す。
4. `git worktree remove` で登録と完了済みのソースコピーを片付ける。未統合のブランチや保全用チェックポイントは残す。

整理の対応表と実行結果は `output/reports/workspace-organization/` を入口にする。Gitの登録先、旧パス、新パス、保存したコミット・生成物、検証結果をそこで確認できる。
