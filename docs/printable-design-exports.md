# 設計から3Dプリント用データを作る

確認した設計の寸法から、フィンと取付面、ノーズ、試着リングを生成し、形状検査、S5用スライス、検査記録付きZIPの保存までをローカルで実行する。以前の2 Lモデルをそのまま配る経路ではない。耐圧ボトルは市販品を使用する。

## 画面とAPI

- 製作フローでは「製作ファイル」→「この設計の印刷データを生成」。独立確認後に出力した `production/report.json` と `assembly.json` を、保存済みハッシュで検査してから使う。
- ボトル設計の候補画面でも、選択中の設計から同じ出力を生成できる。容量由来の代表寸法は未実測の仮定なので、試着リングで確認する。
- 成果物は部品ごとのmm単位STL・3MF、プレビューPNG、S5用UFP・G-code、形状・スライス検査JSON、設計と設定の由来を記録する `print-manifest.json`、一括ZIP。3MFは形状交換用で、Curaの設定付きプロジェクトではない。
- `GET /manufacturing/runtime`：ローカルの依存と対応プロファイル。
- `POST /manufacturing/packages`：`design`、任意の明示的な `geometry`、`printer: "s5-gray-aa04"` を渡す。
- `POST /workbench/projects/{id}/print-package`：現在の `revision` を渡す。製作ファイル未生成、古いrevision、改変済みの元ファイル、重複生成は拒否する。
- 各応答の `files[].url` から保存する。登録外のファイルや検査後にハッシュが変わったファイルは配信しない。

APIはローカルのWeb APIであり、課金型のモデルAPIを呼ばない。プリンターへの送信・印刷開始もこの生成経路には含めない。

## 対応環境

現在の機種別出力は **UltiMaker S5 / Tough PLA Gray / 左AA 0.4**。別機種・別材料を指定した場合は、検証したプロファイルの追加が必要。CuraEngine 5.12.0と既存のBlender、Cura材料定義を使う。実行時に新しいモデルやソフトを取得しない。

| 変数 | 用途 |
| --- | --- |
| `ROCKETWRIGHT_BLENDER` | Blender実行ファイル |
| `ROCKETWRIGHT_CURA_ENGINE` | CuraEngine 5.12.0実行ファイル |
| `ROCKETWRIGHT_CURA_RESOURCES` | Curaの `share/cura/resources` |
| `ROCKETWRIGHT_PRINT_ROOT` | 単体生成APIの出力先。既定は `output/print-packages` |

Web/APIの起動方法は [ローカル統合試験](workbench.md) を参照。製作プロジェクトは `?project=<32桁のID>` で再表示できる。

## 今回の失敗から変えた条件

実機では初層の密着を確認できたが、ユーザーの観察では終盤にフィンが倒れた。印刷プログラムの完了表示だけでは造形成功と判定しない。[映像と観察記録](../assets/print-trials/2026-11-06-fin-retry02/README.md) を保存した。

1. 除去するブリムを従来の7 mmから **20 mm以上、部品との隙間0 mm** にする。細長く高い部品は最大35 mmまで広げ、収まらなければ姿勢変更か分割を求めて停止する。
2. フィンの下辺が接地する角度を形状から計算する。すべてのフィンに45度を固定しない。構造部品の寸法を変えるのではなく、印刷姿勢を変える。
3. 初層の実押出し経路の凸包に、一様な固体と仮定したCAD重心の投影が2 mm以上内側にあることを検査する。これは形状上の支持条件であり、実際の充填後の質量分布、接着強度やノズル接触による転倒まで証明するものではない。
4. 指定値だけでなく、生成G-code中の実押出し速度を検査し、35 mm/sを超える場合は出力を止める。ブリムを含む押出し全経路もベッド内か確認する。

メッシュの閉鎖性、正の体積、自己交差、層の欠落、材料・ノズル・温度・機種、アーカイブCRCも検査する。自動縮小で寸法を合わせることはしない。元設計、寸法、パラメーター、プロファイル、実行エンジン、解決後の設定、出力のハッシュを記録する。

新条件の実機再印刷は未検証。`physical_print_verified` と `flight_validation_current` は `false` のままにする。初層だけでなく終盤の安定、取付寸法と品質を現物で確認する。元の紙製フィン等を印刷PLAへ置き換えるため、質量を測定して飛行・回収解析を更新する必要がある。

## Skills、LLM、ハーネス、スクリプトの分担

| 担当 | 実行すること |
| --- | --- |
| 3Dモデル・印刷のskills | 造形条件、点検、失敗時の切り分けを記述する知識源 |
| ローカルLLM | 利用可能な解析候補や、動画のカメラ・注目部位など制約付きの提案 |
| ハーネス | 採用設計とrevisionを固定し、入力範囲・根拠・ハッシュ・依存・結果を検査し、出力を登録 |
| 固定Python/Blender/Curaスクリプト | 数値計算、寸法付き形状、メッシュ検査、スライス、実経路検査、動画のラベルとMP4合成 |

LLMがG-codeや実行コマンドを直接生成する経路はない。動画も同じ凍結済み設計配置と飛行軌跡を使い、「動画」→仕上げを選択→ローカルLLMの演出提案→2本の制作→再生・MP4保存と進む。写真調は1920×1080・24 fps・設計16秒／飛行12秒、簡易CGは960×540・各4秒。どちらも音声なし。写真素材と照明の処理は既存の `AIvideo/pet-rocket/realism` と共有し、新しい設計を描く。参考用2 L完成映像は「設計例と資料」に別ケースとして表示する。

## 検証

`tests/test_manufacturing.py` は依存がある環境で、新しい1.5 L、2 L、製作フロー由来の形状を実際にBlender/Curaで生成する。寸法、閉じた3MF、ブリム、ベッド範囲、実速度、支持面余裕とダウンロード改変拒否を検査する。依存がなければ実生成ケースはskipと表示する。

```powershell
python -m pytest tests/test_manufacturing.py tests/test_ultimaker_slice_review.py tests/test_workbench.py
```

ソフトウェア検証と実機での成功確認は別記録として扱う。
