# 保存した設計から製作・映像へ

現行の工房画面の「比較」「組立」「出力」から、ペトロケの寸法を保存・編集し、同じ版のCAD、計算、印刷、組立PDF、動画を扱える。
保存済みの2 L参考動画と、新しく制作した設計の動画は別に表示する。
課金モデルAPIの有効化は不要。プリンターへの送信・印刷開始は行わない。

## 使い方

1. 「出力」で「寸法を確認して保存」または「表示中の案から新しい案件」を選ぶ。保存済み案件の選択と設計JSONの読込みもできる。
2. ボトル・ノーズ・フィンの寸法、枚数、肉厚、取付位置、印刷部品以外の乾燥質量、計算条件を確認する。初期寸法は容量からの仮定。部品を実測した場合だけ実測欄を使う。
3. 「CADと飛行を再解析」で、Blenderが同じ寸法の非耐圧部品を作って検査する。そのCADの一様固体の質量と、入力した他の部材の質量を飛行計算へ渡す。印刷部品の実測合計質量があれば推定を置き換える。
4. 結果と前提を確認して「この版を採用」。計算の未達案、古いrevision、解析後に変わったCAD・計算入力は採用できない。これは試作版の採用で、実機・回収・飛行の認定ではない。
5. 同じ採用版から組立PDF、S5用印刷データ、写真調または簡易CGの動画を生成し、個別保存または一括ZIPを作る。
6. 寸法や質量を編集して保存すると、新しい版になる。解析、採用、動画計画、出力一覧を引き継がない。過去の版のファイルは保持する。「この入力を新しい版に戻す」も、入力だけを復元して再解析する。

ヘッダーのJSON保存は、制作案件では入力specを保存する。読込み時は新しい未解析の案件として検査し、外部JSON中の合格結果・ファイルパスを信用しない。
APIの再起動後も案件、版、履歴、登録済みファイルを開き直せる。

## 共通データと適用範囲

`BottleDesign.geometry` にmm単位の共通寸法を保持する。飛行の基準断面積、解析外形、側面図・寸法要約、画面モデル、CAD、組立工程に同じ値を渡す。
旧形式の設計には代表形状を残し、制作案件に保存した後は明示的な形状に切り替える。

解析外形と画面の概略モデルは、穴・丸み・根元補強・取付部を省略した寸法付き包絡。
動画のフィンとノーズは、解析の質量算出に使った登録済みSTLを直接読み込み、同じ位置と枚数で配置する。別の固定機体のモデルへ差し替えない。
印刷時の再生成では、同じ入力だけでなくCADの体積も解析時と照合する。

- 対応する印刷プロファイル：UltiMaker S5 / Tough PLA Gray / 左AA 0.4。
- ボトルは市販品を無加工で使用する。耐圧容器・推進装置は生成対象外。
- 質量は実測またはCADの一様固体推定。充填後の質量、実際の重心、接着・固定・強度は別途確認する。
- 飛行の抗力係数、回収展開などは従来モデルの仮定を持つ。CADが一致してもCFDの精度・構造強度・実飛行の合格にはならない。
- 手や工具の実寸干渉、搭載・回収機構の詳細はこの機能に含まれない。組立PDFは具体寸法を使った試作・仮組みの手順と現物確認欄を出し、未確定の固定条件を創作しない。

## 動画とキャラクター

動画は採用版の凍結したCADと計算軌跡を使用する。Gemmaが登録済みの部位・カメラ・動きを提案し、固定スクリプトが数値・字幕・描画を決める。
標準の演出も選べる。写真調は1080p・24 fps・設計16秒と飛行12秒、簡易CGは各4秒。音声なし。
長い制作はHTTP 202で受け付け、同じ案件をポーリングして確認する。通信断で再投入しない。プロセス終了で中断した操作は、再起動後に未完了として残し、再試行できる。

整備員は待機中に見回し・道具を休め、点検中に計測・書込みを行い、完了後の6秒間は道具をトレーへ戻す。
エラー時は動きを止め、動作軽減・一時停止・非表示は演出だけに作用する。キャラクターの動作を実物の点検完了にしない。

## 保存とAPI

保存先は `ROCKETWRIGHT_DESIGN_ROOT`。既定は `output/design-projects`。
`state.json` と各 `vN/snapshot.json` を原子的に保存する。1 APIプロセスで実行し、同じ案件の操作をロックとrevisionで保護する。

| 操作 | エンドポイント |
| --- | --- |
| 一覧・新規 | `GET /design-projects` / `POST /design-projects {spec}` |
| 開き直し | `GET /design-projects/{id}` |
| 編集保存 | `POST /design-projects/{id}/edit {revision,spec}` |
| 旧入力の復元 | `POST /design-projects/{id}/restore {revision,version}` |
| CAD・計算 | `POST /design-projects/{id}/analyse {revision}` |
| 採用 | `POST /design-projects/{id}/adopt {revision}` |
| PDF | `POST /design-projects/{id}/manual {revision}` |
| スライス | `POST /design-projects/{id}/print {revision}` |
| 演出・制作 | `POST /design-projects/{id}/video-plan {revision,style,local}` / `render-video {revision,style}` |
| 一括ZIP | `POST /design-projects/{id}/archive {revision}` |
| 成果物 | `GET /design-projects/{id}/v{version}/files/{key}` |

未登録・改変済みのファイルは配信しない。ZIPには採用版の入力、部品表、工程、計算記録、CAD、生成済みの印刷データ・PDF・動画、ハッシュ目録と読取専用の整合検査スクリプトを収録する。
未生成の種類は目録とREADMEに明記する。ZIP検査合格と機体・造形成功は別の状態。

## 検証

Pythonでは版の無効化・復元、再起動、旧成果物の取得、改変拒否、JSON検査、課金API無効、PDF、ZIP整合、明示形状と解析・印刷の一致を確認する。
既存の1.5 L・2 L・製作フローの実CAD/スライスも回帰検証の対象。
ブラウザーでは保存・編集・再解析・採用・各出力・動画再生・再読込み・狭幅表示・演出の状態を実際のAPIで確認する。

新しいブリム条件の実機再印刷と、部品の実測質量を用いた飛行検証は未完了のまま記録する。
