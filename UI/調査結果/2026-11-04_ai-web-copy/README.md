## 今回の編集方針

1. 強調のために語句をかぎ括弧で囲まない。直接引用、実際のUIラベルの参照、作品名などの意味は保つ。
2. 見出し・説明・ボタンは、対象、動作、得られる結果を具体的に書く。詩的な演出は明示的に求められた場面へ限定する。
3. 利用者に関係しない開発の進捗や未実装項目を、サイトの見せ場にしない。
4. 料金、保存・送信、利用条件など、現在の行動に関係する条件は、その操作の近くに短く置く。
5. 開発者向けの検証結果・未完了事項と、サイト利用者へ見せる文章を別の目的で書く。

これはユーザーの指定に基づく、このスキル集での既定の文体です。研究が全ての詩的表現や括弧の使用を否定した、という意味ではありません。

## 主な発見

AIの文章に語彙・文法・修辞の偏りが見られる研究と、過剰な装飾・説明を減らす実務ガイドが見つかりました。日本語のかぎ括弧や、Webサイトで未完成事項を強調する現象の発生率を直接測った研究としては扱っていません。

利用者に何ができるかを具体化し、文章が必要か、どこに置くかを編集する方が、記号だけの削除や語尾の言い換えより今回の目的に合います。根拠と判断の対応は各資料に記録しています。
