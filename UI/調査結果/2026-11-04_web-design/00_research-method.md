# 00. 調査方法と読み方

## 調査の問い

今回扱うのは次の十項目です。

- 魅力あるWebサイトを組み立てる手順
- 参考サイトの実例と、目的に合った参考の見つけ方
- HTML・CSS・JavaScriptを使う制作の基礎
- 情報設計、階層、グリッド、余白、整列
- 配色、コントラスト、色の役割
- フォント選択、日本語と欧文の組み合わせ
- 文字の配置、行長、行間、見出し、数値
- SF映画に登場するシステムのような表現
- 「AI生成っぽい」と感じられる見た目の問題
- AIを使いながら個性と整合性を保つ方法

既存アプリの改修、サイトの公開、素材の購入はこの調査に含めません。調査資料はこのディレクトリ内で完結させます。

## 情報の区分

| 区分 | 何を意味するか | 読むときの注意 |
| --- | --- | --- |
| 規格 | W3C Recommendationに書かれた要件 | 適用条件、レベル、例外まで読む |
| 公式実装資料 | MDNなどのWeb技術説明 | 対応ブラウザは採用時に再確認 |
| 組織固有の規則 | 政府・製品のデザインシステム | その組織の数値を全サイトの義務にしない |
| 制作者の説明 | 映画UI制作者のケーススタディなど | 作品の目的と実用サイトの目的を分ける |
| 論文 | 特定の実験に基づく知見 | 実験対象を越えて一般化しない |
| 参考候補 | ギャラリーや製品サイト | 見た目の評価と使いやすさの評価を分ける |
| 本資料の提案 | 調査を踏まえた設計・作業例 | 仮説として試し、実際の内容で調整する |

W3CのUnderstanding文書は規格を説明する参考文書です。規範となる本文は [WCAG 2.2](https://www.w3.org/TR/WCAG22/)（S01）。この資料だけで適合を認定するものではありません。

## 実施した多言語探索

検索で候補を見つけ、なるべく発行主体のページを開き、関連する本文や公式説明を確認しました。以下は実行した検索語の代表例と、そこから選んだ資料です。検索語は次の調査にも使えます。

| 言語 | 実行した検索語の例 | 採用資料・得られた視点 |
| --- | --- | --- |
| 日本語 | `site.design.digital.go.jp タイポグラフィ カラー レイアウト` | デジタル庁。日本語本文と役割ごとの文字設定 |
| English | `site.w3.org WAI WCAG 2.2 contrast minimum text spacing animation from interactions` | WCAG。見た目の品質を検証可能な条件にする |
| Français | `site.systeme-de-design.gouv.fr fondamentaux typographie couleurs espacement` | DSFR。余白を関係性と階層に使う |
| Deutsch | `site.barrierefreiheit-dienstekonsolidierung.bund.de typografie kontrast webdesign` | 検索結果からKERNも確認。アクセシビリティを設計の土台に置く |
| Español | `site:developer.mozilla.org/es/docs/Learn_web_development diseño CSS tipografía` | MDNスペイン語版。HTMLの意味とCSSの役割 |
| 中文 | `site.ant.design/docs/spec 字体 版式 色彩` | Ant Design。書体の階層、数値の比較、色の役割 |
| 한국어 | `KRDS 타이포그래피 색상 site:krds.go.kr` | KRDS。本文・見出し・ラベルの区別、テーマ別の色 |

資料の言語が異なっても、同じ規格や共通の設計慣行に基づく場合があります。八つの独立した実証研究が一致したという意味ではありません。

## 確認の粒度

[sources.csv](sources.csv) の `verification` で確認方法を示します。

- `page_text`: ページ本文・該当説明をWeb取得で確認。
- `search_excerpt`: 検索結果の抜粋で確認。本文を読めなかった場合は根拠を限定。
- `partial`: ページは開いたが本文抽出が不十分。詳細説明の根拠には使わない。
- `redirect_page`: リダイレクト先を開いて内容を確認。
- 製品サイトの本文確認は、完成画面のピクセル比較・実機操作試験とは異なります。

実例サイトについて、ログイン後の機能、有料コンテンツ、全画面幅の表示、Lighthouse結果は評価していません。参考サイトの章に書く「見る場所」「取り入れ方」は、読者が観察するための設計上の提案も含みます。

## 採用と除外

公式規格、運営元のドキュメント、制作者自身の説明を優先しました。SNS上の「全部AIっぽい」といった投稿は問題意識の把握には役立ちますが、外観によるAI判定の根拠には採用していません。

検索で見つかった古いAnt Designのドキュメントは、現行の中国語ページに置き換えました。取得できなかったAsh Thorpの候補ページ、誤ったSANKOU候補URLは根拠に使わず、取得できた制作事例・SANKOU公式ページへ切り替えました。GodlyのURLは調査時にRecentへ転送されたため、現状を区別して記録します。

公開日・更新日が確認できないページには日付を推測して付けません。確認日は全件2026-11-04です。料金、ランキング、フォントやツールの最新バージョンを固定的なおすすめとして扱いません。

## 再調査の方法

1. 用途を決める。例: 「日本語の技術系アプリ」「写真中心のブランドサイト」。
2. 同じ意味の検索語を複数言語で試す。
3. まとめサイトから制作者・公式仕様へのリンクをたどる。
4. 発行主体、対象、更新日、実際に読めた範囲を記録する。
5. 採用する原則と、採用しない装飾を一つずつ書く。
6. 自分の内容で試作し、狭い画面と操作状態も検証する。

検索結果の量より、説明できる判断が増えたかを調査の完了条件にします。
