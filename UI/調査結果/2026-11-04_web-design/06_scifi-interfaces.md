# 06. SF映画のシステムのようなWebデザイン

## 1. FUI・HUD・実用UIを区別する

FUIはfictional / fantasy user interfaceなどの呼び方が使われる、物語の中の架空インターフェースです。HUDは視界へ情報を重ねる表示方法を指すことがあります。どちらも「黒地に水色の線」という一種類のスタイルではありません。

映画では観客に物語や人物の状態を伝えることが大切です。Webでは利用者が自分で操作し、長時間読む必要があります。映画の画面をそのまま再現するより、**機能・情報・世界観・動きのつながり**を学ぶ方が応用しやすくなります。

## 2. 制作者の一次資料から学ぶ

### Blade Runner 2049 — Territory Studio

[公式ケーススタディ](https://territorystudio.com/project/blade-runner-2049/)（S35）は、世界観と登場人物の立場に応じて技術の見え方を設計した経緯を説明しています。Kの機体では古さや傷み、Wallace側では幾何学的で抑制された表現という違いがあります。光学機器や物理的な素材の実験も制作に取り入れています。

**本資料の解釈:** 個性は「未来っぽい部品の数」より、「誰がどんな環境で使う技術か」という一貫した仮説から生まれます。研究室、公共機関、民間企業、個人の工作机では、同じ解析機能でも表現を変えられます。

### Oblivion — GMUNKとクレジット記載の制作チーム

[Oblivion GFX](https://gmunk.com/OBLIVION-GFX)（S36）は、機能性、抑制、統一した色の考え方、複数の画面にまたがるグラフィック言語を説明しています。監視・地図・機体情報など、用途に対応する画面を制作しています。

**本資料の解釈:** 全ての領域を飾るより、何を監視し、何が変化し、どこへ注目すべきかを先に決めると、実用的なSF表現へつながります。

制作物には複数人・複数社が関わります。代表者の名前だけで全画面を制作したと扱わず、各ページのクレジットを確認してください。

### 実在の科学アプリへ戻る

[NASA Eyes](https://science.nasa.gov/eyes/)（S34）も訪れ、対象・時間・視点・説明の関係を観察します。映画UIと実在の探索アプリを比較すると、装飾、説明、操作に必要な情報を分けて考えられます。今回は入口の公式説明を確認しており、各3Dアプリの操作検証は行っていません。

## 3. 世界観を先に文章で作る

本資料の提案する設計メモです。

```text
誰が使うか:
何を確認し、何を判断するか:
どんな環境・組織の道具か:
現在の技術から何が進歩した設定か:
何を精密に、何を簡略に見せるか:
警告はどの状態を意味するか:
この画面に必要のない表現:
```

例: 「静かな研究室で、複数のロケット解析案を比較する。数値と単位を明確にし、進行中だけ変化を強調する」。これだけでも、常時点滅する戦闘用HUDとは違う方向を選べます。

## 4. 表現を六つの層に分ける

| 層 | 要素 | 実装・運用の考え方 |
| --- | --- | --- |
| 構造 | 主図、条件、結果、履歴 | GridやFlexboxで意味のある領域に分ける |
| 文字 | 数値、単位、短いラベル、本文 | 数値と説明の書体・大きさを分ける |
| データ | 軌道、断面、分布、比較 | 軸、凡例、時間、出典を持たせる |
| 状態 | 待機、解析中、合格、失敗 | 色だけでなく文字や形でも示す |
| 表面 | 細い線、グリッド、質感 | 内容より弱くし、操作を妨げない |
| 時間 | 更新、展開、選択、警告 | 本当のイベントに対応させる |

最初は構造・文字・データだけで成立させ、表面と動きを最後に加えるのが本資料の提案です。

## 5. スタイルを混ぜすぎない

| 方向 | 印象を作る要素の例 | 向いている使い方 |
| --- | --- | --- |
| 精密な研究端末 | 明確な単位、基準線、抑えた色 | 解析、比較、計測 |
| 工業的な管制画面 | 機能ごとの領域、状態、短いラベル | 進行監視、ログ |
| 光学・有機的な装置 | スキャン、断面、質感 | 主図や導入の演出 |
| 古い端末 | 少数色、等幅、履歴 | 趣味的な体験や限定された表示 |
| 洗練された未来の製品 | 大きな余白、幾何形状、抑制 | 操作中心の未来的アプリ |

これらは制作の方向を話し合うための本資料の分類です。作品ジャンルの厳密な学術分類や映画の公式スタイル名ではありません。

## 6. 情報の意味に合う図を使う

円を並べるだけでは機能が伝わりません。

- 時系列は時間軸を持つグラフ。
- 回転・方位は角度や方向を示す図。
- 構造は断面や側面図。
- 複数試行のばらつきは分布や散布図。
- 処理段階は履歴や工程の一覧。
- 比較は共通の単位を持つ表。

「高度」「速度」「費用」へ同じ円形ゲージを付けると、それぞれの判断に必要な情報を失う場合があります。図の種類は見せたい問いから選びます。

## 7. Webで作る技術を選ぶ

| 技術 | 選ぶ場面 | 注意 |
| --- | --- | --- |
| HTML / CSS | 文字、表、パネル、主操作 | 意味とキーボード操作を保ちやすい |
| SVG | 軸、図面、少数のベクター要素 | 説明と代替情報を付ける |
| Canvas | 多数の描画要素を更新する場面 | 描画だけでは内容や操作の意味が伝わらない |
| WebGL | 3Dや大量の描画が必要な場面 | 負荷、対応端末、代替表示を検討 |
| CSS / Web Animations | 状態の変化や展開 | 動き軽減と停止時の表示も設計 |

線が少ない機体の側面図なら、まずSVGで十分かを検討します。技術名から逆算して3Dを足す必要はありません。

## 8. 装飾の小さなCSS例

以下は独自の提案例です。背景グリッドと角の印だけに限定しています。

```css
.instrument {
  position: relative;
  padding: 1.5rem;
  background-color: #121d27;
  background-image:
    linear-gradient(#e6edf308 1px, transparent 1px),
    linear-gradient(90deg, #e6edf308 1px, transparent 1px);
  background-size: 2rem 2rem;
  color: #e6edf3;
}
.instrument::before {
  content: "";
  position: absolute;
  inset: 0.5rem auto auto 0.5rem;
  width: 0.8rem;
  height: 0.8rem;
  border-top: 1px solid #67e8f9;
  border-left: 1px solid #67e8f9;
  pointer-events: none;
}
.instrument__status {
  font-variant-numeric: tabular-nums;
  color: #9aaaba;
}
```

この弱いグリッドは装飾用であり、計測グラフの読み取りに必要な線へ転用する場合はコントラストを再検査します。装飾を操作対象の上に置くときは、クリックやフォーカスを邪魔しないようにします。

## 9. 動きには理由と終わりを持たせる

**本資料の試作上の目安:** 小さな状態変化は120〜220ms、パネル展開は180〜320ms程度から試す。規格による推奨時間ではありません。追跡が必要な移動は理解できる速度にし、日常操作を毎回長い演出で待たせないようにします。

| 動き | 意味がある場面 | 避けたい使い方 |
| --- | --- | --- |
| ハイライト | 更新された値を示す | 全ての値を常に明滅 |
| 線の描画 | 利用者が再生した軌跡を示す | 毎回、図が読めるまで待つ |
| パネル展開 | 選んだ項目の詳細を示す | 画面全体を大きく揺らす |
| ローディング | 実際に待機している | 架空の処理を行っているように見せる |

## 10. 動きの要件を混同しない

- [2.3.3 Animation from Interactions](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html)（S06）は**AAA**です。非本質的な操作起因の動きを無効化できる条件です。
- [2.2.2 Pause, Stop, Hide](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html)（S48）は**A**です。自動で始まり、5秒を超え、他の内容と並行する動き等には停止手段などが求められます。本質的な場合の例外があります。自動更新の情報には同じ5秒の猶予があるわけではありません。
- [2.3.1 Three Flashes or Below Threshold](https://www.w3.org/WAI/WCAG22/Understanding/three-flashes-or-below-threshold.html)（S49）は**A**です。閃光の制限には頻度・面積・強さなどの条件があります。見た目だけで安全と判断せず、強い点滅を最初から避けます。

動き軽減の実装には [prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion)（S43）を使えます。

```css
.panel {
  opacity: 1;
  transform: none;
}
@media (prefers-reduced-motion: no-preference) {
  .panel { animation: reveal 180ms ease-out; }
  @keyframes reveal {
    from { opacity: 0; transform: translateY(0.3rem); }
    to { opacity: 1; transform: none; }
  }
}
```

動きがなくても最終状態を表示する例です。JavaScriptでCanvasや動画を動かす場合も設定を確認し、CSSだけで全ての動きが止まるとは考えません。利用者が再生した可視化には停止操作も用意します。

## 11. SFらしさを弱めずに使いやすくする

本文を読める大きさにする、主操作を普通のボタンとして扱う、数字に単位を付ける、更新時刻を示す、出典へ進める。こうした確かさも「精密なシステム」の印象を作ります。

無意味な小文字列、偽の警告、実データに見える乱数、クリックできない操作風の装飾は増やさないようにします。デモ用の架空データは明確にラベルを付けます。世界観の一貫性と、道具としての理由を両立させることが、この資料で提案するSFデザインです。
