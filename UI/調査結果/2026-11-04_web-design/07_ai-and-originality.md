# 07. 「AIっぽさ」を避け、AIと一緒に設計する

## 1. 外観から制作手段は断定できない

紫のグラデーション、Inter、角丸カード、bento grid、暗色テーマは、人間もAIも使う表現です。これらを使っただけでAI生成とは判断できません。

本章でいう「AIっぽさ」は、**対象に固有の内容や判断が見えず、汎用テンプレートを当てたように感じる状態**を指す便宜的な言葉です。科学的なAI検出指標ではありません。改善すべき対象は、色そのものより、内容と構造の関係、細部の一貫性、実際に使える状態です。

## 2. 研究から言える範囲

DoshiとHauserの[研究概要](https://arxiv.org/abs/2312.00506)（S37、v3、2024）は、AIのアイデアを参照する短編執筆の実験で、個々の作品の評価改善と、作品同士の類似性の増加を報告しています。関連する査読論文は [Science Advances, DOI: 10.1126/sciadv.adn5290](https://doi.org/10.1126/sciadv.adn5290) です。

これはWebサイトの外観を判定する実験ではありません。「AIを使うと必ず同じWebサイトになる」「特定のフォントがAIの証拠になる」という結論には使えません。

[Nielsen Norman Groupの2026年の分析](https://www.nngroup.com/articles/state-of-ux-2026/)（S38）は、利用者理解と判断による差別化を考える実務資料です。こちらも外観のAI判定を検証する研究ではありません。

以下はこの区別を踏まえた**本資料の観察仮説と制作提案**です。

## 3. 定型的に見える要因と改善

| よくある見え方 | 問題になる条件 | 改善する方向 |
| --- | --- | --- |
| 大きな中央見出しと説明、二つのボタン | 何をするサービスか具体的に分からない | 利用者の仕事と実際の画面を見せる |
| どこでも同じ三枚カード | 内容の違いを構造へ反映していない | 手順は工程、比較は表、物語は本文へ |
| 大きなbento grid | 見る順序と各枠の意味が曖昧 | 主従と、枠同士の関係を決める |
| グラデーションや光が多い | 強調が分散して内容が弱い | 強調の対象と面積を絞る |
| アイコンが大量にある | 見出しと同じことを繰り返すだけ | 必要な意味のある場所へ絞る |
| 「革新」「可能性」「次世代」が続く | 主張を裏付ける実例がない | 具体的な対象、操作、成果へ書き換える |
| 架空の利用者数や推薦文 | 本当の実績に見せている | 確認済みの実績だけを使う |
| 抽象的な3D球体が主役 | 扱うサービスとの関係が弱い | 固有の対象物や図を主役にする |
| 角丸・線・影がばらばら | 生成のたびに局所的な判断が増える | トークンと役割を共通化する |
| 正常時だけ整っている | 入力不備や処理中が未設計 | 状態と次の行動を先に定義する |
| PCだけきれい | 日本語の長文や狭い画面を後回し | 最長ラベル、最小幅、拡大で確認 |
| 毎回同じ派手な動き | 操作やデータ更新と無関係 | 変化の意味がある場面へ限定 |

禁止事項を増やすだけでは、別のテンプレートへ移るだけになることがあります。「なぜその形を使うか」を説明できることを基準にします。

## 4. 個性を作る入力を用意する

AIへ「かっこいいサイトを作って」と渡す前に、次を用意します。

1. 誰のどんな用事を助けるか。
2. 実際の見出し、本文、ラベル。
3. 固有の写真、図、データ、工程。
4. 参考3件ほどと、それぞれから取り入れる一点。
5. 読みやすさ、画面幅、操作状態などの条件。
6. 採用する色・文字・余白のルール。
7. 評価の基準と、優先する順序。

資料が足りない箇所は「未提供」と伝え、AIに実績や数値を補わせません。

## 5. 一度に完成形を求めず、判断を分ける

**本資料の推奨する分け方**です。

| 段階 | AIへ任せやすいこと | 人が決めること |
| --- | --- | --- |
| 調査 | 資料の分類、疑問の列挙 | 採用する根拠、参考の適合性 |
| 内容 | 見出し案、文章の整理 | 言いたいこと、事実、語調 |
| 構造 | 方向の異なるレイアウト案 | 利用者の優先順位 |
| 表現 | 色・文字・線の試案 | 方向の選択と一貫性 |
| 実装 | 決めた仕様のコード化 | 実画面と操作の確認 |
| レビュー | 抜け、矛盾、状態の洗い出し | 何を直し、何を残すか |

AIに設計と採点を一度に任せると、同じ判断を繰り返して正当化する可能性があります。複数案の違いを明確にし、実際の内容と操作で比較します。これは万能な防止策ではなく、判断を可視化する運用です。

## 6. 指示の改善例

### 曖昧な指示

> 未来的でかっこいいロケットのWebサイトを作って。

何を主役にするか、利用者が何をするか、どの程度の情報量が必要かが未定です。

### 設計判断を渡す指示の例

```text
目的:
自然文で要求を入力し、シミュレーション済みの設計案を比較する画面。

対象:
宇宙や工作に関心はあるが、解析の専門家ではない日本語話者。

主役:
機体側面図、要求との比較、解析の進行。
数値は提供済みのツール結果を表示し、出典へ進めること。

表現:
静かな研究端末。Mission controlの役割別パレットを出発点とする。
長い説明はゴシック、計測値とIDだけに等幅を検討する。

参考:
各参考URLと、取り入れる具体的な一点を別途提示する。
映画画面は世界観の参考とし、本文や操作を小さくしない。

最初の出力:
A: 機体図中心、B: 比較表中心、C: 解析履歴中心の三案。
色違いではなく、情報の優先順位を変える。
まず文章の順序とワイヤーフレームを説明する。

必須の状態:
空、入力不備、解析中、合格、条件未達、通信失敗。

評価:
主操作が分かるか、比較できるか、根拠を読めるか、
狭い画面と動き軽減設定でも成立するか。
```

これは指示の型です。参考URLや実データは実際に提示し、空欄のまま「提示済み」と扱わないでください。

## 7. 初稿を編集する具体策

### 内容を変える

「革新的なAIで無限の可能性を」なら、「要求を入力し、設計案を解析・比較する」へ。抽象的な感情語を、対象と動詞へ変えます。

### 構造を変える

「特徴三枚」を、実際の流れに合う「入力 → 検証 → 比較」へ。比較が中心なら、カードの説明文より共通項目の表を作ります。

### 素材を変える

汎用の光る球体を、機体図、材料、解析経路、現場の写真など、内容に固有の素材へ変えます。自作する場合も、実在資料を誤認させないようにします。

### 細部をそろえる

角丸、線幅、アイコン、見出しの余白、単位の位置、ボタンのラベルを整理します。「この箇所だけ別の作者が作ったように見える」部分を探すと、分割生成の継ぎ目を発見できます。

### 意図のある例外を残す

全てを平均化しません。主図だけ大きくする、ある節だけ本文を深く読ませる、見出しの構図に特徴を持たせるなど、目的を説明できる例外を残します。

## 8. 人の関与を確認するレビュー

「AIっぽさスコア」は付けません。代わりに、次の問いへ具体的に答えます。

- サービス名を別の名前へ置き換えると、内容がそのまま成立してしまわないか。
- この図や文章を選んだ理由は何か。
- 各節の構造は内容の違いを反映しているか。
- 実際の利用者の疑問に答えているか。
- 例外、失敗、制約も誠実に見せているか。
- 利用者にとって普通である方がよい操作まで、独創的にしていないか。
- 最後の判断を、生成結果の雰囲気だけで決めていないか。

定番の書体や部品を使っても、内容、編集、関係性、状態がよく設計されていれば個性を作れます。意外な装飾を足すことだけを差別化の方法にしないようにします。
