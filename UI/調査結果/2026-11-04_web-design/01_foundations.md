# 01. かっこよさを支えるデザインの基礎

## 1. 見た目の前に「画面の仕事」を決める

かっこよい画面でも、何のサイトか分からない、次の操作を探す、文章が読めない状態では使い続けにくくなります。まず次の三文を埋めます。

> このサイトは【誰】のためにある。
> 訪問者は【何】を知り、【何】をする。
> このサイトらしさは【具体的な内容・視点】で表す。

例えばRocketWrightなら、「自然文で要求を伝える人が、シミュレーションした設計案を比較し、根拠を確認する」。ここから、入力、進行、比較、根拠という順序が生まれます。宇宙の背景画像だけでは、この固有性は伝わりません。

これは本資料の提案です。以降の基礎原則も、外部資料の規則を丸写しせず、制作のために整理しています。

## 2. UX、UI、ビジュアルデザインをつなげる

| 観点 | 決めること | 例 |
| --- | --- | --- |
| UX | 目的を達成できる流れ | 失敗した解析を修正して再実行できる |
| 情報設計 | 何をどこで見せるか | まず合否、次に指標、その後に詳細 |
| UI | 操作・状態・応答 | 実行中、取消、完了、再試行 |
| ビジュアル | 階層と印象をどう表すか | 主結果を大きくし、補助情報をまとめる |
| 実装 | 実際の端末で成立させる | 読み順、可変幅、フォーカス、読み込み |

色や書体の定義だけでなく、レイアウト、余白などを共通のルールとして持つ考え方は、[デジタル庁のローカルデザインシステム](https://design.digital.go.jp/dads/guidance/local-design-system/)（S39）でも整理されています。

## 3. 階層: すべてを同じ強さにしない

視覚的な階層は、大きさだけでは作れません。位置、余白、太さ、明度差、面積、動きも注意を引きます。

例として、解析結果を次の順で見せます。

1. **結果:** 要求を満たしたか。
2. **主要な理由:** 目標との差、制約。
3. **比較:** 他の案との違い。
4. **根拠:** モデル、条件、出典、詳細。

全部を太字・アクセント色・カードにすると、優先順位が消えます。主役を選び、背景に置く情報も選ぶことが編集です。

### 手を動かす練習

同じ内容を、見出し、本文、補足という三段階だけで組みます。色は一色にして、文字サイズと余白だけで読めるか確かめます。読める構造になってから色を戻します。

## 4. 近接: 余白で意味を分ける

ラベルと入力欄は近く、別の質問とは離す。見出しは、前の節よりも後ろの本文に近づける。余白は空いている場所であり、情報の関係を示す記号でもあります。

フランスの[DSFRの余白ガイド](https://www.systeme-de-design.gouv.fr/version-courante/fr/fondamentaux/espacement)（S09）は、関係する要素には小さい間隔、独立する要素には大きい間隔を使う考え方を説明しています。4pxや8px系の値は同システムの運用方法で、Web全体の必須規格ではありません。

**本資料の初期案:** 内部の間隔を8〜16px、グループ間を24〜32px、節の切り替えを48〜96px程度から試す。文章量と画面幅で調整します。値を機械的に守って見出しと本文が分離するなら、関係性を優先します。

## 5. 整列: 見えない線を減らす

左端、文字の基線、画像の端、数値の列をそろえると、画面の構造を見つけやすくなります。

- 長い本文は左そろえから始める。
- 比較する数値は右そろえ、小数点の桁や単位も統一する。
- 見出しと本文の開始位置をそろえる。
- 中央そろえは短い宣言や小さなまとまりに絞って試す。
- 非対称にするときも、基準になるグリッドを残す。

整列とは、すべてを左右対称にすることではありません。大きな図と細い説明欄を組み合わせても、始点と間隔が整理されていれば秩序を作れます。

## 6. 対比: 一つの違いをはっきり作る

「少しだけ違う」が積み重なると、意図が曖昧になります。同じ役割はそろえ、違う役割には理解できる差を付けます。

| 曖昧な例 | 改善案 |
| --- | --- |
| 見出し18px、本文17pxで太さも同じ | 見出しを大きくするか、太さと上余白を変える |
| ほぼ同じ灰色のボタンが複数 | 主操作、補助操作、危険操作の役割を分ける |
| 似た角丸が多数 | 少数の角丸トークンにまとめる |
| 全グラフが発光する | 選択中・警告中など意味のある対象だけ強調 |

コントラストは見た目の好みだけで決めず、文字や操作対象の要件を確認します。具体的な判定は配色の章で扱います。

## 7. 反復と変化: 統一した上で見せ場を作る

統一する候補は、余白、角丸、文字階層、アイコン、線の太さ、状態色です。変化を付ける候補は、主図の大きさ、節の構造、写真のトリミング、見出しの構図です。

「全て同じカード」は整理の手段として便利ですが、内容の性質が違うのに同じ構造へ押し込むと単調になります。

- 手順は番号と時間軸。
- 数値の比較は表やグラフ。
- 記事は読み進められる本文。
- 作品は画像と説明。
- 意思決定は選択肢と根拠。

内容が求める形を選ぶと、装飾を増やさずに変化を作れます。

## 8. 密度と余白を用途に合わせる

ポートフォリオ、ニュース、監視画面、申請フォームは、同じ余白と文字サイズでは成立しません。密度を上げるときも、文字を小さくする前に、重複、見出し、列、表示タイミングを整理します。

[Ant Designの字体ガイド](https://ant.design/docs/spec/font-cn)（S12）は業務画面の文脈で文字体系を説明しています。一方、[GOV.UKの本文ガイド](https://design-system.service.gov.uk/styles/paragraphs/)（S08）は本文の役割に応じた文字設定を持ちます。この違いは「どちらかが間違い」ではなく、目的と対象が違う例です。

## 9. ブランドの個性を内容に根づかせる

次の問いに答えると、テンプレートを越える材料が見つかります。

- このサービスしか扱わない対象物は何か。
- 実物、現場、手順、履歴のうち何を見せられるか。
- 利用者が比較したい量は何か。
- 運営者が大切にする言葉や視点は何か。
- 「安心」「技術」「遊び心」を、何で証明するか。

ロケット解析なら、機体の側面図、試行の履歴、条件付きの合否、単位付きの指標が固有の表現になります。「未来」「革新」という抽象語を増やすより、実際の仕事を見せる方が設計の理由を説明できます。

## 10. 初稿を直す順番

**本資料の提案する順序**は、内容 → 情報の順序 → 大きな配置 → 文字 → 余白 → 色 → 細部 → 動きです。

スクリーンショットを縮小して主役が分かるか、見出しだけ読んで内容が分かるか、最初の操作が迷わず見つかるかを確かめます。最後に実物を操作して、見た目だけでは分からない状態も確認します。
