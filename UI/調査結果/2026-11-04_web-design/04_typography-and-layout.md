# 04. フォントと文字の配置

## 1. フォントの名前だけで完成させない

書体を選ぶことと、読みやすい文字組みを作ることは別です。サイズ、太さ、行間、字間、行長、そろえ方、周囲の余白を一緒に決めます。

| 種類 | 向いている役割 | 確認すること |
| --- | --- | --- |
| サンセリフ / ゴシック | UI、説明、技術的な内容 | 小サイズで字形を区別できるか |
| セリフ / 明朝 | 記事、文化、編集的な印象 | 細い線が画面で消えないか |
| 等幅 | コード、識別子、桁を比較する表示 | 長い日本語本文まで等幅にしていないか |
| ディスプレイ書体 | 短い大見出し、タイトル | 装飾性が内容の理解を妨げないか |

これは用途を考えるための分類です。「明朝は必ず高級」「等幅なら必ずSF」といった固定的な意味はありません。内容、組み方、文化的文脈でも印象が変わります。

## 2. 最初に検討しやすい組み合わせ

次は**本資料の選定案**です。実サイトが使用する書体を断定する表ではありません。

| 方向 | 日本語の候補 | 欧文・数値の候補 | 使い方 |
| --- | --- | --- | --- |
| 読みやすい技術サービス | Noto Sans JP / 源ノ角ゴシックJP | Inter | 本文を安定させ、数値の太さと桁を調整 |
| 工業的な計測画面 | システムのゴシック / IBM Plex Sans JP | IBM Plex Sans / Mono | 等幅をラベル・ID・数値に限定して試す |
| 編集的な読み物 | 使用権を確認した明朝 | セリフ書体 | 見出し・本文・注釈の役割を分ける |
| 軽量な初期実装 | system-uiと日本語フォールバック | 同じスタック | Webフォントを導入する前に構造を確認 |

公式配布元: [Inter](https://rsms.me/inter/)（S21）、[Source Han Sans](https://github.com/adobe-fonts/source-han-sans)（S22）、[IBM Plex](https://github.com/IBM/plex)（S41）。Interには等幅数字などのOpenType機能がありますが、日本語全文をInterだけで表示できるとは扱いません。

[デジタル庁](https://design.digital.go.jp/dads/foundations/typography/)（S07）はNoto Sans JPとNoto Sans Monoを採用しています。これは参考になる選択例で、全サイトで同じ書体を使う義務ではありません。

## 3. 日本語と欧文を合わせるとき

同じ16pxでも、書体によって見かけの大きさ、字面、基線、太さが違います。実際の文章で確認します。

```text
飛行解析レポート / Flight analysis
機体ID: RW-EXAMPLE-001
最大高度: 1,234.5 m
O 0 / I l 1 / − – - / μ m / ℃ °C
「設計条件」と（解析モデル）の確認
```

ここにある値とIDは**文字表示確認のための架空の例**で、解析結果ではありません。

確認点:

- 漢字、ひらがな、英小文字、大文字の見かけの大きさが極端に違わないか。
- 0とO、1とlとI、マイナス記号の区別が必要か。
- 日本語部分だけ別フォントに切り替わったとき、行の高さや改行が崩れないか。
- 日本語、中国語、韓国語で地域に適した字形を使う必要があるか。
- 太字が実際のウェイトで表示されているか。

`lang="ja"` などの文書言語を正しく設定し、必要なら欧文の数値部分へ別クラスを使います。装飾用に無意味な英文を増やすより、利用者が理解できるラベルを優先します。

## 4. 文字階層の初期案

次の数値は**本資料の試作用の目安**であり、WCAGの一律最低文字サイズではありません。

| 役割 | サイズの初期案 | 行高の初期案 | 備考 |
| --- | --- | --- | --- |
| 大きな見出し | 32〜64px | 1.15〜1.35 | 日本語の行数と改行位置を確認 |
| 節の見出し | 24〜32px | 1.3〜1.5 | 上下余白で本文との関係を作る |
| 長い日本語本文 | 16〜18px | 1.7〜1.9 | 文字の複雑さと行長で調整 |
| UIのラベル | 14〜16px | 1.4〜1.6 | 長いラベル・拡大時も収まるか |
| 補足 | 14〜16px | 1.5〜1.7 | 小さく薄くすることだけで差を付けない |
| 主な計測値 | 28〜48px | 1.1〜1.3 | 単位を近くに置く |

[KRDSのタイポグラフィ](https://www.krds.go.kr/html/site/style/style_03.html)（S14）は見出し・本文・役割別のトークンを区分しています。[ブラジル政府系のV4 Alpha](https://next-ds.estaleiro.serpro.gov.br/fundamentos/tipografia)（S16）もスケールと行間を説明していますが、試行版の数値を安定版の規則として採用しないようにします。

## 5. 行長とそろえ方

本資料の初期案では、日本語の読み物を1行25〜40字程度、欧文を45〜75文字程度から試します。普遍的な最適値ではありません。文字サイズ、内容、対象読者、段組みで調整します。

`ch` は「0」の幅を基準とする単位で、日本語一字の幅とは違います。`65ch` と「65文字」は一致しません。日本語には `ic` が使える環境もありますが、実表示で確認します。

| 内容 | そろえ方の出発点 |
| --- | --- |
| 長い本文 | 左そろえ |
| 短い宣言・ヒーロー | 左または中央。改行を確認 |
| 数値の比較 | 右そろえ、桁と単位をそろえる |
| ラベルと説明 | 共通の開始位置を持たせる |
| 注釈・出典 | 対象の図や数値の近くへ置く |

均等割り付けを使うときは、単語や文字の間が不自然に開かないかを見ます。細い欄での両端そろえは特に確認が必要です。

## 6. CSSで文字を組む例

```css
body {
  font-family: system-ui, "Noto Sans JP", "Yu Gothic",
    "Hiragino Kaku Gothic ProN", sans-serif;
  font-size: 1rem;
  line-height: 1.8;
}

.prose {
  max-inline-size: 40rem;
  margin-inline: auto;
  padding-inline: 1rem;
  overflow-wrap: anywhere;
}

h1 {
  font-size: clamp(2rem, 1.4rem + 3vw, 4rem);
  line-height: 1.25;
}

h2 {
  margin-block: 2.5em 0.75em;
  line-height: 1.4;
}

p { margin-block: 0 1.2em; }

.metric {
  font-variant-numeric: tabular-nums lining-nums;
  text-align: end;
}

.metric-unit {
  font-size: 0.6em;
  margin-inline-start: 0.25em;
}
```

この例はローカルに存在するフォントへのフォールバック例です。名前を書いただけでNoto Sans JPがダウンロードされるわけではありません。Interを第一候補として使うなら、別途読み込みを設定するか、数値部分だけに適用します。

`tabular-nums` は対応フォントで数字の幅をそろえる指定です。小数点、桁数、単位の統一まで自動で行うわけではありません。[Ant Designの字体ガイド](https://ant.design/docs/spec/font-cn)（S12）にも数値比較の文脈で登場します。

## 7. 改行と日本語組版

- 見出しを見た目だけの理由で一文字ずつ改行しない。
- PC用の手動改行がスマートフォンで不自然にならないか見る。
- 日本語の自然な改行を壊すような `word-break: break-all` の一律適用を避ける。
- 長いURLや識別子は、通常の文章とは別に折り返しを扱う。
- 日本語本文を画像化して文字配置を固定しない。
- 装飾的な字間は短いラベルで試し、長文に広く適用しない。
- 英大文字ラベルの字間と、日本語本文の字間は別に設計する。

禁則処理など、ブラウザの日本語組版を生かしつつ、採用書体で句読点や括弧の位置も確認します。

## 8. フォントの読み込みと権利

[font-display](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@font-face/font-display)（S19）は、フォントが使えるまでの表示を制御します。`swap` は素早く代替書体を表示できますが、書体の切り替えで行数や配置が動く可能性があります。

制作時には次を確認します。

1. フォールバックの状態でも情報が読めること。
2. 必要なウェイトと言語範囲だけを読み込むこと。
3. 使わないフォントを大量にpreloadしないこと。
4. ライセンスのWeb埋め込み・再配布・改変条件を確認すること。
5. 配布物に必要なライセンス文を残すこと。

オープンソースの書体にも条件があります。Typewolfなどで見つけた書体名は、配布元へ戻って確かめます。

## 9. 文字間隔変更への耐性

[WCAG 1.4.12](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html)（S04）は、利用者が行高1.5倍、段落後2倍、字間0.12em、単語間0.16emへ変更しても内容・機能が失われないことを求めます。これは全サイトの既定値をその数値へ設定する要求ではありません。言語・文字体系による適用上の例外もあります。

固定の高さに長文を押し込む、重要なラベルを隠す、カード内の文字を切り捨てる、といった設計は変更時に破綻しやすくなります。行数が増えることを受け入れる構造から作ってください。
