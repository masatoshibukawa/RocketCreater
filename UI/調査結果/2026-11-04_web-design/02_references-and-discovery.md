# 02. 参考サイトの選び方と探し方

## 1. 何の参考が必要かを先に決める

「かっこいいサイト」で検索するだけでは、似た流行を集めやすくなります。欲しい判断を先に言葉にします。

| 目的 | 探す参考 | 見る場所 |
| --- | --- | --- |
| サービスを短く説明する | 製品紹介・ランディングページ | 最初の一画面、説明順序、行動への導線 |
| 長い文章を読ませる | 記事・資料・編集系サイト | 行長、見出し、本文、図版と注釈 |
| 実用アプリを作る | 実際の製品・デザインシステム | 入力、一覧、詳細、失敗、空、実行中 |
| ブランドの個性を作る | 制作会社・文化施設・作品集 | 書体、素材、写真、編集上の視点 |
| SFのシステムらしさを作る | 制作者の映画UI事例・実際の科学アプリ | データの意味、状態、操作、画面の世界観 |

トップページの見せ方と、ログイン後の業務画面の使い方は別々に観察します。

## 2. 最初に訪れる実在サイト

公開ページの本文・構成を確認した候補です。以下の「観察・応用」は本資料の提案であり、全画面の表示検証や性能評価を終えたランキングではありません。

| サイト | 参考にする点 | 自分の制作で試すこと | 適用時の注意 |
| --- | --- | --- | --- |
| [Linear](https://linear.app/)（S31） | 製品の説明と具体的な作業例の接続 | 抽象的な宣伝文の近くに実際の操作例を置く | 宣伝用の構図を、そのまま高密度の実用画面にしない |
| [Stripe](https://stripe.com/au)（S32） | 複数製品を用途別に説明する構成 | 機能名の列挙を利用者の目的へ置き換える | 地域・時期で表示が変わる。色や構図の模倣だけで終えない |
| [Are.na](https://www.are.na/)（S33） | 保存・整理・検索・接続という説明の分解 | 自分のサービスを動詞の連なりで説明する | 写真や資料の収集では出典も一緒に残す |
| [NASA Eyes](https://science.nasa.gov/eyes/)（S34） | 科学データと探索体験への入口 | 見たい対象、時刻、操作の意味を主図の近くに置く | 各3Dアプリの操作・アクセシビリティは別途確認 |
| [GOV.UK](https://www.gov.uk/)（S44） | 検索と目的別分類による入口 | 多数の機能を利用者の用事から分類する | 公式書体・ブランドの利用条件を一般サイトへ転用しない |
| [IDEO](https://www.ideo.com/)（S45） | 主張と具体的な仕事の事例 | 実例で「何が変わったか」を説明する | 画像の大きさだけをまねず、事例の構造を読む |
| [無印良品ネットストア](https://www.muji.com/jp/ja/store)（S46） | 日本語のカテゴリと商品の整理 | 名称、写真、価格、選択肢の関係を観察する | ECには在庫・購入条件など固有の要件がある |
| [Pentagram](https://www.pentagram.com/)（S47） | 分野・媒体を横断する制作事例 | Web以外の編集・サイン・書体も参考にする | 掲載作品ごとの作者・権利を区別する |

映画UIの具体例は、続くSFデザインの章で扱います。制作者の説明が読める [Territory Studio](https://territorystudio.com/project/blade-runner-2049/)（S35）と [GMUNK](https://gmunk.com/OBLIVION-GFX)（S36）を優先してください。

## 4. 8言語で探すときの検索語

以下は**次の探索に使う提案語**です。実施済みの代表検索は [調査方法](00_research-method.md) に記録しています。

| 英語 | editorial web design / typographic hierarchy / art direction | FUI / fictional user interface / screen graphics / telemetry UI |
| フランス語 | mise en page web / hiérarchie visuelle / typographie | interface futuriste / interface de science-fiction |
| ドイツ語 | Webdesign Raster / Typografie / Weißraum / Barrierefreiheit | futuristische Benutzeroberfläche / Science-Fiction Interface |
| スペイン語 | diseño web / jerarquía visual / retícula / tipografía | interfaz futurista / interfaz de ciencia ficción |
| 中国語 | 网页设计 / 版式设计 / 字体 / 信息层级 / 留白 | 科幻界面 / 未来感界面 / 数据可视化 |
| 韓国語 | 웹디자인 / 타이포그래피 / 여백 / 시각적 위계 | SF 인터페이스 / 미래형 UI / 데이터 시각화 |

「cyberpunk」だけでは都市やイラストが多くなります。「screen graphics」「interface case study」「telemetry」を加えると、画面そのものや制作過程に近づけます。逆に基礎では、見た目の流行語より「hierarchy」「grid」「readability」を使います。

## 5. 参考は分解して記録する

一つのサイトを丸ごと採用せず、例えば構造はA、文字の密度はB、素材の質感はCというように役割を分けます。その後、色や余白の共通ルールを自分で設計し、寄せ集めに見えないようにします。

記録テンプレート:

```text
URL / 制作者 / 確認日:
サイトの目的と対象:
参考にする画面・状態:
観察できた事実:
よいと感じた理由（自分の解釈）:
自分の内容への変換:
採用しない点と理由:
権利・出典:
小さい画面とキーボードで追加確認する点:
```

「余白がきれい」から、「本文の幅を制限し、主図との間隔を大きくして、読む場所と見る場所を分けている」まで具体化すると、実装に使える知識になります。

## 6. 収集を終えて作り始める目安

本資料の提案では、方向の異なる候補をまず集め、そこから**主参考3件と補助参考3件程度**へ絞ります。件数自体に科学的な最適値はありません。

採用理由を三つ説明でき、最初の一画面と主要な操作状態を描けるようになったら試作へ進みます。参考を増やしても判断が変わらなくなったら、検索より実際の文章で組む方が有益です。
