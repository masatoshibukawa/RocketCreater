# Webサイトを公開する判断と確認

デプロイ先の選択、無料枠の比較、プレビューと本番の切替を扱う場合に読む。

1. 配信するファイルと、実行するSSR/API/worker、保存先を分ける。Next.js等の動的機能を使うなら、静的出力の可否を対象版で確認する。
2. 公開目的、商用か、想定トラフィック、許容できる停止、共同開発・private repoの条件を調べる。無料プラン、期限付き試用、課金契約の無料枠を区別し、現在の公式条件と対象アカウントのプランを照合する。
3. 帯域・要求数・build・実行・保存を、周期と集計範囲つきで見積もる。ドメイン更新、DB、外部API、AI推論を加える。上限で止まるか、自動課金されるか、通知と実際の上限を確認する。
4. 配信元、対象commit、プロジェクトのルート、ビルドコマンド、出力先、環境別の接続先とsecretを整理する。プレビューのアクセス制御を確認する。Git連携ではpushの前に本番自動公開の有無を確かめる。
5. 公開が依頼されていれば、実URLを利用者の権限で開き、HTTPS・深いURL・主操作・APIとファイルの取得を確認する。稼働版と復旧方法を記録する。調査依頼では必要な手順と適合条件を渡す。

公開先の提供URLと独自ドメインの接続枠、登録・更新費用を分ける。最終提出なら提出先に渡すURL・ファイル・リポジトリの実物を対象に、作業名、リンク先、生成物のメタデータを点検し、必要な著作者表示・ライセンス・出典・AI利用申告を残す。
