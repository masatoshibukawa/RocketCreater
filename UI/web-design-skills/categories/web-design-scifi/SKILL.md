# 機能と世界観を結ぶSF表現

## 入力と設計

誰が、何を監視・比較・操作し、どんな環境や組織で使う道具なのかを決める。ユーザーが指定した作品や雰囲気は、制作者の説明と見た範囲を分けて観察する。

- 映画UIの物語上の役割と、Webの長時間の読解・実操作を区別する。
- 構造、文字、データ、状態を先に成立させ、質感・細い線・発光・動きを足す。
- 時系列、方位、構造、分布、比較などの問いに合う図を選ぶ。同じ円形ゲージを全てへ付けない。
- 数値には単位、条件、時刻や出典など必要な文脈を置く。架空データは表示例と明記する。
- 更新・選択・解析進行など本当のイベントへ動きを対応させ、本文や操作の上で装飾を主役にしない。

色をシアン、本文を極小の等幅、全要素を常時点滅へ固定しない。明るい研究室や抑制した未来表現も、用途に合えば選べる。

## 動きと確認

動きを減らした状態でも最終内容と操作を残す。CSSだけでなくCanvas・動画などの動きも確認する。長く動く情報や自動更新には、適用条件に応じた停止・制御を設ける。

WCAG 2.3.3はAAA、2.2.2と2.3.1はAであり、混同しない。自動更新情報へ一律に5秒の猶予を当てはめない。強い閃光を演出の出発点にしない。

## 成果物

世界観の短い説明、画面の主図と状態、選んだ表現の理由、試作または実装、動き軽減と操作の確認を渡す。映画の画面・ロゴを自分の制作素材として無断で転用しない。
