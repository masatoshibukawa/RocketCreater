# 学習と検証を次の修正へつなぐ

## 入力と進め方

学びたい点、現在の成果物、利用者の用事、制作段階、試せる環境を確認する。学習、既存画面のレビュー、利用者確認を区別し、依頼に必要な方法を選ぶ。

- 学習では、実際の内容で小さな一画面を完成させる。単色、一書体、同内容の異なる構図など、学習目的に合う制約を選ぶ。
- レビューでは、利用者が何を理解・実行するかを先に決め、画面と必要な状態を確認する。
- 内容、構造、文字、余白、色、操作、速度のどこに原因があるか分ける。
- 指摘は観察事実、影響する用事、修正案、確認方法で書く。重大な操作不能と好みの提案を同列にしない。
- 利用者確認では、サイトの目的を説明する、主操作を探す、案を比較する、根拠を探す、失敗から回復するなどの課題を使う。
- 確認できたことと、未確認・再現できないことを分けて残す。

色ペア検査、スクリーンショット観察、自動検査、実操作、利用者テストは異なる証拠である。一つの結果で全体適合や全利用者への効果を保証しない。

## 成果物と確認

学習なら練習・成果物・振り返りの観点、レビューなら優先度付きの指摘と根拠、利用者確認なら課題・観察・次の変更を渡す。所要日数や点数を成果の保証としない。

修正を依頼されていれば、レビューだけで止めず、許可された範囲で修正と再確認を進める。学習相談へ勝手なアプリ変更を追加しない。
