# 固有の内容と判断を取り戻す

## 入力と原因の分類

現状の画面、実際のサービス内容、利用者、参考、変更できる範囲を確認する。紫、Inter、角丸、bento gridなどをAI制作の証拠や一律の禁止対象にしない。

- 抽象的な文言、内容と合わない反復構造、汎用素材、文字や余白の不統一、未設計の状態を分けて指摘する。
- サービス固有の対象・動詞・実例へ文章を具体化する。実績・推薦文・数値を作って補わない。
- 文言の定型感には [コピーの基準](../web-design-copy/SKILL.md) を使う。強調括弧、求められていない詩的表現、未完成事項の見せ場化を、別の装飾表現へ置き換えない。
- 手順、比較、説明、作品など内容の違いを構造へ反映する。カード数を変えるだけで改善としない。
- 機体図、工程、現場、記録など、そのサービスに意味のある素材を選ぶ。
- AIへの指示には目的、対象、実際の内容、参考から取り入れる一点、条件、評価方法を渡す。
- 複数案を出すなら、色違いではなく主役や情報の順序を変える。採用理由を示して実装・編集へ進む。

定番の部品で分かりやすい操作を、独自性のためだけに不慣れな操作へ変えない。統一を保ちながら、目的を説明できる例外を残す。

## 成果物と確認

根拠のある指摘、変更前後の具体例、必要なら設計指示文や実装を渡す。AIっぽさのスコアや出所判定を作らない。

サービス名の置換だけで成立してしまわないか、構造が内容を反映しているか、失敗や制約も扱えるかを確認する。短編執筆などの実験結果を、そのままWeb外観の検出根拠へ一般化しない。

## 作業用テンプレート

生成への指示や編集内容を具体化するときは、[設計指示と編集記録](references/creative-brief.md) を使う。
