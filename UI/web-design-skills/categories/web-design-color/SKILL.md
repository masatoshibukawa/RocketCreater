# 色の役割と組み合わせを設計する

## 入力と設計

既存ブランド色、対象画面、テーマ、文字・操作・グラフの用途を確認する。

- background、surface、text、muted、accent、on-accent、focus、必要な境界、状態色を分ける。
- 彩度を増やす前に面の明るさと主従を整える。明暗テーマを単純反転で済ませない。
- 通常文字は4.5:1、大きな文字は3:1をAAの出発点として、適用条件・例外を原資料で確認する。大きな文字は18pt、または14ptの太字以上が基準になる。
- 操作・状態を識別するために必要な視覚情報と意味ある図の部分は、隣接色との3:1を確認する。全ての装飾線へ一律に要求しない。
- 色だけで合否や選択を示さず、文字・形・位置などを併用する。
- グラフでは分類、連続量、基準からの正負を区別する。系列色と警告色を混同させない。

OKLCHのLや色相の差だけで合格を推測しない。実際の前景と背景、透明度、画像、hoverやfocusなどの状態を検査する。判定は丸め前の値で行う。

## 成果物と確認

役割別トークン、適用箇所、検査した組み合わせと計算値・方法を渡す。未検査の状態も明示する。色ペアの合格をページ全体のWCAG適合と表現しない。

## 作業用テンプレート

新しい色トークンと検証結果を作るときは、[色の作業表と計算例](references/color-contract.md) を使う。

## 深掘り

パレットと根拠が必要な場合は、[配色の調査](../../../調査結果/2026-11-04_web-design/03_color.md) を参照する。[調査パレットの再計算](../../../調査結果/2026-11-04_web-design/examples/check_contrast.py) は同梱CSVの24組専用で、任意の新パレットを検査する道具ではない。
