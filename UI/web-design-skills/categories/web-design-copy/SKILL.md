# 具体的で直接的なWebコピー

## このスキル集の既定

強調のためのかぎ括弧、求められていない詩的なコピー、利用者に関係しない未完成事項の強調を加えない。これはユーザー指定に基づく既定の文体であり、全てのジャンルに対する規則ではない。引用や詩的表現を明示的に求められた場合は、その指定に合わせる。

## 入力を確かめる

対象の画面、読者、主操作、実際に使える機能、データの性質、文章の用途を確認する。サイト利用者向けの文章と、開発者向けの進捗・検証報告を区別する。機能や状態が不明ならコードや仕様を確認し、未実装と決めつけて注意文を追加しない。

## 編集する

1. 見出しで何のサービス・情報か、説明で何ができるか、ボタンで次に何が起きるかを具体化する。
2. 普通の語を強調・分類・言い換えのために引用符で囲まない。直接引用、実際のUIラベルの参照、固有の名称、入力文字列など、意味のある表記は保つ。一括置換で括弧やコードを削らない。
3. 比喩、壮大な約束、抽象語の連続、対比の決め台詞を、実際の対象と動作へ書き換える。短い語への言い換えだけで内容の曖昧さを残さない。
4. 見出しを繰り返す説明、意味のない導入・結び、実在の条件を示さない留保は削る。必要な条件は対象・範囲・次の操作として書く。
5. 利用者の判断に関係しない技術選定、接続待ち、将来機能、未確認の試験を、ヒーローや特徴カードへ載せない。開発者向けの報告へ置く。
6. 料金、保存・送信、権限、操作の成立などに影響する事実は、関連する操作や結果の近くに、読める短い文で示す。文章の場所や長さを直し、必要な情報を隠さない。
7. 実装していない機能や架空の実績を、できることとして書かない。現在の利用可能な範囲に合う見出し・操作・状態へ組み直す。

人間らしさを出すために、不自然な口語、誤字、無根拠な自信を加えない。肯定的な文体と、機能・数値の根拠を両立させる。

## 成果物と確認

依頼に応じて、書き換えたコピー、変更理由、必要なら画面への実装を渡す。提案だけの依頼へ勝手な画面変更を追加しない。

- 普通の語を意味なくかぎ括弧で囲んでいないか。
- 最初の見出しと説明で対象・動作・結果が分かるか。
- ボタンの文言と、実際に次に起きることが一致するか。
- 開発の事情が利用者向けの主情報へ混ざっていないか。
- 操作に必要な条件を、見つけられる場所に残しているか。
- 書き換えで機能・状態・数値について新しい事実を作っていないか。

## 作業用の例と記録

文言の書き換えや条件の配置では、[コピーの編集例](references/copy-editing.md) を必要な部分だけ読む。

研究の根拠は [AIコピー調査](../../../調査結果/2026-11-04_ai-web-copy/README.md) にある。引用符や特定の語を、AI制作の証拠としない。
