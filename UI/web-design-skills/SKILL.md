依頼を、必要な判断と成果物へ分解する。下のカテゴリから該当する `SKILL.md` を読み、必要な参照資料だけを追加で読む。全カテゴリを毎回読み込まない。

## 依頼に合う進め方

- 新規サイト: 基礎で目的と内容を決め、必要なら参考探索。配色・文字組み・コピーを実装へつなぎ、実践と検証で確認する。
- 既存画面の改善: 症状を担当するカテゴリから始め、必要な範囲だけ実装・検証を足す。
- SF表現: SFスキルから始め、必要に応じて配色・文字組み・実装を組み合わせる。画面の世界観を、求められていない詩的コピーの指定にしない。
- 定型感の改善: AIと独自性で原因を分け、構造なら基礎、文言ならコピー、配置なら文字配置など、原因のあるカテゴリで直す。
- 調査や助言だけの依頼は、その範囲で成果を返す。実装依頼は調査だけで止めず、許可された作業を具体化する。

カテゴリを選ぶ行為は別エージェントの起動ではない。スキルを順に参照し、担当する成果物を一つの依頼としてまとめる。

## 共通の判断基準

利用者、主操作、実際の内容、既存のデザインシステム・技術・ユーザー指定を起点にする。不明点は利用可能な資料から確認し、重大な未定事項だけを質問する。

規格上の要件、組織固有の慣行、試作上の目安、自分の提案を区別する。参考の見た目を品質保証やAI制作の証拠にしない。調査時点の情報は更新されうるため、最新性が必要な仕様や推奨は原資料で再確認する。

通常の説明とサイトのコピーは、具体的・直接的に書く。強調用のかぎ括弧、求められていない詩的な比喩、利用者に関係しない未完成事項の強調を加えない。文章を生成・修正する場合は [コピーの基準](categories/web-design-copy/SKILL.md) を使う。

開発者向けの報告は、作成・変更したものと結果を先に述べ、判断に必要な確認結果・未完了事項を短く記録する。その情報をサイト本文へ自動で転記しない。計画だけを完成実装として扱わない。

## このパッケージの位置づけ

このディレクトリの入口を読む場合は、この `SKILL.md` を指定する。カテゴリは下の独立したスキルで、索引への登録がなくてもファイルを直接読んで使える。自動検出・インストールの設定とは別の、リポジトリ内のスキル原本である。

依頼例:

```text
UI/web-design-skills/SKILL.mdを使って、このサイトの改善を進めてください。
UI/web-design-skills/categories/web-design-color/SKILL.mdを使って、配色を見直してください。
```

形式と段階的な読み込みは [OpenAI公式スキル資料](https://learn.chatgpt.com/docs/build-skills) を参照。元の調査は [Webデザイン調査ノート](../調査結果/2026-11-04_web-design/README.md)。通常の作業に調査全件の再読は不要。
