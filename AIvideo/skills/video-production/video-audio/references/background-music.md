# 動画BGMの設計と制作

BGMの選定・作曲・生成・差し替えで使う。目的、公開先、カット表、ナレーション、使える実音を確認し、依頼に応じてキュー表、試聴用の案、個別トラック、最終ミックスを作る。

## 場面で音楽が担う役割を決める

- **解釈**。同じ映像でも、音楽によって視聴者の受け取る感情や状況が変わる。和音の解決、盛り上がり、音の着地が、画面の示す結果と合っているか確認する。技術デモでは未達の結果に勝利を思わせる音を重ねると、説明と印象がずれる。 [映像に対する解釈の実験](https://www.frontiersin.org/journals/psychology/articles/10.3389/fpsyg.2020.02242/full)
- **聞き取り**。声と音楽が同時に鳴るときは、声と重なる帯域、音の立ち上がり、音数、人声に注意する。歌詞付きの曲は同じ曲の歌詞なし版より発話を聞き取りにくくした実験がある。解説では歌なしから試し、打音や耳を引く旋律も声の隙間へ移す。 [歌詞と発話の聞き取りの実験](https://pubmed.ncbi.nlm.nih.gov/34323547/)
- **時間**。テンポとパルスで進行感、音色・音域・楽器数で密度、和音で緊張と解放を調整する。全カットを拍に合わせる必要はない。視聴者に見てほしい変化へ着地を置き、数値を読む間や実音が証拠になる区間では、音を減らすか休ませる。

| 動画・場面 | 最初に試す音と使い方 |
| --- | --- |
| 技術デモ・解説 | 柔らかい持続音と弱いパルス。重要な文や結果表示では音数を減らす。 |
| 広告・短い製品紹介 | 短いモチーフと明瞭な着地。製品の登場やロゴに合わせ、声のない箇所で曲を前に出す。 |
| ドキュメンタリー・実機映像 | 控えめな持続音やBGMなし。動作や場所を伝える現場音のために余白をつくる。 |
| SF・物語 | 同じ短いモチーフを音色や音域を変えて再提示し、場面間のつながりを作る。 |
| 操作チュートリアル・ライブデモ | 冒頭・締めだけ短い曲を試す。本編は声と操作音を優先する。 |

## キュー表から短尺を作る

1. 仮ナレーション入りの映像を見て、開始・終了、画面の変化、優先する音、BGMの役割、入り・抜き・着地を表にする。台詞が動く場合は、修正しやすい区間や楽器別の素材を作る。
2. 代表的な短い区間で比較する。既存曲なら音数、歌、編集しやすい小節や余韻で絞る。手で作るならパッド、低音、パルスを分ける。例えば4拍子・96 BPMでは8小節が20秒になる。D–A–Eの持続音を置き、後半だけ弱いパルスを足せば、同じモチーフの薄い版と動く版を作れる。調やテンポは場面に応じて変える。
3. 音楽モデルには用途、尺、編成、展開、終わり方、除外する音を渡す。同じ尺と同じ映像で複数テイクを比較する。部分生成や延長を使うときは、同じモチーフ・音色が続くか、継ぎ目でリズムや和音がずれないかを試聴する。映像に同期する着地はタイムラインで確定する。
4. 曲と声を重ねて選んだら、必要な場合は小節境界で切り、余韻の重なりを調整する。パッド、低音、パルスを別々に書き出せる場合は分けて残す。ステレオ音源を後から分離した素材は、音漏れや残響の欠落を試聴する。

生成指示の例。20秒のインストで、日本語の技術ナレーションの下に敷く。柔らかいアナログパッドと弱いパルス。前半はパッドだけ、後半でパルスを足し、最後に短い余韻。歌、人声、強いドラム、急な盛り上がりは除く。

## ミックスと比較

- 声、現場音、効果音、音楽を別トラックにする。まず声の音量をそろえ、重要な文の手前で音楽を滑らかに下げて文の後で戻す。固定映像ではキーフレーム、長尺では声を検出入力にしたサイドチェイン圧縮が使える。息継ぎのたびに上下する場合は保持時間や戻りを調整する。音量調整後も声と競う箇所は、パートを外すか、重なる帯域を実際に聴いてからEQで調整する。 [Fairlightの音声編集](https://www.blackmagicdesign.com/products/davinciresolve/fairlight)、[FFmpegフィルター](https://ffmpeg.org/ffmpeg-filters.html)
- TVドキュメンタリーを対象にした小規模な試聴研究では、発話を音楽より少なくとも10 LU高くする目安が提案された。これは比較する区間の声と音楽のラウドネス差であり、フェーダーの減衰量とは異なる。最終ミックスの統合ラウドネスとトゥルーピークは納品先の仕様で判断する。 [ダッキングの試聴研究](https://aes.org/publications/elibrary/elibrary-page/?id=20711)、[EBU R128](https://tech.ebu.ch/publications/r128)
- 同じ映像と同じ声レベルで、BGMなし・既存曲・新案を比較する。スマホのスピーカーとイヤホンで、字幕なしでも数字・専門語・否定が聞き取れるか、実音を覆っていないか、終端やループが自然か確認する。実施した試聴や測定と、資料だけで比較した点を分けて記録する。

## ツールの選択

| 手段 | 選ぶ条件・役割 |
| --- | --- |
| 音源ライブラリ | 既存曲でよいときは、編集に必要な尺・版と、映像への組み込み・公開先・クレジット条件で絞る。 [YouTube Audio Library](https://support.google.com/youtube/answer/3376882) |
| MIDI・DAW・映像編集 | 音の着地やパートを後から細かく変えるなら、REAPER等で作曲し、DaVinci ResolveのFairlight等で映像に同期・ミックスする。反復処理や測定はPythonとFFmpegを使える。 [REAPER](https://www.reaper.fm/)、[Fairlight](https://www.blackmagicdesign.com/products/davinciresolve/fairlight)、[FFmpeg](https://ffmpeg.org/ffmpeg-filters.html) |
| クラウド音楽モデル | Lyria 3.5はテキストや画像を使った曲案の生成に向き、Lyria 3 Clipで短尺を比較できる。Eleven Music APIは曲の区間ごとの長さやスタイルをJSONで指定できる。 [Lyria API](https://ai.google.dev/gemini-api/docs/music-generation?hl=en)、[Eleven Musicの構成指定](https://elevenlabs.io/docs/eleven-api/guides/how-to/music/composition-plans) |
| MCP | チャットから生成サービスを呼ぶなら、クライアントで音楽生成ツールが見えるか確認する。ElevenLabsの公式リモートMCPはOAuthで接続し、ワークスペースのクレジットを消費する。生成モデル、MCP接続、編集工程を分け、未接続ならWeb UIやAPIを候補にする。 [ElevenLabs公式MCP](https://elevenlabs.io/docs/eleven-api/resources/mcp-server) |
| ローカル音楽モデル | ACE-Step 1.5は曲案の生成や区間の再生成、Stable Audio 3は音楽や音の素材生成の候補。採用する版の対応モード、重みの条件、OS・GPU・空きVRAMを確認し、代表区間で計測する。 [ACE-Step](https://github.com/ace-step/ACE-Step-1.5)、[ComfyUI公式ワークフロー](https://comfy.org/workflows/audio_ace_step_1_5_split/)、[Stable Audio 3モデルカード](https://huggingface.co/stabilityai/stable-audio-3-small-music) |
| ローカルLLM | Ollama＋Gemma等に、台本・字幕・カット表から `start_ms`、`end_ms`、`role`、`instrumentation`、`foreground` を含むキュー表を作らせる。スキーマに加え、順序、範囲、尺、無音区間をコードで検証する。音はMIDIレンダリング、音楽モデル、既存曲のいずれかで用意する。GPUを共用する場合は計画と音楽生成を順に実行する。 [既存のローカルLLM構成](../../../../local-director/README.md)、[Ollamaの構造化出力](https://docs.ollama.com/capabilities/structured-outputs) |
