# 原理に基づくTTSの選定と原因の切り分け

声が不自然、専門語を誤読する、長尺で声が変わる、多言語化や自動編集が必要、といったときに読む。原理の詳細は [深掘り調査](../../../../research/2026-11-07/narration-deep-dive/README.md) に置き、この手順は制作時の判断に使う。

## 方式から過剰に推測しない

- 文字の正規化、発音、韻律、音響表現、波形生成は機能として分ける。end-to-endのモデルでも、入力の読みが自動で正しくなる保証はない。
- FastSpeech系のduration制御、VITS系の確率的なリズム、flow matchingの計算ステップ、音声言語モデルの参照・指示は、それぞれ使う実装に露出した機能を確認する。
- VITSのnormalizing flowとflow matchingは同一手法ではない。LLMとflow matchingは併用される場合がある。
- 文字トークン、音声codecのフレーム・codebook、PCMのサンプルレートを分けて記録する。モデル名のHzを出力音声のサンプルレートとしない。
- 推論中の反復、原稿・設定・テイクの改善ループ、重みの追加学習を区別する。再生成しただけで学習したとは報告しない。

## 症状から変える箇所を選ぶ

| 症状 | 先に調べるもの | 改善する候補 |
| --- | --- | --- |
| 人名・英略語・単位の誤読 | 発音用文字列、辞書、言語設定 | 読みを指定し、字幕の表記は維持 |
| 音は明瞭だが棒読み | 文の構造、句の区切り、強調と間 | 意味の単位で再構成し、対応する演技設定を比較 |
| 発音が正しくても違和感 | アクセント、助詞、語尾、句の接続 | 該当言語の確認者による試聴。ASRだけに頼らない |
| 文ごとに別人に聞こえる | モデル版、話者、参照、設定、後処理 | 固定条件をそろえ、前後を含めて再生成・試聴 |
| 参照音声の響きや雑音が移る | 参照録音と生成の素音声 | 条件の良い許諾済み参照へ替えて比較 |
| 脱落・反復・語尾の欠け | 入力、生成上限、長さの推定、実尺 | 不良箇所を含む意味単位で再生成。欠けた語を編集で隠さない |
| 尺が超過する | 情報量、間、生成側の速度指定 | 原稿→間→話速→小さな時間伸縮の順を候補にする |
| 別エンジンに替えると抑揚が壊れる | パラメータの意味と対応範囲 | 同名の項目も公式仕様を読み、既定値から比較 |
| 言語を変えると声・発音が崩れる | 言語対応、話者の適性、前処理 | 対象言語の原稿・読み・話者で比較し直す |
| BGMを入れると説明が聞こえない | 素音声とミックス、残響、音量 | BGMの帯域・音量・ダッキングを比較し、声自体の問題と分ける |

表は診断候補で、症状だけから特定モデルのバグと断定しない。修正する変数を絞り、改善した文の前後も聞く。

## 多言語・長尺の確認

資料を調べる言語、モデルが合成できる言語、評価する言語を区別する。同じベンダーの翻訳文書を独立した評価に数えない。他言語用の音素タグやSSMLが、日本語や別モデルでも使えると推測しない。

声の固定は話者IDだけで判断せず、版・参照・設定・後処理も保存する。短い比較で候補を選んでから、章の冒頭・中盤・末尾を続けて聞く。文を分ける場合は、同じ声か、自然な間か、接続で語が切れていないかを確認する。

## 比較結果を意味のある形で残す

- 正確さ、自然さ、声の維持、演技、実尺、速度、資源、利用条件を別項目で記録する。
- CER/WERは補助。生のASR出力と正規化規則を残し、数値・単位・否定・予定の誤りを正規化で消さない。日本語WERは分かち書きも記録する。
- A/Bの好み比較と、声の同一性を調べるABX等を混同しない。MOSは異なる原稿・確認者・条件の値をそのまま順位へ並べない。
- RTFは合成時間÷出力秒数、TTFAは最初の再生可能な音までの時間。モデル読込とウォーム推論、精度、端末、同時実行を分ける。
- 字幕のforced alignmentは時刻合わせであり、原稿を正しく読めた証明ではない。採用・編集後の音声へ合わせる。
- 未測定はnull等で明示し、0や推定値を実測値として埋めない。
