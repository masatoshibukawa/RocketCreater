# 動画制作の索引

ユーザーが求める成果物から必要な工程を選び、下位の `SKILL.md` を読んで作業する。このファイルは制作全体の入口であり、すべての下位スキルを一括で読み込むためのものではない。

## カテゴリを選ぶ

| カテゴリ | 読み込むスキル | 主な成果物 |
| --- | --- | --- |
| AI映像生成と写実表現 | [video-generate](video-generate/SKILL.md) | 動画ショット、入力画像、プロンプト、生成条件 |
| SF映画とVFX | [video-sf-vfx](video-sf-vfx/SKILL.md) | ショット分解、3D・実写・AIの素材、合成映像 |
| 音声と音楽制作 | [video-audio](video-audio/SKILL.md) | 声、効果音、環境音、音楽、同期した音声 |
| ローカル生成環境 | [video-local-runtime](video-local-runtime/SKILL.md) | 実機に合う実行経路、分離環境、動作確認記録 |
| LLMによる制作支援 | [video-llm-direction](video-llm-direction/SKILL.md) | 台本、ショット表、動作プロンプト、改善案 |
| 制作工程と品質管理 | [video-production-management](video-production-management/SKILL.md) | 素材構成、テイク管理、編集、完成物の検証 |
| 出典と利用条件 | [video-research-rights](video-research-rights/SKILL.md) | 一次資料、条件付き比較、素材とモデルの利用条件 |

「動画を作って」のような複数工程の依頼は、全体を整理してから必要なスキルを組み合わせる。「Wanで画像を動かして」は映像生成、「ComfyUIを導入して」はローカル環境、「日本語ナレーションだけ」は音声へ直接進む。[AIナレーションの制作手順](video-audio/references/japanese-narration.md) には無料・ローカル候補の選び方、発音、短尺比較、動画との同期をまとめている。商用条件の比較だけなら映像生成を始めない。

## 依頼を制作条件へ置き換える

既に示された目的、尺、縦横比、納品先、素材、使用ツール、ローカルかクラウドかという希望を引き継ぐ。足りない情報が結果や費用を大きく変える場合だけ確認し、決められる構図やカット案の作業は進める。作例の30秒・6カットを他の依頼の固定条件にしない。

依頼が調査、台本、プロンプト、環境構築、実際の生成、編集のどこまでを含むかを見定める。生成や編集まで依頼され、必要なツールと権限がある場合は成果物まで作る。計画だけを生成済みの動画として渡さない。

## 工程をつなぐ

1. 人物、衣装、舞台、光源、進行方向など、ショットをまたいで守る要素を決める。
2. 各ショットでAI生成、実写、3D、合成のどれが修正しやすいかを選ぶ。
3. 必要なカテゴリだけを読み、入力素材と設定を確定して生成・編集する。
4. テイクを確認し、採用する範囲と音を編集でつなぐ。生成尺と最終採用尺を分けて記録する。
5. 出力ファイルを再生し、映像の連続性、音の同期、冒頭と末尾、書き出し条件を確認する。

工程間では、ショットID、参照素材、動作、カメラ、音、継続して守る条件、採用テイクを引き継ぐ。[ショット表](../../research/2026-11-04/templates/shot_plan.example.json) と [生成記録](../../research/2026-11-04/templates/generation_record.example.json) は必要な場合にコピーして使う。これらは設計・記録用JSONで、ComfyUIへ投入する実行ワークフローではない。

## 調査資料の位置づけ

[調査の入口](../../research/2026-11-04/README.md) は2026年11月4日の資料である。モデル、API、ライセンス、Windows対応、必要メモリの条件は、実際に採用する版の一次資料で確認する。保存済みPC仕様を現在の空きVRAMや導入状況として扱わない。

ローカルの既存LLMや動画環境を特定できていなかったこと、生成ベンチマークを実施していなかったことを引き継ぐ。対応ツールを確認できない場合は、進められた素材・設定と、未完了の工程を明示する。

## このパッケージの使い方

このリポジトリでは、このファイルをパスで指定して読み込み、表から下位ファイルへ進める。カテゴリが明確なら下位ファイルを直接指定してよい。作成しただけで環境のスキル一覧へ登録されたとは報告しない。登録や配布を依頼された場合は、その環境の探索規則を確認し、調査資料への相対参照も維持する。
