# WindowsでのComfyUI＋Wan2.2実行

[local-runtime](../../../../local-runtime/README.md)に、2026年11月4日にこのPCで導入・生成まで検証したコードと記録がある。既存環境を更新する前に、そこにあるリビジョンと現在の環境を比較する。

## モデルと実行系

検証した組はComfyUI 0.44.0、Python 3.11.6、PyTorch 2.14.1+cu130、Wan2.2 TI2V-5B FP16、UMT5 FP8、Wan2.2 VAE。ComfyOrgの再パッケージに含まれる対応する3点を使い、HFのLFSサイズとSHA-256を照合した。モデル、仮想環境、キャッシュ、ログ、出力はGitへ含めない。

`start.py`は専用venvのPythonでComfyUIを起動する。`generate.py`と`verify.py`も専用venvのPythonで実行する。システムPythonにPillow等がない場合に、全体環境へ追加する必要はない。

## 起動とAPI

`--listen 127.0.0.1`でこのPCからだけ接続できるようにし、`--offline`、`--disable-all-custom-nodes`で外部生成サービスと追加ノードを使わない構成にした。これはOSレベルの通信遮断を保証する設定ではない。必要な重みは先に取得する。

ネットワーク制限のある実行環境ではlocalhostも拒否されうる。WinError 10013が出る場合は、別のAPIへ迂回せず、その実行環境の承認経路でローカル接続を許可する。GPU名の表示だけで起動成功とせず、待ち受け開始と`/system_stats`の応答を確認する。

APIグラフとUI形式のグラフを区別する。`workflow-api.json`は`class_type`と`inputs`を持つAPI用であり、ショット表や画面配置JSONではない。実行前に`/object_info`で必要なノードを確認し、`/prompt`の応答と`/history/<id>`の成功状態を別々に確認する。

## 試作と評価

後続の比較では、Wan2.2 I2V 14Bの高ノイズ・低ノイズFP8とWan2.1 VAEの組も、同じ4090で短い動画生成まで実行できた。5BのVAEを14Bへ流用しない。14Bの公式ComfyUI構成は幅・高さの16の倍数を受け付け、5Bの32の倍数という例を全モデル共通の制約へしない。

今回、VRAMが逼迫したDynamicVRAMの比較は約491秒かかった。標準オフロード（`start.py --conservative`）での別テイクは約56秒だった。メモリ管理の切り替えはこの実機の対処例であり、速度差の原因を設定だけへ断定しない。他のGPUプロセスは停止しない。専用サーバーを再起動する際は、PID・起動引数・キューが今回のものか確認し、完了直後のジョブを中断扱いへ書き換えない。

公式5Bテンプレートに基づき、`Wan22ImageToVideoLatent`へ画像を接続した。画像入力を有効にしない場合はテキストだけからの生成になる。幅と高さは32の倍数、フレーム数は4n+1の条件を確認する。今回の小さい試験は832×480、49フレーム、24fps、20 stepsで、RTX 4090でサーバー実行26.52秒だった。この値を720pや長尺の推定実測値として使わない。

今回の入力はBlender由来なので、写実的というプロンプトを加えただけで実写調へ変わるとは扱わない。微小な動きや材質の変化と、機械の形状変化を区別して比較する。正確な文字とHUDは後工程で合成する。

出力はMP4を全フレームデコードし、寸法、fps、枚数、非黒画像と変化を確認する。時刻付きコンタクトシートと重要フレームで目視確認し、リアルタイム再生の確認を行っていない場合は記録する。今回の5B出力は無音で、音声生成の成功とは扱わない。

ローカル経路にサービスの透かしを加える処理はないが、モデルが不要な文字を描く可能性は出力で確認する。サービス由来の透かしを削除する工程に置き換えない。出力メタデータに作業用のパスを埋め込まず、AI生成であることや必要な出典・ライセンスは保持する。
