## 中心に置くこと

**ロケット設計で専門分野を行き来する判断を、Claude APIと検証ハーネスでつなぐ。モデル上で解析・再設計を反復し、製作に渡せるデータへ接続する。**

大きな背景は宇宙輸送の設計開発、今回の具体的な実演はPETロケット。両者の規模と実証範囲を区別する。冒頭ではアプリで追える設計・解析・出力を先に見せる。

2026-11-07の本人説明に合わせ、製品の目標構成は**現在ローカルLLMが担う全判断箇所をClaude APIへ移行**、開発の主力は**Claude Code**とする。API移行は今後の実装・収録条件。現在のGemma記録は移行前の仕組みの検証資料として保持する。この計画作成で移行やAPI実行を完了したとは扱わない。

## 技術の見せ方

| 担当 | 本編で伝える役割 | 裏付けるもの |
| --- | --- | --- |
| アプリAPI | 要求・保存状態・実行指示・進捗を画面と接続 | 実際の操作とイベント |
| Claude API（目標構成） | 許可された選択肢と結果を読み、次の解析・設計変更を選び、理由を返す | 移行後のモデル名・入力・ツール結果・選択の記録 |
| ハーネス | 依存関係、適用範囲、精度、計算予算、判定の失効・再確認を管理 | 候補の除外理由と現在版の判定 |
| スクリプト・ソルバー | CAD、空力、飛行、構造等の数値計算 | 実行条件・入出力と対応する画面 |
| フィードバック処理 | 確認できた履歴から予測差や費用を整理し、次の判断に戻す | 予測と観測、次の判断入力の対応 |
| Claude Code | 開発の主力。仕様から実装・デバッグ・テストへ進める | 本人が示せる開発の一件と差分・確認結果 |

階層性は「簡易な候補探索→詳細解析→独立した確認」。適応性は「今の不足に応じて対象・手法・精度を選ぶ」。反復は、**機体を変えるループ**と**数値設定を細かくするループ**を一つずつ見せる。全ソルバーの名前を列挙する時間にしない。

結果を次の判断へ戻す仕組みを示す。LLM自体の重み更新、一般的な探索効率の向上、実飛行精度の改善は、今回確認した事実へ置き換えない。別の予測器を学習した場合もClaude自体の学習と分ける。詳細は[主張と証拠](evidence-map.md)。
