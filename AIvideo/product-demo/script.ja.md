# 日本語ナレーション初稿

`plan.json`から生成。未収録の仮台本。実行の結果に合わせて言葉を確定し、録音後に字幕を同期する。

## S01 / 00:00–00:15 / 初めて設計する人の課題を、実アプリから示す

はじめてロケットを設計すると、形だけでは決められません。
質量や部品、飛行条件をつなぐ判断が必要です。
RocketWrightは、その検討を一つの流れにまとめます。

画面：3Dモデルと条件欄を同時に見せ、入力前の迷いを一文で置く。結果を先出しする場合も同じ収録案件だけを使う。

確認：チームの経歴や利用者の効果を未確認のまま語らない。

## S02 / 00:15–00:30 / 一人の利用者の要求を入力する

今回は、1.5リットルのペットボトルで、
卵を回収し、30メートルを目指します。予算は3,000円。
この要求を、そのままアプリに伝えます。

画面：設計の相談へscenarioの要求文を入力。seedと環境条件も記録する。入力が長い部分は準備済みと表示して短縮可。

確認：30mは要求値。達成値として表示しない。

## S03 / 00:30–00:47 / Claudeが要求と道具を結び付ける

Claudeが要求と制約を整理し、設計の候補を考えます。
必要な計算や部品の確認を、道具へつなぎます。
ここで見せるのは、実際の入力と実行記録です。

画面：実際のClaude実行の説明とツール呼出を表示。要求、部品の候補、計算の戻り値の対応を読める範囲で示す。

確認：Gemmaや模擬クライアントをClaudeとして見せない。

## S04 / 00:47–01:10 / 数値と部品の根拠を確かめる

数値は、専用の計算コードが出します。
部品の構成と飛行条件をそろえて、候補を確かめます。
計算結果だけでなく、部品の出典と仮定も辿れます。

画面：候補の3D、部品構成、条件、費用や飛行結果を対応させる。画面の数値はその実行から読み取り、台本へ事前の達成値を埋めない。

確認：シミュレーションの判定を、実機の安全認証と呼ばない。

## S05 / 01:10–01:38 / 検査の未達を受け、理由に沿って選び直す

この案は、入力した条件をまだ満たしていません。
Claudeが検査結果を読み、見直す箇所と理由を説明します。
変更した案を、同じ判定条件で再計算します。
結果を受けて検討を進めるところが、このデモの核です。

画面：同じ実行の未達条件、Claudeの外部に説明可能な理由、変更、再検査を示す。実際の未達→修正が得られない場合は収録案件を再選定する。

確認：別の成功実行をつながない。目標・閾値を黙って変えない。

## S06 / 01:38–01:59 / 解析結果を利用者が読み取る

解析では、飛行の推移と条件を確認できます。
表示する機体とグラフは、同じ設計案の計算結果です。
回収の映像や数値も、実機での成功とは分けて示します。

画面：解析→高度の推移／飛行と回収を表示。同じsource_idの時系列を再生する。流体解析は実行したsolverと精度・収束の状態を示せる場合だけ挿入。

確認：CG・記録再生・待ち時間の省略をその場で表示する。

## S07 / 01:59–02:19 / 同じ案の使える成果物を取り出す

確認した案から、図面や部品表、製作票を取り出します。
同じ設計の条件と根拠を、次の作業へ持ち帰れます。
作成できないものは、その理由も表示します。

画面：出力→製作票・印刷データ／設計図SVG。製作票PDF、部品表、側面図を実際に開く。組立手順・S5データ・CGは同じ保存版で取得できた場合だけ補足。

確認：任意のClaude案から組立工程まで自動生成できるとは言わない。

## S08 / 02:19–02:33 / 条件の変化に対する判断の変化を示す

条件が変わったときも、どこを見直すかが大切です。
変えた条件と、それを受けた判断を並べて確認します。

画面：比較用の要求は一つだけ変更。元の要求と新しい要求、モデル・環境・予算を記録する。追試を示せない場合は同じ時間枠で出典と仮定の確認へ差し替える。

確認：比較する実行は別実行と明記。学習効果や一般精度に拡張しない。

## S09 / 02:33–02:47 / Claudeとドメイン知識の役割を結ぶ

Claudeは条件を読み、検査結果から選び直します。
コードは数値を計算し、人は仮定と現物を確認します。
ロケット固有の条件を、この流れに組み込んでいます。

画面：実アプリの履歴と検査の根拠を背景に、モデルの判断・コードの計算・人が確認する範囲を指示する。チームの経験は確認した一件だけ短く挿入。

確認：モデル内部の思考を推測して演出しない。本人の経験を創作しない。
