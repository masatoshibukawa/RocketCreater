# 収録・編集・採用の計画

現在の流れは[175秒・9章の構成案](structure.md)。下表はその案に合わせた今後の制作順序で、台本・字幕は構成の検討後に確定する。

解析の収録は[指定チャットの分析](analysis-story.md)を基準にする。部品・機体・ミッションの受け渡し、対象・手法・評価の候補、依存処理とLLM選択、履歴・外部予測器の入力を追う。段階7の分岐専用条件を段階6の設計合格へ流用しない。現在のGemmaの実証と、移行後のClaude API収録を区別する。

## 進める順序

| 工程 | 作るもの | 完了条件 |
| --- | --- | --- |
| 1. 構成と代表画面 | 9章の配分、導入・チーム・反復の3場面 | 主張と見た目の方向が揃う |
| 2. 移行後の実行選定・試し録り | Claude APIで同じ要求の検査・変更・再検査を辿るB06の素材 | 次の判断へ戻った結果を、小さい再生画面でも追える |
| 3. 通し収録 | 一つの実行を辿る元映像とイベントログ | 元の時刻・案件・版を保存。省略箇所を特定できる |
| 4. 仮編集 | 175秒の無音構成と仮字幕 | 主張と画面が一致。処理待ちの省略を表示 |
| 5. 音と字幕 | 日本語の声、必要な操作音、同期した字幕 | 読み、音割れ、語尾、数字・否定・専門語を実際に確認 |
| 6. 初見確認・修正 | 理解できなかった箇所と修正記録 | 「誰の課題／Claudeの役割／得た出力／限界」を説明してもらう |
| 7. 完成物の採用 | overview内のMP4・サムネイル・出典・検証記録 | 全編再生、聴取、数値、権限、提出範囲を確認 |

制作の目標は11月7日に実行と粗編集、11月8日午前に音・字幕、午後に初見確認と最終確認、**11月8日19:00までに提出準備完了**。これは作業案で、公式締切は20:00 JST。未完了の工程を時間だけで合格にしない。

## 収録対象を固定する

- コード確認の基準はmainの`34a84967a218ca1672c68d4ea0dc72b0b51c653f`。実際の収録ビルドのSHA・API/UIの版・端末・解像度は別に記録する。
- 未マージの機能を採る場合は、統合・その版での確認を先に行い、収録対象のSHAを更新する。計算条件に関係する実装変更後は新しい実行を使う。
- この計画の作成ではアプリ起動・クラウド設計・GPU解析・プリンター操作は行わない。現在、クラウド設計は既定で無効。全ローカルLLM箇所をClaude APIへ移行する本人の方針を前提に、移行後のコードと実行を選ぶ。現在のGemma結果をClaudeの実行結果へ読み替えない。
- ネットワークなしで素材を用意する場合は、保存済みの**実際のClaude実行**を記録再生と明示する。模擬クライアントやコードの読み取りだけでは、実行時Claudeの証拠を満たさない。

## ファイルと記録

`output/media/product-demo/`内を、`capture/`、`audio/`、`generated/`、`edit/`、`review/`、`planning/`に分ける。準備コードで作成できる。

一つの収録に、日時、コードSHA、入力とseed、環境、モデル、run/source/project/version ID、元ファイルとハッシュ、実経過時間、使用範囲、短縮表示を記録する。認証情報や私用の通知を収録しない。元の失敗や中断も残し、採用素材だけの一覧を別に作る。

## 画面・音・字幕

1920×1080・30fpsを初稿の目標とする。UIの文字が読める拡大率へ調整し、意味のないマウス移動や通知を減らす。数値・単位・判定・ダウンロード操作を字幕で隠さない。

ナレーションは本人の声を第一候補にし、声の担当は未定。仮字幕は台本と同じ文を使うが、均等な時刻割りは録音後に合わせ直す。BGMは未選定で、声の明瞭さを先に確かめる。音声合成を採る場合は話者・利用条件・読みを確認する。まだ音声やBGMを生成したという意味ではない。

## 失敗時の切替

| 起きたこと | 対応 |
| --- | --- |
| 目的の未達・修正が記録できない | 別成功テイクで補わず、案件の選定へ戻る |
| 生実行が長い | 元の全長を残し、編集箇所へ「待ち時間を省略」等を表示。動画尺を処理時間と呼ばない |
| S08の条件変更を証明できない | 同じ14秒を出典・仮定の読み方へ差し替え、台本・字幕も一緒に更新 |
| 保存版のCAD・印刷・動画が同じ案件に結び付かない | 図面・部品表・製作票を中心にし、別設計のCGを成果として挿入しない |
| 写真調の機体が背景に埋もれる | 技術検査の合格だけで採用せず、UI中心の構成を維持して改良を待つ |
| 公開URLがログインを要求する | 採用せず閲覧方法を直し、別アカウントで再確認 |

旧S08の条件変更は、旧原稿を使う場合の分岐。9章案ではB06の再判断を優先する。B08の印刷素材は意図して別試作を示す挿入場面とし、切り替え時から「既存2L案・別試作」を表示する。Claude API移行が収録までに完了しない場合は、モデル表記と提出条件を再検討してから本編の構成を直す。

## 採用と提出の確認

完成MP4の全フレーム、全長、映像・音声トラックを検査する。実際の全編再生、音声聴取、字幕確認、別アカウントのURL再生は別に記録する。

提出するファイル・URL・リポジトリの範囲を確定してから、名称、絶対パス、本文・コメント、リンク先ホスト、メタデータ、ブランチ・コミット・PRを点検する。必要なAI利用申告、著作者、ライセンス、出典は保持する。既存プレビューのホスト名に由来表記が残る場合は、最終URLを未確定のままとし、提出方法を決めてから確認する。

採用前は[overviewのmanifest](../../assets/product-demo/overview/manifest.json)に完成物を追加しない。大会提出と動画の公開操作は、この計画作成には含めない。
