# RocketWright 仮v1

構成、尺、画面の見え方を確認する175秒の試写版。日本語の仮ナレーションと焼き付け字幕、書き出し用の字幕ファイルを用意した。共有用の動画と字幕は[試写素材](../../assets/product-demo/previews/v1/README.md)、編集時の収録素材は `output/media/product-demo/` に置く。

元のWindows音声版に加え、[4案の比較とAIナレーション差し替え版](narration-v1.md) を用意した。同じ映像を使用した別ファイルで、どちらも試写用。

- MP4: `output/media/product-demo/generated/preview-v1/rocketwright-preview-v1.mp4`
- SRT、主要12場面の一覧画像、書き出し確認値も同じディレクトリに保存。
- [編集データ](preview-v1.json)に24カットの時刻、表示文、字幕と読み上げを記録。

| 時刻 | 試写で見るポイント |
| --- | --- |
| 0:00–0:50 | 要求、モデルベース開発、フィン変更の影響から、設計を行き来する必要性が伝わるか。 |
| 0:50–1:06 | コックピットの緑の画面で2人を紹介。本人写真を参照した構成イメージ。 |
| 1:06–1:40 | 船外カットから階層型・適応型・5者の分担へ。ここまでで次の実例が理解できるか。 |
| 1:40–2:30 | 保存済みのGemmaの解析を、候補選択、再計算、未達、詳細確認の順に表示。UI資料は別案件と明記。 |
| 2:30–2:42 | 別の既存2L案の試作。2:33–2:38は[確認済みの5秒実写](print-progress.md)。印刷成功や飛行品質は示さない。 |
| 2:42–2:55 | Claude Codeによる開発と、実行時のClaude API移行予定を分けて表示。 |

冒頭のフィン厚さの例は段階7の分岐検証。1:40以降の根元長変更は段階5、詳細確認は段階6の記録を用いた。証拠と数値の対応は[解析の構成メモ](analysis-story.md)を参照。実アプリで同じ案件を通して収録する場面は、今回は保存記録の再構成で代用した。

Windowsの日本語音声「Microsoft Haruka」と、Pillow・NumPy・imageio-ffmpeg入りのメディア用Python環境で、リポジトリのルートから書き出す。素材は[9枚の配置](nine-frame-plan.json)と[実写の確認記録](print-insert-5s-verification.json)の各パスに置く。詳細解析の図は、編集データで固定したコミットから取り出す。

```powershell
output/media-venv/Scripts/python.exe -X utf8 AIvideo/product-demo/tools/render_preview_v1.py
```

ローカル出力は175秒、1920×1080、30 fps、AAC 48 kHz。映像5,250フレームを通して読み込み、2:33–2:38の150フレームを元の実写クリップと順番に比較した。仮音声とSFの構成イメージは試写用。提出版では、同一案件の実画面を収録し、音声と写真の扱いも確認する。
