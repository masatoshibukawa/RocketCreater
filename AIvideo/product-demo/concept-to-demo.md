# 背景・概念・役割分担から、機能とデモへ

構成検討中。**背景で生まれた問いに、階層型・適応型という考え方で答え、5者の役割分担で動く仕組みにし、その動作と結果を実演で確かめる。** この因果関係を動画全体の中心にする。

## 一本につなぐ順序

```mermaid
flowchart LR
  A[背景・意義<br/>何が難しく、なぜ必要か] --> B[設計の考え方<br/>階層型・適応型]
  B --> C[動かす仕組み<br/>5者の役割分担]
  C --> D[プロダクトの機能<br/>候補選択・再解析・履歴・出力]
  D --> E[実演と結果<br/>何が動き、どこまで確かめたか]
```

## 前半の問いと、後半で確かめるもの

| 背景で生まれる問い | 概念での答え | 実装の分担 | 実演で確かめること |
| --- | --- | --- | --- |
| 部品の改善が機体全体では悪化する。どこまで影響するか | **階層型**：部品の特性→機体の応答→ミッションの成否をつなぐ | スクリプトが各層を計算し、ハーネスが依存・設計版・判定を管理。LLMが戻る検討先を選ぶ | フィン変更で質量・飛行が変わる。同じ版で再解析し、影響を受けた古い判定が失効する |
| 状況が変わるたび、何をどこまで調べるか判断が要る | **適応型**：対象・手法・評価を、条件・不足・必要精度・資源に応じて選ぶ | ハーネスが実行できる組を絞り、予測器が改善量・費用を補助し、LLMが次の一手を選ぶ | 現在の未達と候補を表示し、選んだ手と理由、その後の計算結果まで追う |
| 判断を自動化しても、根拠と要求を保てるか | **役割分担**：目的、選択、予測、計算、実行管理を分ける | 利用者が要求を固定し、LLMが選択、予測器が補助、スクリプトが計算、ハーネスが検査・状態確定 | 要求が維持され、候補・選択・実計算・現在版の判定が結び付く。履歴が次の判断へ戻る |

物理の3階層、設計変数の層、解析精度、5者の役割は異なる整理。図も役割ごとに切り替える。[解析の分析](analysis-story.md)と[5者の分担](roles.md)を説明の基準にする。

## B05：34秒で概念から実演へ渡す

B05の開始とともに実アプリの操作を始める。概念図は、その操作が何を意味するかを示す短い重ね表示とする。B06は同じ案件の続きとして、説明した関係が動く一巡を確かめる。

| 時間 | 答える問い・画面 | 視聴者が理解して次へ進むこと |
| --- | --- | --- |
| 01:06–01:18 | **部分の変更が全体へどう響くか**。B03のフィンをそのまま使い、部品→機体→ミッションへ結果、逆方向に要求が渡る関係を実データの表示へ重ねる | 階層は、影響と要求を追うためにある |
| 01:18–01:28 | **次は何を調べるか**。今の不足から、対象・手法・評価の実行可能な組へ寄る。精度と資源の条件も示す | 適応性は、状況に応じて次の問いを選び直すこと |
| 01:28–01:40 | **判断と計算をどうつなぐか**。利用者、ハーネス、LLM、予測器、スクリプトの図。要求→候補と予測→選択→計算→確認を短く追う | この分担を使って、次の実演の一巡が動く |

コックピットから宇宙へ引き、光が集まる転換はB04末尾〜B05冒頭の数秒に収める。その光を依存関係と情報の受け渡しへ接続する。説明は実画面や実データの表示に重ね、独立したスライドを順に読む構成にはしない。台本・声はまだ確定しない。

## B06：説明した仕組みを32秒の一巡で確かめる

1. **01:40–01:44**：固定要求と現在の不足を確認。
2. **01:44–01:50**：ハーネスが用意した候補・除外理由、予測器による見込みを読む。
3. **01:50–01:54**：LLMの実際の選択と短い理由を表示。
4. **01:54–02:02**：計算を実行し、部品・機体・ミッションへ値が伝わる様子を見せる。待ち時間の短縮は表示。
5. **02:02–02:08**：同じ要求・現在の設計版で再判定。残る未達も表示。
6. **02:08–02:12**：予測と結果・費用を履歴へ戻し、次の判断入力につながるところを示す。

同じ案件・設計版の関係を追えることを優先する。B03の分岐試験と、新たに収録する実行が異なる場合は切り替えを明示する。現在のGemmaの証拠と、移行後に採るClaude APIの実行も区別する。

## B07で示す「機能・性能・結果」

| 種類 | 示したいもの | 今回の根拠と範囲 |
| --- | --- | --- |
| 機能 | 候補選択、再設計、依存する再計算、旧判定の失効、履歴参照、出力 | その動作の入力・選択・結果と、同じ版の記録で示す |
| 探索システムの性能 | 要求達成までの時間・解析回数・選択失敗率、候補の予測誤差等 | 履歴・予測器の動作は確認済み。一般的な探索効率の改善には、未使用条件・同一予算の比較が残る |
| 機体のモデル上の性能 | 高度、姿勢、変形、数値精度等 | 条件付きの計算値。現在の詳細確認には高度・静安定余裕・空力精度の未達がある |
| 実世界との接点 | CAD・製作データ、印刷工程 | 5秒の実写は既存2L案の別試作。今回の機体の完成や実飛行の保証へ広げない |

仕組みの説明は設計仮説、実演はその動作の証拠、性能改善は条件をそろえた評価の結論として分ける。出力ファイルが作れることと、要求を満たす機体が得られたことも区別する。

全体175秒は維持し、B05を34秒、B06を32秒、B07を18秒、B08を12秒、B09を13秒へ配分する。前半の必要性50秒とチーム紹介16秒は維持する。9枚の画像自体は据え置き、各場面の意味と時間をこの関係へ合わせる。
