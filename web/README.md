# RocketWright web UI

The default entry is now a dark production workbench for the local bottle-workshop trial.
It connects human analysis checkpoints, saved evidence, production downloads and separate
design/flight videos. See [local workbench operation](../docs/workbench.md).
The general conversation screen remains available. Paid design calls are disabled by default;
the API returns HTTP 423 until explicitly enabled during the final connection review.

Single-screen Next.js (App Router, TypeScript, React 19) frontend for the RocketWright design
agent. Left column: the conversation. Right column: tier badge and attempt counter, live attempt
log, reviewer verdicts per candidate, design candidate cards, and the flight charts (ascent profile for commercial/heavy, landing
scatter for bottle/amateur). Charts use Recharts only.

## Run

Requirements: Node >= 18.18 and the Python backend.

```bash
# backend (repository root)
uv run uvicorn api.main:app --reload --port 8000

# frontend
cd web
npm install
npm run dev          # http://localhost:3000
```

The backend allows CORS from `http://localhost:3000` and `http://127.0.0.1:3000`.

### Environment

| Variable | Default | Meaning |
| --- | --- | --- |
| `NEXT_PUBLIC_API_BASE` | `/backend` | Same-origin API prefix, or an explicit backend origin. |
| `ROCKETWRIGHT_API_URL` | `http://127.0.0.1:8000` | Server-side target of the `/backend` forwarding rule. |

Put it in `web/.env.local` to override, e.g. `NEXT_PUBLIC_API_BASE=http://127.0.0.1:8000`.

## How it works

- `app/lib/sse.ts`: pure SSE parser (`parseSseChunk`) for the `fetch` ReadableStream; the request
  is a POST, so `EventSource` cannot be used.
- `app/lib/designState.ts`: pure reducer that folds `AgentEvent`s (thinking / text / tool_call /
  tool_result / candidate / final / error / question) into UI state. Testable without React.
- `app/lib/useDesignStream.ts`: the hook that POSTs to `/design` and drives the reducer.
- `app/components/*`: presentational client components (chat, tier badge, attempt log, review
  panel, candidate cards, flight charts).
- `app/components/ReviewPanel.tsx` + `app/lib/reviewTypes.ts`: the review panel folds `review`
  events (per-aspect reviewer verdicts for one candidate: 安定性 / 回収 / 費用 / 安全, each a chip
  coloured by severity ok / minor / major / blocker, with findings and suggested changes) and
  shows a 「レビューで除外」 badge plus the `warning` event of kind `review_gate` when a blocker
  removed a design from the final list. `reviewsFromEvents` is a pure helper, testable without
  React.

Every number shown comes from a tool result in the stream; the UI only converts units
(`format.ts`). Provenance violations reported by the backend are shown as errors in the chat.

## Build verification

The integrated production build and TypeScript checks passed with Node 24.19.0 and the committed
pnpm lockfile. The existing candidate card required an explicit bottle-tier guard for TypeScript
narrowing. UI rendering uses plain CSS and Recharts; no additional UI kit was introduced.

## Drawings, reports and downloads

Candidate cards carry a collapsible 側面図 (side view) and download links.

- The side view is fetched lazily when the section is opened: `POST /artifacts/render` with the
  card's design returns `{id, download: {svg}}`, then `GET /artifacts/<id>.svg` returns the SVG
  generated by `rocketwright/drawing.py`. The SVG is our own output, which is why it is injected
  with `dangerouslySetInnerHTML`.
- Download links appear when the stream carries a `download` map: a `tool_result` of
  `export_report` (`report` .md / `bom` .csv / `json`) or `render_drawing` (`svg`), or a
  `final.result.designs[*].download` entry. `app/lib/api.ts` (`exportInfoFromEvents`) collects
  them; the cards match them to a design by value and list unmatched ones under the cards.
- Paths are backend-relative (`/artifacts/rep_1.md`) and are joined onto `NEXT_PUBLIC_API_BASE`
  by `apiUrl`. The backend serves `GET /artifacts/{id}.{svg|md|csv|json}` with the right media
  type; md/csv/json use `Content-Disposition: attachment`. Artifacts live in the backend process
  (`rocketwright/agent/store.py`, bounded, not persisted): restart the API and the links expire.
