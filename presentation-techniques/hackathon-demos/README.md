# ソフトウェアハッカソンのデモ発表

確認日: 2026-11-07

デモ発表では、作品の面白さや価値、実際の動作、技術的な工夫を、審査員が確認できる形で見せる。大会ごとの評価項目を先に読み、それぞれをどの操作・結果・説明で示すか決める。

技育関連イベント、Hack U、JPHACKS、MLH系の運営ガイド、海外の学生・テーマ別ハッカソンを、日本語・英語・中国語・韓国語・フランス語・スペイン語で探索した。公式ルール、運営者の助言、受賞結果、開発者のREADME、参加者の振り返りを分けて扱う。

## 最初に押さえること

1. **大会と審査段階を特定する。** 技育祭はカンファレンス、技育CAMPは勉強会・ハッカソン、技育展はピッチコンテスト。同じ作品でも求める完成度と発表条件が変わる。[技育プロジェクト公式](https://geek.supporterz.jp/geekpjt)
2. **早い段階で何ができるかを見せる。** 短く利用場面を説明し、入力から成果までの代表的な動作を通す。Devpostは、画面収録と説明によってアプリの動きを理解できる動画を勧める。[Devpost](https://help.devpost.com/article/84-video-making-best-practices)
3. **技術名に、難所・判断・動作の証拠を添える。** どの制約をどう解いたか、自分たちが実装した部分は何かを伝える。楽しさやインタラクション自体が価値となる作品もある。[HackNTXの評価項目](https://www.hackntx.com/judging-criteria)
4. **ライブ・録画・モックを明確にする。** 規則に応じて動作を見せ、トラブルに備えて実際の動作記録と資料を手元に保存する。録画や試作品を現在のライブ動作と取り違えさせない。
5. **受賞例からは具体的な工夫を取り出す。** 受賞した事実、公式の作品説明、本人の振り返り、こちらの分析を区別する。受賞者だけを見た比較から、ある技法で必ず勝てるとは結論できない。

## 調査の範囲

公開された文章、募集要項、受賞発表、READMEを用いた分析。リンク先の動画全編を再生して、声色・視線・身振りを採点したものではない。作品のコードを実行した性能検証も行っていない。発表や作品についての自己申告は、その出典を示して扱う。

原資料にない秒単位の構成、故障時の対応、練習用の型は、資料を踏まえた実務上の提案として示す。大会の指定がある場合はそれに合わせる。
