# 大会の違いとデモ発表の評価項目

## 技育のイベントを区別する

| イベント | 公式の位置付け | 発表の準備で考えること |
| --- | --- | --- |
| 技育祭 | 学生向けテックカンファレンス | 講演と、作品を審査するハッカソンを混同しない |
| 技育CAMP | 技術勉強会・ハッカソン | 開発期間内の成果、動作、工夫を見せる。回ごとの条件を確認する |
| 技育博 | 制作物を持ち寄る交流・フィードバックの場 | 短い説明を繰り返し、触ってもらい、疑問を聞く準備をする |
| 技育展 | 自作プロダクトを発表するピッチコンテスト | 継続開発した作品の価値・完成度・技術を、限られた時間で示す |

位置付けは[技育プロジェクト公式](https://geek.supporterz.jp/geekpjt)による。技育展の条件を、キックオフ以降に新規開発するCAMPの条件へ転用しない。

## 実際の発表時間と評価の違い

| 大会・資料 | 確認した形式と時間 | 評価・提出で重要なこと |
| --- | --- | --- |
| 技育CAMP2026 Vol.4 | 当該募集ページはプレゼン2〜3分を想定。チーム数で変更する場合あり | 資料、動作デモ、可能ならGitHub。キックオフ前の開発は不可 |
| 技育展2026 | 公開参加要項は予選・決勝とも180秒のプレゼンを指定 | 書類はこだわり、技術的挑戦、継続開発の伸びしろ。予選は作品の価値、完成度、技術レベル。予選までに動作する状態が必要 |
| 技育展2025 | 当該要項も予選・決勝180秒 | 2024年の体験談にある1分予選等を、2025・2026年のルールとして扱わない |
| Open Hack U 2025 TOKYO | 1チーム180秒、延長不可と明記 | 新規性、技術性、発展性、再現性。アイデアやプレゼンだけでなく、実際に動くものがあるか |
| JPHACKS2019の公開ガイド | 過去年度の評価例 | 問題着眼点、実行可能性、完成度・動作性、プレゼン。動作デモと開発差分を確認する。現行基準と同一とはしない |

| HackNTXの公開基準 | 実演を推奨 | 技術、設計、完成度。話術やアイデア自体を評価しないと明記。未完成でも作ったものと学びを示せる |
| NASA Space Apps 2025ガイド | 提出デモは7枚以内のスライド、または30秒以内の動画 | 主要言語、リンクのアクセス、指定データ、AI利用申告等の最低条件と、作品全体の評価を分ける |
| 韓国 SW중심대학 共同ハッカソン2023 | 最終発表は質疑込みで1チーム5分 | 専門家70％・参加者投票30％。専門家は創造性30、実装完成度25、使いやすさ20、商用可能性15、テーマ適合10 |
| Ocean Hackathon 2026 | 地域発表は数分・現地の公用語。国際決勝は英語 | 実証・デモ、データの利用、環境・社会的影響、構想、革新性、チームの連携・コミュニケーション |
| HP SCDS 2024案内 | 最大5分の発表と、その後の短い質疑 | 実用シナリオでのデモ、目標と達成度、長所・短所、使用技術。コードと実行方法等も提出 |
| HerTechVenture公開規則 | 最大5分 | 創造性、技術実装、社会的影響、発表、チームワークを各20％で評価 |

## 評価項目を見せる場面へ変換する

次は資料を組み合わせた設計用の対応表。重みは自分が参加する大会から転記する。

| 審査項目 | 発表で示す材料 | 技術者向けに深掘りする材料 |
| --- | --- | --- |
| 着眼点・独自性 | 従来のやり方と、新しい体験の違い | 代替方法、なぜこの組み合わせを選んだか |
| 価値・影響 | 誰がどこで使い、何が改善するか | 観察、利用者の反応、比較条件。娯楽なら楽しさや操作体験 |
| 技術的挑戦 | 難所一つと、それを越えた動作 | 制約、設計上の判断、アルゴリズム、失敗からの変更 |
| 完成度・再現性 | 入力から結果までの一続きの実演 | 実装済み範囲、実行条件、動かない条件、再現方法 |
| 設計・使いやすさ | 初めての人が使う流れ、結果の分かりやすさ | なぜそのUIか、例外や待ち時間の扱い |
| チームワーク・期間内の貢献 | 誰が何を担当し、期間内に何を作ったか | 既存部分との差分、連携の仕組み、提出コミット |
| スポンサー賞 | 指定製品が体験のどこを実現するか | APIやデータの具体的な入出力、利用の必須条件を満たす証拠 |

「有名なAPIを使う」「市場を大きく見せる」「スライドを派手にする」を、すべての大会の必須条件にしない。例えばHackNTXとHerTechVentureでは、発表自体の評価の扱いが違う。採点項目の根拠を見つけることが、優先順位を決める出発点になる。

## 開発範囲とスポンサー条件を確認する

JPHACKS2025の案内は、スポンサーが提供するハードウェア・APIの案内と、持ち込みについて説明している。それだけで特定APIの使用が全体賞に必須とは読まない。通常の全体賞と、個別企業賞・テーマ賞を分けて確認する。[JPHACKS2025](https://jphacks.com/2025/hackday)

一方、テーマ指定型の和泰AIハッカソン2026は、企業課題とAI活用を提案に含める。初期提案の動画、最終の実証、実演を同じ段階の要件として混ぜない。[当該案内](https://ht-hackathon.tw/tw/home/)
