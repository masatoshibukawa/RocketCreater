# 一般ソフトウェア大会

利用時は [共通の判断](../../../SKILL.md) を確認する。

大会、年度、段階、狙う賞を確定し、時間・提出物・開発範囲・動作条件を当該要項から読む。技育祭/CAMP/博/展の違いを確認し、過去参加記の1分予選を現在のルールにしない。

- 審査項目→見せる操作・結果・説明の表を作る。全体賞と企業賞・テーマ賞を分ける。
- 利用者の一場面を入力から結果まで通す。楽しさ・インタラクション中心なら無理に業務課題を作らない。
- 技術名に、制約→選んだ方法→自作の実装→動作の証拠を添える。コード量や苦労だけで難しさを示さない。
- 自作と既存部品、期間前後の差分、担当、実装済み・未実装を示す。公開READMEの将来予定を完成機能へ含めない。
- 台本は1・2・3・5分案を参考にし、質問と接続を引いてから調整する。
- 動作と画面共有、初期状態への復帰、機器の見え方、許可された代替録画を準備する。

成果物は採点と証拠の表、実演シナリオ、時間表、技術難所の説明と想定質問。発表自体を評価しない大会もあるので、すべての大会を話術や市場規模で採点する型にしない。受賞分析が必要なら調査カテゴリも読む。
