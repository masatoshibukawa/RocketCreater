# LLM事業者・専門分野の大会

利用時は [共通の判断](../../../SKILL.md) を確認する。

主催・共催・協賛、年度・段階・賞、募集目的を確かめる。サービス利用を「参加に必要／トラック必須／特別賞で評価／提供だけ」に仕分け、APIクレジットや受賞者の特徴から義務を作らない。

- 開発時の利用、製品の実行時の利用、人とモデル・計算の役割を分ける。開発だけの利用を製品内APIとして見せない。
- 経験→見落とされる制約→判断・評価・実装→利用者の成果を一つの動作で示す。「非エンジニア」「専門家」という属性だけに頼らない。
- LLMで何が現実的になったかを、入力解釈・道具・状態・検証・成果物のつながりで説明する。APIで絶対にしかできないことの断言や呼出回数で補わない。
- 条件変更、検査の失敗と修正、根拠の参照など、実際に再現できる核を選ぶ。モデル内部の思考を推測で演出しない。
- 比較するなら、従来手順・同じモデルのチャット・知識なし・固定処理の目的を区別し、入力・情報・予算・完了条件をそろえる。
- Researchトラックは問いと再現可能な結果、Buildは利用者のツール。自動化最大だけでなく、学習・表現・遊びの価値もあり得る。

成果物は募集条件と証拠の表、経験が効いた一件、実装と照合した動画台本。記録済みClaude日本大会は日本語3分以内の実動作、スライド発表不可という提供案内があるが、最新認証フォームは未確認。今回の依頼が同大会なら当該記録と最新案内を照合する。Codexの過去回の講評を同じ条件にしない。
