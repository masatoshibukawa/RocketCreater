# 出典評価・大会・受賞者調査

利用時は [共通の判断](../../../SKILL.md) を確認する。

発表技法の根拠を調べる場合と、大会・受賞作品を調べる場合を分ける。ウェブを調べる依頼では実際に調べ、保存済み資料だけで最新調査を装わない。

技法の根拠では、原著実験・調査・メタ分析と、大学・投資家・主催者の実務助言を区別する。対象集団、比較した条件、結果指標、確認できた本文の範囲を記録する。同じ論文の再掲や紹介を独立した効果の証拠として数えない。好きだという評価、理解できたという測定、受賞・投資の結果は別である。公開抄録だけなら全文精査とせず、限界と未確認を残す。

大会では、年・版、段階、賞を記録し、公式募集→規則・審査→公式結果→作者の実装説明→参加者の振り返りを照合する。

- 必須条件と推奨、全体賞とトラック・スポンサー賞、提供技術と必須技術を分ける。配点未公表なら重みを作らない。
- 受賞は公式表示と本人報告、Finalistを区別する。記事掲載日と大会年、現行READMEと受賞時の実装も分ける。
- 比較列は利用者・体験、入力と出力、技術難所、専門知識、確認できる証拠、発表への応用、限界を使う。
- 勝者のみの共通点を勝因・勝率へ変換しない。異なる価値やAPI構成の反例も探す。個別の採点理由が未公開ならそのまま残す。
- 作者の数値、予測、模擬データ、サンプル画面、将来予定を独立検証した実績にしない。
- 読んだ範囲、取得日、一次/自己申告/推論/提案を記録する。未取得や認証が必要な本文を取得済みにしない。秘密の原資料・アクセス情報を資料集へ再配布しない。

成果物は版を特定した条件表、受賞・Finalistの比較表、出典と確認範囲、次の制作に使える具体的な提案。調査依頼を無断の応募・外部投稿・関係者への送信へ広げない。
