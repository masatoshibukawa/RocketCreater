# 1分から5分のビジネスピッチ

各表は**発表のみの持ち時間**に対する独自の配分案。数字は区切りの目安であり、実際の原稿は制限より短く通せるように練習する。質疑込みの枠では、先に質疑の時間を差し引く。

## 1分で価値と次の依頼を伝える

**向く場面:** 初対面、交流会、営業の入口、投資家への短い紹介、提案の予告。

MIT Orbitは、1分では会社名、誰に提供するか、顧客の便益を中心にし、専門的な説明を増やさないよう勧める。まず「何をするのか」を理解してもらう。[原文](https://orbit-kb.mit.edu/hc/en-us/articles/205147056-What-are-typical-pitch-durations-for-a-startup/)

| 時間 | 役割 | 話すこと |
| --- | --- | --- |
| 0:00〜0:10 | 対象と課題 | 会社・提案名、誰がどんな問題を持つか |
| 0:10〜0:30 | 解決と便益 | どう改善し、その人に何が起きるか |
| 0:30〜0:45 | 信用の根拠 | 実績、検証、関係する経験のうち強いもの一つ |
| 0:45〜1:00 | 次の行動 | 誰に何を相談・依頼したいか |

**技法:** 一文の価値提案と、一つの裏付けに絞る。数字を並べず、顧客の変化を言う。投資家なら次回面談、営業なら課題の確認やデモ、社内なら検討の許可など、目的に合った依頼で結ぶ。

**削るもの:** 長い自己紹介、会社沿革、機能一覧、詳しい技術、市場分析の全体。裏付けを入れる余裕がなければ、顧客と価値を優先する。

**スライド:** なしでも成立させる。一枚使うなら、価値を示す一文と、画面・写真・数字など一つの材料にする。

## 2分で利用場面と選ぶ理由を加える

**向く場面:** 短い事業紹介、予選のピッチ、提携や営業の最初の説明。

Seattle Universityの2分版は、フック、短い要約、顧客と問題、解決、検証、代替、顧客獲得、チーム、事業モデル、依頼を推奨項目にする。全部を別々の長い説明にせず、関連する項目をまとめて話す。[原文PDF](http://cms.seattleu.edu/media/seattle-university/albers-school-of-business/student-life/innovation-and-entrepreneurship-center-iec/files/HSBPC-Pitch-Outline.pdf)

| 時間 | 役割 | 話すこと |
| --- | --- | --- |
| 0:00〜0:15 | 一文の全体像 | 顧客、課題、提案 |
| 0:15〜0:35 | 課題の場面 | 現在の対処と負担を一つ |
| 0:35〜1:05 | 解決の場面 | 入力・利用・成果の短い流れ |
| 1:05〜1:30 | 証拠と違い | 検証結果と、既存の方法より選ばれる理由 |
| 1:30〜1:45 | 実現する理由 | チーム、事業モデル、導入方法のうち重要な条件 |
| 1:45〜2:00 | 次の行動 | 依頼、相手が得るもの、確認したいこと |

**技法:** 顧客の「現在のやり方→新しいやり方→結果」を一つの場面で示す。冒頭のフックは、課題に関係する事実や短い場面にする。内容と無関係な驚きで時間を使わない。

**削るもの:** 複数の顧客像、複数のデモ、競合企業の長い紹介。重要な差を一つだけ説明する。

**スライド:** 1〜3枚を開始目安にする。現在の負担、改善後、証拠と依頼を、必要に応じて統合する。

## 3分で全体像を通す

**向く場面:** Demo Day、コンテスト、事業の概要紹介、意思決定者への短い提案。

Techstarsは、3分を事業全体を説明しつつ各部分を絞れる重要な長さとして扱う。課題と解決の導入を急ぎすぎず、冒頭と最後の依頼を明確にする。[原文](https://www.techstars.com/blog/founder-advice/inside-week-1-a-sneak-peek-into-the-techstars-accelerator-experience)

| 時間 | 役割 | 話すこと |
| --- | --- | --- |
| 0:00〜0:20 | 全体像 | 顧客と、一文の事業・提案説明 |
| 0:20〜0:45 | 問題 | 課題が起きる場面と現在の対処 |
| 0:45〜1:20 | 解決 | 仕組み、短い実演または結果 |
| 1:20〜1:50 | 証拠 | 需要、利用、売上、比較、技術等の強い事実 |
| 1:50〜2:20 | 成立条件 | 市場・価格・販売、または導入対象・便益 |
| 2:20〜2:40 | なぜ自分たちか | 経験や能力が効いた判断と結果 |
| 2:40〜3:00 | 依頼 | 必要な資源、到達目標、次の行動 |

**技法:** 「問題→解決→証拠→成立する理由→依頼」を一続きにする。重要な情報を全部独立した章にするより、Why nowや競争上の差を関係する場面へ組み込む。

**削るもの:** 二番目以降の用途、機能の枝分かれ、細かな沿革や経歴。質疑に必要なものは補足資料へ移す。

**スライド:** 3〜5枚を作成開始の目安にし、各画面の主張を一つにする。YCの短いDemo Day向け解説も、読める・単純・一目で分かることを重視する。[YC](https://www.ycombinator.com/library/4T-how-to-design-a-better-pitch-deck)

**練習:** MIT Orbitは3分版を2分30秒で話せるようにして30秒の余裕を持つことを勧める。一つの練習基準として使い、当日の上限や指定された内容を確認する。[MIT](https://orbit-kb.mit.edu/hc/en-us/articles/205147056-What-are-typical-pitch-durations-for-a-startup/)

## 5分で証拠による納得を作る

**向く場面:** 短い提案審査、事業コンテスト、サービス紹介、初回の具体的な検討。

Bpifranceは5分を短いピッチの区分として挙げる。MIT Orbitも5〜10分を、関心を得てさらに詳しい面談へ進むための長さとして説明している。[Bpifrance](https://bpifrance-creation.fr/encyclopedie/porteur-projet-preparation-droits-obligations/preparation/plan-type-pitch-presenter)、[MIT](https://orbit-kb.mit.edu/hc/en-us/articles/205147056-What-are-typical-pitch-durations-for-a-startup/)

| 時間 | 役割 | 話すこと |
| --- | --- | --- |
| 0:00〜0:20 | 全体像 | 何を提案し、何を判断してほしいか |
| 0:20〜1:00 | 課題 | 対象顧客、負担、現在の方法 |
| 1:00〜2:00 | 解決 | 重要な利用場面の実演や具体例 |
| 2:00〜2:55 | 証拠 | 結果、顧客の行動、比較、検証条件 |
| 2:55〜3:35 | 成立条件 | 市場・価格・販売、または便益・費用・導入先 |
| 3:35〜4:15 | 選ぶ理由 | 競合・代替との違いと、実行できるチーム |
| 4:15〜4:40 | 計画 | 次の到達目標と必要な資源 |
| 4:40〜5:00 | 結び | 中心の主張と依頼を再提示 |

**技法:** 3分版で短く触れた証拠を、比較条件や利用場面まで含めて説明する。「こう動く」という実演に、何を確認できたのかという結論を添える。ソフトウェアなら操作を全部見せず、価値が分かる一つの処理を選ぶ。

**削るもの:** 機能ツアー、細かな市場区分、複数年の数値表の読み上げ。質問されそうな情報は、すぐ出せる補足へ置く。

**スライド:** 4〜6枚を出発点にする。Bpifranceの口頭説明ガイドには、5分で5枚以内という例もある。枚数から内容を埋めるより、読める図と一つの主張で構成する。[原文](https://bpifrance-creation.fr/encyclopedie/porteur-projet-preparation-droits-obligations/preparation/presenter-oralement-son)

## 短いピッチの共通チェック

- 最初の文だけで、誰に何を提供するか分かるか。
- 裏付けとなる事実があり、仮説と区別できるか。
- 「なぜ自分たちか」が、提案に関係する経験や判断になっているか。
- 最後に相手へ求める行動が一つに定まっているか。
- 時間超過時に削る場面を決め、早口に頼らず通せるか。
