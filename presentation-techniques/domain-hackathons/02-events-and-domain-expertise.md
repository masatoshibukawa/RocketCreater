最後の例では、名称がハッカソンでも受賞競争を前提にできない。募集の目的が共同研究や能力形成なら、引き継げる成果や再現手順に重心を置くのが自然である。

提出形式も揃っていない。NASAの2025年全体ガイドのデモは7枚以内または30秒以内が最低条件で、日本大会の日本語3分動画とは違う。ローカル会場の発表時間と、全体審査への提出物も分ける。5観点の記載を各20％の公式配点へ読み替えない。[D14](sources.md)

## 生命科学大会は、今回に特に近い比較対象

Anthropic・Cerebral ValleyとGladstoneの大会は、専門家を明示的に募っている。Researchでは、生物学の問いに対する発見・学習済みモデル・他人が再現できる分析を成果とする。Buildでは、科学者・クリニック・バイオ企業など具体的な利用者に足りない道具を作る。研究データを提供し、審査員にも両組織の担当者が入る。[募集ページ](https://cerebralvalley.ai/e/built-with-claude-life-sciences)

この違いから、同じ3分でも構成を変えるとよい。

| Research向けの提案 | Build向けの提案 |
| --- | --- |
| 問い → データと比較条件 → 分析 → 結果 → 不確実性・再現方法 | 利用者の障壁 → 入力 → 実処理 → 使える出力 → 検証・利用後の変化 |
| 判断単位は「何が分かったか」 | 判断単位は「誰が何をできるようになったか」 |
| 有意でなかった結果も問いへの回答になり得る | 完成した導線と未実装の導線を分ける |

研究トラックに、必ず顧客数や収益計画を詰め込む必要はない。利用者向けツールに、研究上の新規発見があるかのような主張を足す必要もない。それぞれの成果を支える証拠を優先する。

## 主催者、審査員、専門家が担う役割

一般的な比較では、次の3つの目的が重なり得る。どれが強いかは開催回の募集・審査・賞で判断する。

| 目的 | 資料から分かる例 | 専門家を集める意義についての分析 |
| --- | --- | --- |
| 製品の新しい可能性を発見する | Opus 4.6/4.7の募集 | 製品チームが自分たちでは知りにくい用途と制約を持ち込める |
| 現場の課題を解決する | Japan、MIT医療、Ocean | 何が本当に困るか、既存手順のどこを変えてよいかを判断できる |
| 研究成果と再現性を生む | Life Sciences、SciLifeLab | 良い問い、意味のある比較、データの適用範囲を定められる |

日本大会はプロジェクトと作り手を世界に紹介すると公表しているため、作り手の経験が物語に入るのは自然である。一方、「主催者に好かれるAPIを多く使うほど勝てる」とする非公開の採点ルールは確認できない。

## 大会全体の賞と、スポンサー賞を分ける

MIT GrandHack 2026のInterSystems Challengeは、同社のGenAIまたはFHIR技術を使う課題であり、審査にも技術利用と技術的な整合性が明記される。この条件は、そのスポンサー課題に挑戦する理由を直接説明できる。[スポンサーの要項](https://developer.intersystems.com/intersystems-challenge-mit-grandhack-2026/)

Columbia X NYUの作品にはClaude TrackとLinkup Challengeの受賞表示がある。Linkup賞の受賞を、そのままAnthropic本体主催の大会の総合上位やClaude活用の最高評価と扱わない。[公式ギャラリー・作品ページ／D18](sources.md)

実務では「参加に必要」「特定トラックで必要」「特別賞で評価」「提供されているだけ」の4つに使用サービスを仕分ける。この区分を作ってから、発表の中で何を説明するか決める。

## ドメイン知識を製品のどこへ入れるか

次は大会横断の分析から作った設計・発表用の観点である。

| 知識が効く場所 | 知識を持つ人から得るもの | 製品とデモでの証拠 |
| --- | --- | --- |
| 課題の発見 | 現場で反復する失敗、隠れた手戻り | 具体的な一件と、従来の処理 |
| 入力・データ | 重要な資料、単位、地域語、欠損の意味 | 同じ入力のどこを読むかを表示 |
| 判断 | 優先度、許されない誤り、例外 | 条件変更で判定が変わる一例 |
| 評価 | 専門家の判定、既知の事例、失敗条件 | 評価対象・正解の作り方・失敗例 |
| 操作と成果物 | 次の担当者が使える情報、必要な順序 | 出力を受け取って次の行動へ進む |
| 適用範囲 | 地域・制度・対象・測定条件 | どこまで確認したかを明示 |

肩書がなくても、当事者としての経験、継続的な趣味、地域へのアクセス、専門家への聞き取りが強みになり得る。例えば職人の知識を集めたMaestrIAは、知識を構造化して比較評価に使う方法の参考になる。ただし、聞き取り1人分を業界全体の正解としない。

チーム編成では、課題を知る人、作れる人、評価できる人の機能を確保する。最大2名の大会なら一人が複数の役を担い、外部への聞き取り等の扱いは当該大会のルールに沿って確認する。専門家の名前を並べるより、誰がどの判断をしたかを示す方が再現可能である。

## 言語・地域差は、出力と評価にも入る

日本大会は提出も日本語。Oceanの2026年規則はローカル発表を開催国の公用語、国際決勝を英語とする。NASAの2025年ガイドは主に英語の提出を最低条件とする。これらは明文の形式差であり、国民性の推測ではない。[U01・D12・D14](sources.md)

翻訳だけでは保存できない知識もある。MaestrIAの主催者紹介には地域の材料、職人の言い回し、相場を知識に入れる例がある。許認可や医療の手順も、利用地域が変われば前提を確認し直す必要がある。ローカル知識を評価用ケースにも反映する、という設計上の提案につながる。

専門外の審査員へは、最初に「誰が・何を決めるための道具か」を平易に示す。専門家へは、その後に元データ、判断基準、例外を辿れるようにする。全員に同じ専門用語を一度に説明するより、理解と検証の入口を用意する。
