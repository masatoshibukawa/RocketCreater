# 目的・構成・主張と根拠

## 研究発表で何を判断してもらうか

MITの技術発表ガイドは、新しい成果を伝える場合と、実験装置への助言を求める場合で、方法と結果の重点を変える。名古屋大学のガイドも発表の場の目的と、その後の議論を重視する。[S01・S02](sources.md)

以下は、それを研究の場面へ適用した整理である。

| 場面 | 聴衆に判断してもらうこと | 本編の重点 |
| --- | --- | --- |
| 学会の口頭発表 | 新しい知見・方法に意味があり、根拠が十分か | 問い、既知との差、主要結果、解釈と範囲 |
| 研究室の進捗報告 | 次に何を調べ、どの判断を変えるべきか | 前回の問い、試行、失敗、未確定事項、相談 |
| 論文紹介 | 著者の主張がデータに支えられているか | 中心主張、決定的な実験・議論、対照、限界 |
| ポスター | 立ち止まって議論・共同研究する価値があるか | 一つの主要メッセージ、図、詳細へ進める導線 |
| 学位・資格審査 | 独立して研究を進め、選択と限界を説明できるか | 貢献、方法の妥当性、個人の担当、技術的な質問への準備 |
| 一般向け研究紹介 | 問いと意味を専門外の人が理解できるか | 具体的な問い、研究の工夫、発見・意義 |
| 研究費のピッチ | この計画を、この体制で支援する理由があるか | 問い、着眼点、実行可能性、予備的根拠、リスクと代替策 |

学会発表でも複数分野の聴衆がいる。専門家という属性だけで前提知識が共有されていると考えず、その場に必要な用語と比較対象を説明する。

## 論文の章を縮める前に、論証を組み立てる

論文は戻って読めるが、口頭発表は時間に沿って進む。MITは発表を論文と異なる順序で構成してよいとする。[S01](sources.md) 次の7項目を一文ずつ書く方法は、制作のための提案である。

1. **問い**：何が分かっていない、あるいは何を達成できないのか。
2. **不足**：既存研究は何を説明でき、どの条件が残るのか。
3. **着眼点**：今回どの考え方・観測・方法を試すのか。
4. **検査方法**：何を測り、比較し、どんな結果なら主張を支持するのか。
5. **結果**：実際に何を観測・導出したのか。
6. **解釈**：その結果から何が分かり、どの別解釈が残るのか。
7. **適用範囲**：対象、条件、仮定、未検証の場所はどこか。

各主要結果をこの問いへ戻す。実施した作業の時系列と、聴衆が理解しやすい論理の順序が違う場合は、後者を選ぶ。試行錯誤の経緯は、方法の選択や限界を理解するために必要な部分を残す。

## 貢献の種類に合わせて証拠を選ぶ

次は分野横断の検討用リストで、全研究に全項目を課すチェック表ではない。

| 貢献 | 説明する証拠の例 | 主張を広げすぎる例 |
| --- | --- | --- |
| 新しい観測・実験結果 | 対象と条件、測定方法、比較、ばらつき、反復 | 一つの条件から全対象への一般化 |
| 理論・証明 | 定義、仮定、命題、証明の要点、既存結果との関係 | 数値例のみで一般命題を証明したとする |
| 計算・機械学習の方法 | 評価データ、比較手法、計算・調整予算、外部条件、失敗例 | 一つのデモを汎用性能とする |
| シミュレーション | モデル仮定、検証対象、実測との照合、感度・収束 | 計算が完走したことを現実との一致とする |
| 定性・フィールド研究 | 対象と選定、記録・分析の過程、解釈を支える事例、反例 | 抽出した一つの発言で集団全体を代表させる |
| データセット・研究ツール | 取得・加工・品質、既存との差、利用手順、再現可能性 | 配布したことだけで有効性を実証したとする |

成果物の見栄えと研究の根拠を両方示す。可視化、アプリ、実演は有用でも、それ自体が比較・妥当性確認の代わりになるとは限らない。

## 方法をどこまで説明するか

本編には、結果を評価するのに必要な方法を置く。入力・対象、対照、操作、指標、重要な仮定が分からなければ、聴衆は結果を判断できない。細かな設定・導出・追加ケースは補足へ置き、必要時に辿れるようにする。

方法そのものが貢献なら、その仕組みと既存との差を主役にする。結果だけを大きく見せる構成へ一律に寄せない。進捗報告で方法への相談が目的なら、未確定の設計を詳しく議論する方が有用である。

## 結果・解釈・期待を分けて話す

| 種類 | 発話の型 |
| --- | --- |
| 観測・導出 | 「この条件で、［測定・計算・導出結果］が得られました」 |
| データに基づく解釈 | 「この結果は、［説明］と整合します。ただし［別解釈］は残ります」 |
| 未検証の仮説 | 「［原因］の可能性がありますが、この実験では切り分けていません」 |
| 将来計画 | 「次に［条件・比較］を追加して確かめます」 |

統計的に有意でないことを、そのまま効果ゼロの証明としない。推定の幅や対象数、研究設計が許す結論を示す。誤差棒の種類と独立した観測の単位も必要になる。[F02](sources.md)

弱い結果を強そうな物語で補うより、何を否定・限定できたかと、次に識別したい点を説明する。発見した順序を入れ替えて伝えても、事前の仮説と事後の解釈を混同しない。

## 研究計画と研究費ピッチ

研究費ピッチの2026年の教育記事は、審査者に合わせた科学的な論証と、申請者・計画の適合を重視し、物語が証拠や不確実性を置き換えてはならないと述べる。採択率を比較した実験ではない。[S18](sources.md)

まだ結果がない計画は、「問い → 検証可能な予測 → 方法 → 予備的根拠 → 成否の判断 → リスクと代替策」と組み立てる案が使える。予備データ、他者の既報、自分たちがこれから得たい結果を明確に分ける。

## 研究室と論文紹介での重点

進捗報告では「今週やったこと」に加え、「何を判断するためにやり、その結果で何が変わったか」を示す。未完成な研究を、完成済みの成果発表のように演出する必要はない。

論文紹介では、図を全て番号順に紹介する義務はない。UVAのガイドは中心主張を支える重要な実験の選択と、議論の進行を重視する。[S09](sources.md) 著者の結論、自分の読み取り、追加で必要と考える検証を分ける。
