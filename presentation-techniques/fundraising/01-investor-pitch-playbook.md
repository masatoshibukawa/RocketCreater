# 資金調達ピッチの構成と投資家に示す証拠

投資家が検討できるピッチは、顧客の課題から、解決、需要の証拠、成長の仕組み、チームの能力、調達後の到達点までがつながっている。スライドの順序は、その事業の最も強い証拠と、投資家が確かめたい点に合わせて調整する。[Sequoia](https://articles.sequoiacap.com/writing-a-business-plan)、[YC](https://www.ycombinator.com/library/4A-a-guide-to-seed-fundraising)

以下の構成とワークシートは、[原語資料15件](sources.md)を組み合わせた実務上の提案。個社の必要調達額や投資条件を決めるものではない。

## 投資家と面談の目的を決める

連絡前に、投資対象の業界・地域・段階、投資金額の範囲、過去の投資先、自社に関心を持つ理由を確認する。紹介や登壇からの初回接点なら、次の面談を得ることが当面の目標になり得る。検討が進んだ面談なら、残る懸念への回答や意思決定の手順を確認する。[YC](https://www.ycombinator.com/library/4A-a-guide-to-seed-fundraising)

エンジェル、VC、CVCという名称に加え、相手の投資方針と意思決定者を調べる。事業会社との面談では、出資、試験導入、販売提携のどれを相談するかも冒頭で明確にする。

## 調達段階に合わせて証拠を選ぶ

| 段階の目安 | 主に説明する不確実性 | 示す証拠の例 |
| --- | --- | --- |
| プレシード | 課題は実在するか。このチームは解けるか | 顧客への聞き取りと行動観察、試作品、支払意思の検証、技術上の進捗、チームが得た独自の理解 |
| シード | 解決が使われ、事業につながる兆候はあるか | 初期の有料利用、繰り返しの利用、継続率、顧客の反応、価格や販売経路の検証 |
| シリーズAを目指す段階 | 成長を再現・拡張できるか。何が制約か | 顧客群別の継続、売上の質、販売経路ごとの獲得、営業期間、採算、追加投資で改善する制約 |

これは、需要検証から成長・財務へ問いが深まるという資料の助言を、一般的な段階名に対応させた整理。ラウンド名と証拠の水準は一対一ではない。創薬・ハードウェア・ディープテックなどでは、売上以前の技術検証、製造、規制対応、実証先などが重要な到達点になる。[Plataforma ONE](https://one.gob.es/es/contenidos/buscas-financiacion-trucos-para-acercarte-potenciales-organismos-inversores)、[YC](https://www.ycombinator.com/library/4A-a-guide-to-seed-fundraising)

## 用途別に資料を作る

| 用途 | 必要な働き | 入れる情報 |
| --- | --- | --- |
| 初回のメール | 事業と相手に連絡する理由を理解してもらう | 顧客・課題・解決、強い事実、チーム、具体的な依頼 |
| 送付して読んでもらうデック | 話し手がいなくても意味が通り、社内で回覧できる | 主張の見出し、必要な説明、数字の定義・期間・出典、連絡先 |
| 面談で話すデック | 短く全体像を共有し、質問に応じて深掘りする | 中心の主張と証拠、実演、質問に使う補足資料 |
| Demo Dayの登壇 | 限られた時間で記憶され、次の接点を作る | 一目で分かるスライド、絞ったメッセージ、次の行動 |
| 投資検討の詳細資料 | 主張の根拠を確認できるようにする | 月次の数値、顧客群別データ、財務計画、契約・資本関係等の要求された資料 |

送付用の説明を登壇で全部読み上げず、登壇用の画像だけで詳細の確認を済ませない。YCのDemo Day向けデザインと、KVIC寄稿の再読・回覧を重視する助言は、この使い分けで両立できる。[YCのデザイン解説](https://www.ycombinator.com/library/4T-how-to-design-a-better-pitch-deck)、[KVIC](http://kvicnewsletter.co.kr/page/newsletter/vol58/html/06.html)

## 12枚で作る構成案

| 枚 | 伝える主張 | 載せる材料と確認すること |
| --- | --- | --- |
| 1 会社と一文の説明 | 誰の何を改善する会社か | 会社名、対象顧客、成果。事業が分からない抽象的な標語で終えない |
| 2 課題と現在の対処 | 顧客に十分に大きな困り事がある | 顧客の具体的な場面、頻度、時間や費用、現在の代替手段 |
| 3 解決と実演 | 顧客の作業や結果がどう変わるか | 入力、処理、成果の短い流れ。実装済みと計画を区別する |
| 4 今取り組む理由 | 最近の変化が機会を作っている | 技術、費用、顧客行動、制度等の具体的な変化と自社との関係 |
| 5 需要と進捗 | 仮説を支える行動や実績がある | 利用、継続、支払、技術実証。期間・対象・定義を付ける |
| 6 市場と最初の顧客 | 成長の余地と最初の入口がある | 対象顧客数、単価、到達可能な範囲、その後の拡張 |
| 7 事業モデル | 誰が何にいくら払うか | 利用者と支払者、価格、契約単位、費用の構造 |
| 8 顧客獲得と成長 | 顧客に届く方法を説明できる | 販売経路、営業の流れ、検証結果、今後試す施策 |
| 9 競合と優位性 | 顧客が自社を選ぶ理由がある | 直接・間接競合、手作業や現状維持、重要な比較軸 |
| 10 チーム | この課題と計画に適した能力がある | 関係する経験、その経験が変えた判断、役割分担、不足する役割 |
| 11 財務と調達計画 | 資金が成果につながる | 手元資金、支出と収入の前提、希望調達額、使途、到達目標 |
| 12 将来像と次の行動 | 成功時の姿と今回の依頼が明確 | 中心の論点の再提示、次回面談や確認してほしい資料、連絡先 |

Sequoia、YC、INCIBE、Bpifranceの項目をまとめた構成案。12枚は固定ルールではない。強い実績があるなら早めに示し、一つの図では伝わらない論点は分ける。短い登壇では統合し、詳細は補足へ移す。[Sequoia](https://articles.sequoiacap.com/writing-a-business-plan)、[INCIBE](https://www.incibe.es/sites/default/files/Emprendimiento/Guia%20r%C3%A1pida%20para%20elaborar%20tu%20pitch%20deck/INCIBE%20-%20GUIA-ES-4%20-%20Gu%C3%ADa%20r%C3%A1pida%20para%20elaborar%20tu%20Pitch%20Deck.pdf)、[Bpifrance](https://bpifrance-creation.fr/encyclopedie/porteur-projet-preparation-droits-obligations/preparation/plan-type-pitch-presenter)

## 数字を信頼して読めるようにする

実績、見込み、目標を見た目と言葉で分ける。比較するグラフでは期間・集計対象・計算方法をそろえ、施策前後で何が変わったかを説明する。原資料が重視する実際の財務・需要・継続の情報を、次のように定義して用意する。[江苏股权交易中心](https://www.jseec.com.cn/enterprise-roadshow-howto.html)、[INCIBE](https://www.incibe.es/sites/default/files/Emprendimiento/Guia%20r%C3%A1pida%20para%20elaborar%20tu%20pitch%20deck/INCIBE%20-%20GUIA-ES-4%20-%20Gu%C3%ADa%20r%C3%A1pida%20para%20elaborar%20tu%20Pitch%20Deck.pdf)

| 数字 | 一緒に示す条件 |
| --- | --- |
| 利用者・顧客数 | 登録、活動中、支払中のどれか。個人・組織・契約の単位 |
| 継続率 | 使い始めた時期で分けた顧客群、対象数、観測期間、継続の定義 |
| MRR・ARR | 定期売上の算定範囲。ARRを月次売上の12倍で年換算する場合はその旨を記載し、単発の収入を混ぜない。確定した将来売上とは区別する |
| 売上・受注・取扱高 | 売上計上、契約締結、流通した総額のどれか。通貨と期間 |
| パイプライン | 相談、実証、購入意向、契約済みの別。未確定案件を売上へ足さない |
| 粗利・案件の採算 | 売上から差し引く費用範囲。AIなら推論、再実行、外部ツール、人手対応等 |
| 顧客獲得費用 | 費用に含む人員・広告等、獲得した顧客の範囲、期間と獲得までの遅れ |
| 成長率 | 起点と終点の実数、月次・年次の別、母数。少数からの増加では実数も示す |

売上前なら、何が未検証かと次に試す方法を具体化する。短い観測から長期の顧客価値を確定したように見せるより、現時点の継続と費用を示す。

## 市場規模を積み上げる

大きな市場総額は長期の可能性を示す材料になるが、最初の売上の説明には顧客と価格が必要になる。Coralは、対象顧客の像と支払意思を考えた積み上げを勧めている。[原文](https://coralcap.co/2018/05/how-to-create-a-defensible-market-size)

**計算の練習用の仮定:** 対象企業1万社、年額20万円なら年間20億円の候補市場になる。そのうち当面提供できる地域・条件に合う企業が2千社なら年間4億円。さらに、販売人員・営業期間・導入能力から初期100社を目指すなら年間2千万円の売上計画になる。これは架空の計算であり、RocketCreaterの市場規模や売上予測ではない。

資料には、企業数の出典と重複の扱い、価格の検証方法、当面提供できる範囲の理由を付ける。総市場の何％を取るという計算に加え、実際にどう顧客へ届くかを説明する。

## 競合とチームを対応させる

競合には、同じ製品だけでなく、別の方法で同じ問題を解く企業、顧客の手作業、既存の社内ツールも含めて検討する。比較軸は顧客の購入理由に関係するものを選ぶ。自社に有利な軸を置くだけで終わらず、選ばれない条件も理解する。[Coral](https://www.coralcap.co/2018/05/how-to-talk-about-competitors/)

「なぜ自分たちか」は、肩書きから一歩進め、次の因果関係で話す。

> 私たちは［現場の経験・顧客との接点・技術］から、［他では見落とされていた制約］を知った。そのため［設計・評価・販売方法］を選び、［確認できた結果］を得た。

これは台本用の型。研究経験、顧客へのアクセス、独自に蓄積したデータや評価方法などを、実際の判断と結果に対応させる。BLTが強調する差別化とチームの関係を、検証可能な説明へ落とし込む。[BLT](https://blt.kr/column?bmode=view&idx=11155144)

## 調達額を使途と到達目標に結び付ける

「開発とマーケティングに使う」から具体化し、誰を採用し、何を作り、どの顧客に届け、どの条件で成果を確認するかを示す。YCは次に資金調達可能な到達点と必要資金を結び付け、Bpifranceは希望額と使途を説明するよう勧める。[YC](https://www.ycombinator.com/library/4A-a-guide-to-seed-fundraising)、[Bpifrance](https://bpifrance-creation.fr/encyclopedie/porteur-projet-preparation-droits-obligations/preparation/plan-type-pitch-presenter)

概算は「計画期間の現金支出＋必要な余裕資金−期首現金−保守的に見積もった現金収入−確度の高いその他資金」から考える。そのうえで月次の資金残高を確認する。総額が足りていても、入金より先に支払が集中する場合がある。

| 使途 | 到達目標 | 確認方法 | 未達時の対応 |
| --- | --- | --- | --- |
| ［担当者・人数・費用・時期］ | ［顧客や技術がどの状態になるか］ | ［指標・評価対象・期限］ | ［何を縮小・変更して検証するか］ |

希望額が少ない場合と十分な場合の計画も用意し、追加資金が何を早めるか説明する。原資料に出てくる過去の相場や期間を、そのまま必要額の根拠にしない。

## AIスタートアップへ応用する

以下は、顧客価値、競合、費用、チームという投資家の問いを、AI事業へ適用した整理。

| 説明すること | 用意する証拠 |
| --- | --- |
| 顧客の作業がどう変わるか | 従来の手順と、新しい手順の時間・品質・費用の比較 |
| LLM・APIがどの役割を担うか | 入力、外部ツール、処理、検証、人の確認、成果の具体的な流れ |
| 継続して任せられるか | 代表的な利用条件と失敗条件での評価、失敗時の対応、顧客の再利用 |
| 事業として採算が合うか | 成功した一件当たりの推論・再試行・人手対応等の費用と、顧客の支払額 |
| 他社と何が違うか | 業務への統合、顧客接点、利用できるデータ、評価方法、運用能力のうち実在する強み |
| なぜこのチームか | ドメイン知識が必要だった制約、設計判断、失敗からの変更と確認結果 |

スポンサー主催のハッカソンでは製品・APIの活用方法を示すことが審査上の論点になり得る。資金調達では、その実装を顧客の支払・継続・成長・採算へつなぐ。同じデモを使う場合も、示す結論を投資家の問いに合わせる。

RocketCreaterでは、候補生成、設計上の制約、評価、制作物への反映を説明する際に、実行記録と確認できた範囲を添える。チームのドメイン知識が、どの制約や評価を必要にしたかを示す。顧客数、費用削減、市場規模などは、この資料を根拠に実績として加えない。
